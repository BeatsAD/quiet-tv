# HOME、守护与 ADB 配置

[统一入口](../AGENT.md)。只在任务进入本阶段时读取；先完成[连接与任务记录](connect.md)，执行前后遵守[验收要求](acceptance.md)。下方是底层工具示例；Agent 应按[任务记录说明](session.md)通过 `agent_session.py run` 调用，由任务分配新记录路径。

## 海信开机接管排查

识别到海信／VIDAA Android 电视，且出现“开机先进入聚好看或原厂首页”“实体 HOME 返回原桌面”“停用原桌面后黑屏”时，Agent 必须进入本分支，再决定接管路线。用户继续使用原安装请求，无需另外指定“优先级”或“开机解锁”。非 Android 电视不适用。先完成已授权的只读检查，不因一次 HOME 设置失败、黑屏或 ADB 身份特殊，就直接结论为“权限不足、系统必须依赖原桌面、无法改造”。有明确权限拒绝时保留原始错误，但只据此说明该操作受限。

### AI 实际调用的开机桌面脚本

可执行入口为 [configure_boot_home.py](../../scripts/configure_boot_home.py)。它已接入 `install_quiet_tv.py --goal takeover`：首次安装先trial并登记基础试用通过，任务工具再沿用该APK进入配置；无标准 HOME 路线时继续现有兼容守护。若仅尝试标准 HOME、读回确认仍为原桌面且设备身份不变，也继续评估兼容守护；读回未知、出现其他 HOME 或涉及厂商属性的部分修改时停止，按记录核对恢复。`trial`、`update` 和只读验收不会调用写入路径。独立 Agent 必须从同一次 `latest.json.tools` 下载并校验索引列出的全部工具与规则，不能只复制本文或只下载一个脚本。

已有 Quiet TV、只需配置开机桌面时，AI 先执行预览，再在已有开机接管授权内以新记录目录加 `--apply` 执行，不要求用户另写命令：

```sh
python3 scripts/configure_boot_home.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --record "$NEW_PREVIEW_DIR"
python3 scripts/configure_boot_home.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --record "$NEW_APPLY_DIR" --apply
```

脚本拉取实际已安装 APK 并检查签名、包名、系统档位和 HOME 声明；API24+ 另核对 `HomeActivity` 的 `directBootAware`，缺失时停止配置并提示选择支持该能力的适配发布包，不凭最新源码假定旧 APK 支持。声明存在不证明解锁前存储访问正确，仍需启动实测。单独配置不下载安装包，不重复更新主程序，也不新建常驻电脑进程。

脚本实际执行并读回系统默认 HOME；当设备品牌为海信／VIDAA、目标为用户0、本机存在启用的系统包 `com.jamdeo.tv.vod` 且它是 HOME 候选、`persist.vt.use_home_pkg` 当前值确为该包或 Quiet TV 时，复用项目现有海信路由，将该属性指向 Quiet TV。属性缺失、值不明、非系统包或非主用户时不试写，仅报告标准 HOME 的配置范围；不能把标准 HOME 成功说成厂商开机路由已修复。属性已匹配目标时不重复写。保留原桌面、应用数据、其他系统包及开机动画，不提升 HOME 优先级或冒用原厂包名。

每次使用全新电脑私有记录目录，写入前保存设备／固件／用户、实际 APK 校验值、原 HOME、包状态及属性原值；逐步记录待执行、命令结果及读回值。执行中断、权限拒绝或读回不符时停止后续修改，显示实际错误，不自动重试、重启或扩大到禁用原桌面。仅 HOME 查询／设置能力缺失或目标不在候选中的已知无写入结果，才允许安装入口继续独立守护方案；已经尝试写入后失败，先处理记录中的未完成变更。

撤销本脚本实际尝试过的变更时，AI 使用该次 `record.jsonl`，先预览，再按已有恢复授权加 `--apply`：

```sh
python3 scripts/configure_boot_home.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --restore-record "$OLD_RECORD_DIR/record.jsonl" --record "$NEW_RESTORE_PREVIEW_DIR"
python3 scripts/configure_boot_home.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --restore-record "$OLD_RECORD_DIR/record.jsonl" --record "$NEW_RESTORE_APPLY_DIR" --apply
```

恢复重新核对目标、用户和固件，拒绝覆盖其他操作已经改变的现场；只恢复本次 HOME／海信属性原值，不执行记录中的任意 shell，不撤销安装或其他守护权限。原 HOME 已经是 Quiet TV 时，撤销仍恢复到该次操作前的状态，不冒称恢复原厂。需要恢复整个安装流程时，仍结合原安装与守护记录按下方“请求恢复原桌面”处理。

脚本返回成功只表示配置已写入并读回。AI 必须继续按本页授权要求让用户核验实体 HOME、普通重启、断电开机及待机唤醒，记录首屏和最终页面；不把守护延迟跳转描述为“开机立即进入新桌面”。站点工具更新后即可配置已具备能力的主程序，但不能让旧 APK 自动获得缺少的 Direct Boot 或厂商能力。

### 线索来源与适用边界

用户提供的视频文字版描述了“原桌面优先级 50、新桌面 0，使用约 12KB 程序在开机解锁前承接 HOME，停用原厂首页并更换聚好看开机动画”的成功案例。目前未取得原视频链接、型号／固件、完整命令或助手 APK／源码；这是一条待核实的候选路线，不是 Quiet TV 的真机验收或可直接执行的禁用规则。数字 50／0、包名 `com.jamdeo.tv.vod`、助手大小和无广告效果均不能复制为本机事实。

Android 的 [Direct Boot](https://developer.android.com/privacy-and-security/direct-boot) 从 Android 7.0／API24 引入；解锁前可运行组件须声明 `directBootAware`，需要持久数据时使用设备保护存储。Android 4.4／5／6 不套用该机制，继续查厂商启动、按键路由及组件依赖。用户存储未解锁与锁屏界面不是同一个状态，不能仅凭黑屏或 `Keyguard` 锁定推断 Direct Boot。

### 按现场证据分流

先补齐型号、完整固件指纹、API、目标用户、实际安装包及 HOME 形态、原桌面组件和包／组件状态。沿用上方已保存的恢复基线；不要求用户猜系统字段。结合固件支持的 HOME 查询、`dumpsys package`、`dumpsys user`、前台组件和相关启动日志读取下列证据；命令不支持或字段缺失标为未知，不以默认值补齐。

| 检查项 | 判断与下一步 |
| --- | --- |
| HOME 候选、有效优先级、默认 HOME 与实体按键后的前台组件 | 记录同一用户的实际候选与解析结果。若高优先级原 HOME 被选中，继续核对默认选择及厂商路由；不能只凭清单中的 priority 判定根因。普通应用请求正优先级可能被系统限制为 0，不把“改成 51／100”当成通用修复。规则见 [Android intent-filter](https://developer.android.com/guide/topics/manifest/intent-filter-element)。 |
| API24+ 开机时的用户存储状态及实际 APK 组件 | 核对启动当时是否未解锁、HOME 是否能在 Direct Boot 运行，以及是否出现访问凭据保护存储的异常。读取安装在电视上的 APK 清单，不能用最新源码替代。开机结束后已解锁的快照不能证明启动阶段没有问题。 |
| 默认 HOME 已指向 Quiet TV，但原桌面仍被拉起 | 按用户动作时间线核对实际启动组件及发起方，区分厂商显式启动、实体 HOME 私有路由、守护未绑定／配置丢失与系统重新解析 HOME，不只反复设置默认值。 |
| 停用后黑屏、启动卡住或 ADB 断连 | 先核对已有修改及恢复通道，按授权恢复有记录的原状态。不能据此证明永久系统依赖，也不能继续停用其他系统包试错；连接恢复后先读状态，不重放修改。 |
| LOGO、启动动画、视频广告和原厂首页 | 分别记录出现顺序、可识别组件及用户画面。HOME 接管和广告／动画处理独立判断，桌面直达不等于所有启动广告已消失。 |

需要重启、断电或待机复现时，沿用本页电源测试授权要求；没有授权或恢复通道时先报告缺失的启动阶段证据，继续其他只读检查。

### 轻量启动中转候选路线

只有证据指向解锁前 HOME 缺失或存储访问不兼容时，才进一步评估“Direct Boot 临时 HOME → 用户存储解锁 → Quiet TV”路线。先检查实际发布包是否已经具备该能力；现有包可以处理时优先复用，不重复安装助手。

候选助手应有可被系统选中的、`directBootAware` 的 HOME Activity，在解锁前显示最小页面且不读取凭据保护的偏好、数据库或媒体；解锁后再显式启动已核验的 Quiet TV 组件。应同时检查当前用户是否已解锁并监听 `ACTION_USER_UNLOCKED`，避免错过广播；不能把后台接收器收到开机广播当作桌面已显示。目标未安装、被禁用、启动失败或配置暂停时，应有可用的恢复入口，避免递归发送 HOME。无需冒用原厂包名或声称取得系统权限。

这描述的是实现与核验条件，不代表已经提供海信专用助手。普通安装流程只使用已发布、已核验且适配的包；缺少匹配助手时明确报告，不临时编译、改签或从不明来源下载安装。用户另行选择源码实验后，才准备针对该固件的实现、签名／包名／目标组件／哈希与恢复方案；构建成功仍不代表冷启动成功。已知权限拒绝和厂商强制路由也不会仅因加入 `directBootAware` 自动消失。

### 原桌面、动画与恢复

默认保留原桌面。本分支不授予禁用资格，不改写[固件规则](../../app/src/main/assets/setup-presets.json)；只有满足[可选禁用原桌面](install.md#首次安装试用默认桌面与可选管理)的本机条件且用户明确选择，才按实际组件操作。教程中的批量删除预装应用不是接管前置条件，不予复刻。现有保留原桌面的代理／守护与停用原桌面的路线不能混用，先核对各自依赖。

动画替换作为独立候选：先确定是应用广告、厂商设置还是系统动画文件，并核对可写权限、原文件／配置及恢复办法。未取得原方法时标为未确认，不把停用聚好看等同于替换系统动画，不提供通用系统文件覆盖命令；普通安装／接管授权不包含动画修改。

`pm enable com.jamdeo.tv.vod` 只可能恢复已安装且被停用的该包，不能恢复删除的其他应用、修改的动画、隐藏状态或原默认 HOME。仅在本机确认包身份、用户及原状态后生成对应恢复命令：原 `enabled=0` 与显式启用 `enabled=1` 分别按固件支持的 `default-state`／`enable` 处理；隐藏、卸载或组件单独禁用另按本机记录恢复，不统一替换成 `enable`。恢复后读回状态并验证原桌面，不能承诺“一条命令恢复原厂状态”。

交付分别列出候选路线、已确认原因、缺失证据、实际采用方案，以及实体 HOME、普通重启、断电冷启动、待机唤醒、广告／动画和恢复结果。未做的项目标为未验证；不将教程作者的成功、助手体积或源码能力写成当前电视已完成改造。


## 兼容守护的权限与范围

仅当用户明确请求自动接管桌面或另行授权兼容守护，且实际安装包包含相应组件时，才配置兼容守护的无障碍、通知访问及写安全设置能力；使用实际包名和已核对用户。首次权限配置不等于开机验收。新开发版进入配置后默认为自动，后续重启无需重复确认；系统 HOME 仍属原桌面时不得报告默认 HOME 已修改，不因守护可运行而禁用原桌面。用户明确暂停后不得重启、重绑或更新替其打开。历史安装包不因本文更新而获得该能力。

本修复提供[电脑配置脚本及步骤](../SETUP.md#桌面守护实验)：电脑 ADB 已授权即可完成首次配置，无需等待 Quiet TV 内置 ADB 认证成功。预览后，在已有守护配置授权范围内使用 `--apply`；该参数明确启用守护，含主动暂停的配置也会开启，不在只读诊断、首装基础检查或仅更新时执行。先核对指定电视、前台用户、原主页及实际 APK 的 `HomeGuardSetupReceiver`；旧 1.2.0 包缺少入口时先说明版本差异，未获更新授权不自行安装。脚本保留原桌面与其他服务，权限写入、服务绑定、事件可用及实体接管分别确认。Android 5／6补偿需用量统计授权；Android 4.4不开放。端口连通、ADB 开关开启、内置握手超时均不能单独证明电脑 ADB 授权状态或固件封锁。



## ADB 常开与重启验收

默认安装请求包含 ADB 常开，不需要用户在电视桌面设置开关。独立修复 ADB、同时保留现有桌面路线和暂停状态时：

```sh
python3 configure_home_guard.py --serial "$TV_SERIAL" --user "$TV_USER" --package "$QUIET_PACKAGE" --adb-only --keep-adb
```

预览后在已有授权内用 `--apply --record "$NEW_PRIVATE_RECORD"` 执行。工具先保存原权限、开关和应用选项，核对实际能力，再授予写安全设置权限并持久保存保持选项；读回应用状态及 `adb_enabled=1` 才确认配置步骤。此路径不授予守护所需的无障碍、悬浮窗或使用统计权限，不改变原桌面和暂停状态。

用户明确要求停止保持时，独立命令改用 `--no-keep-adb`，只停止自动恢复，不主动关闭当前连接或删除授权；这与安装入口的同名参数“本次不新增开启”语义不同。默认流程不自动执行此操作。

配置和验收分开：记录固件、当前连接方式、实际端口和 `/proc/sys/kernel/random/boot_id`；用户授权重启测试后，通过原授权连接重新建立 ADB，核对同一设备、变化后的 boot_id、`adb_enabled=1` 和应用内 `adb.selected/ready/settingEnabled`。网络模式还须通过实际网络地址重连，不能用 USB／模拟器串行通道成功代替。冷启动和待机唤醒分别验证。断连后不得盲目重启、反复开关或扫描网络；无法重新连接时通过电视系统授权或已知 USB 恢复路径继续，并报告未通过。
