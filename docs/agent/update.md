# 保留数据升级

[统一入口](../AGENT.md)。只在任务进入本阶段时读取；先完成[连接与任务记录](connect.md)，执行前后遵守[验收要求](acceptance.md)。下方是底层工具示例；Agent 应按[任务记录说明](session.md)通过 `agent_session.py run` 调用，由任务分配新记录路径。

## 已有安装：覆盖校验与仅更新

已有可用接管方案时，默认请求和仅更新请求均使用 `--goal update`，不重新配置桌面、守护或ADB。默认请求还有其他修复目标时，在升级路线验收完成后显式plan对应修复；仅更新意图不会允许配置动作。

| 检测结果 | 处理 |
| --- | --- |
| 适用档位有更高 `versionCode`，包名、签名及系统架构匹配 | 保留数据覆盖升级，保持原默认桌面、应用启禁状态及设置，不重新执行首次设置或精简。 |
| 已安装包与适用附件的 `versionName`、`versionCode`、SHA-256 均相同 | 告知无需重装；如用户有故障，另行诊断，不用重装代替判断。 |
| `versionCode` 相同但文件不同，或已安装构建号更高 | 说明差异并停止覆盖，不默认修复、换档或降级。 |
| 包名、签名、系统或架构不匹配 | 明确不满足的条件，停止直接覆盖，不通过卸载解决。 |

软件版本相同不代表构建号相同。已安装同批高号通用包时，不能覆盖安装低号 ARM 包；专用包不满足条件而通用包满足时可选通用包。无符合条件的更新包则保留现状并说明，等待更高构建号的匹配包，不卸载、清数据或强制降级。

1.3.0 配套 APK 仅在主程序构建号递增、固件、HOME 形态、原桌面及助手版本未变时沿用配置；保留暂停和 ADB 选择，已启用代理重新握手，旧实体场景验收清为待验证。缺少该修复的旧包不能获得此保证。

覆盖后核对版本与已安装文件，再分别检查原 HOME、守护路线与暂停选择、ADB 保持选项和实际开关、原桌面恢复记录及启禁状态是否保持，请用户确认桌面能打开、壁纸与排序等原设置仍在。当前源码的新安装与升级均不自动弹出设置向导；已发布旧包可能仍有引导，按实际 APK 判断。如出现状态变化，报告差异，不自动重新配置。用户另行要求调整默认桌面或应用时，再进入对应可选流程。


## 执行顺序

先核对[安装说明](install.md)中的版本、分包和签名条件。已有可用接管方案时，即使用户使用默认请求，也先选择 `--goal update`，不重跑 `takeover`。升级预览和执行分别通过任务工具调用，保留原路线、暂停及恢复基线。

```sh
python3 agent_session.py plan --session "$SESSION_DIR" --route update --note "实际版本及升级条件"
python3 agent_session.py run --session "$SESSION_DIR" --tool install_quiet_tv -- --goal update
python3 agent_session.py run --session "$SESSION_DIR" --tool install_quiet_tv -- --goal update --apply
```

相同适配APK会直接报告无需更新，不下载或启动。覆盖完成后APK由工具自动核验；Agent核对原路线、暂停、恢复记录及用户数据后，用 `accept --check preservation` 记录实际结果，再finish。缺必要证据仍为待确认。

没有适用的新包则跳过安装。默认请求需要保持 ADB 时，按[独立 ADB 配置](home.md#adb-常开与重启验收)检查实际能力，必要时调用 `configure_home_guard --adb-only --keep-adb`，不启用已暂停守护；用户仅更新则保持其已有 ADB 选择。发现其他配置异常才按[维护指南](../AGENT_ADAPT.zh-CN.md)在授权范围内修复。
