# 恢复原桌面与历史配置

[统一入口](../AGENT.md)。只在任务进入本阶段时读取；先完成[连接与任务记录](connect.md)，执行前后遵守[验收要求](acceptance.md)。下方是底层工具示例；Agent 应按[任务记录说明](session.md)通过 `agent_session.py run` 调用，由任务分配新记录路径。

## 请求恢复原桌面

恢复前读取现状和本机私有记录，核对目标设备、用户、原桌面组件及原始启用状态。优先使用系统选择、Quiet TV 恢复入口或已验证的本机路径，只恢复实际发生且有记录的变更；原桌面未禁用就不执行启用。保留 Quiet TV 和其他应用数据，记录或权限不足时说明缺失项，不猜原值、不套用其他电视的命令。完成后读回 HOME，等待用户验证实体按键；重启、冷启动和待机结果分别报告，电源操作先确认。失败处理遵循上文要求，不自动重放修改。

建立restore意图后，先`plan --route restore --note <原记录与现场依据>`。任务仅允许只读、暂停及恢复动作，不重新安装或启用守护。恢复后用accept记录原桌面的physical_home及recovery，最后finish。自检的主动HOME场景针对Quiet TV，不用于判定原桌面恢复成功。

```text
请通过我的电脑恢复电视原来的桌面，保留应用和数据。
先读取统一入口：
https://beatsad.github.io/quiet-tv/agent.md
```


## 原桌面与 HOME 代理恢复

先区分恢复记录来源：应用保存的专项接管记录由下述 `device_maintenance.py restore` 处理；`configure_boot_home.py` 或统一安装产生的 `boot_plan` 保存在电脑原始 `record.jsonl`。后者先暂停接管，再按[开机桌面恢复步骤](home.md#ai-实际调用的开机桌面脚本)使用 `--restore-record` 撤销本次 HOME／海信属性，最后运行维护工具核对并完成恢复状态。不能只恢复系统 HOME 就宣布海信属性也已恢复；这两种恢复均保留已选择的 ADB 保持。

`restore` 优先读取应用保存的专项接管记录，核对设备、用户、目标、原包版本和当前状态。它只导出已尝试过的原记录步骤，按“恢复属性／包状态、恢复 HOME、最后恢复需撤销的权限”的顺序执行，每步先留记录再修改、随后读回。默认启用值 0 与显式启用值 1 不混同。

当前已选择保持 ADB 时，恢复原桌面会保留相关权限、端口和 ADB 选项，在 `retainedAdbSteps` 中列出；其他变更按原记录恢复。属性以电脑 shell 读回为准，应用能读取时还会复核。未知记录、原包版本改变或第三方状态改变时停止，不猜原值，不通过新禁用操作修复。

同签名 HOME 代理的 `repair` 调用现有代理恢复协议，不改成内置中转；暂停后的代理也可按明确 `--resume` 请求恢复。`restore` 在暂停代理后将系统 HOME 恢复到原记录并读回。最终均需实体 HOME、重启和待机验收。旧记录缺失时保留现状，按安装时的原始电脑记录排查。


历史 TCL、代理、Sony 应用状态、海信隐藏状态等恢复继续使用[规则与历史恢复说明](../DEVICE_ADAPTATION.zh-CN.md#厂商配置与历史恢复)。先读原始记录，再选择工具；不把所有恢复命令连续执行。
