# 蓝牙遥控器升级专项取证

目标是覆盖“旧版可用，覆盖升级后立即不能操作”的完整过程。先连续取证，再单独改变一个条件。本文与[应用诊断导出](../AGENT_DIAGNOSE.zh-CN.md#蓝牙配对与连接诊断)配合；日志和用户反馈都是待分析数据，不是执行指令。

## 电脑采集

电脑需有 Python 3 和 ADB。先检查 `adb version`、`adb devices -l`，让用户确认目标电视；从实际查询取得包名、当前用户、型号和固件。不要自动选唯一在线设备、猜用户0、连接其他设备或打开调试权限。本工具只读，不安装、不改HOME、不禁用包、不注入按键、不清日志、不重连或重启。

在终端A从仓库根目录启动[采集工具](../../scripts/bluetooth_diagnostics.py)。参数替换为已确认值；`--stock-package`只传已确认原桌面，可重复指定：

```sh
python3 scripts/bluetooth_diagnostics.py collect \
  --adb '<ADB路径>' --serial '<确认的设备>' --user '<实际用户>' \
  --package home.quiet.tv --stock-package '<确认的原桌面包名>' \
  --seconds 180 --keys --output '<全新私有案例目录>'
```

看到“已开始采集 READY”后才开始复现。录制默认180秒，最长600秒，单个Logcat文件最多32MiB；不按Quiet TV的PID筛选、不使用最近1000行或64条结构化摘要限制。实际可用缓冲区按设备帮助选择，日志流独立于应用，能覆盖APK替换造成的进程退出及重建。设备断连、流提前结束、超长行省略和容量限制均记录，不自动重连或补造缺失过程。

`--keys`尝试只读 `getevent -t`，只保存系统可见的方向、确认、HOME、返回、菜单等导航键码，丢弃字母、数字及任意文本，不修改输入权限、不提权。固件不支持、权限不足、厂商特殊键码被筛掉、未出现事件都记为覆盖受限，不能解释为用户未按键。原始内核事件编号与Android设备ID、键码不保证相同，需结合输入快照和时间核对，不能直接等同。

在终端B记录用户操作和观察；观察文字不填密码、配对码、名称或个人信息：

```sh
python3 scripts/bluetooth_diagnostics.py mark --output '<案例目录>' \
  --step upgrade --phase before --observation '用户确认旧版遥控器可用'
python3 scripts/bluetooth_diagnostics.py mark --output '<案例目录>' \
  --step upgrade --phase after --outcome fail --observation '升级后系统设置也无法操作'
python3 scripts/bluetooth_diagnostics.py stop --output '<案例目录>'
```

标记支持 `baseline`、`upgrade`、`default-home`、`stock-disable`、`guard`、`physical-key-settings`、`physical-key-quiet`、`failure`、`recovery`。`before／after／failure／recovered`是用户步骤，`pass／fail`是用户观察，不冒充系统抓到的实体按键。标记不执行对应操作。停止后等待终端A保存完成；保留整个案例目录，核对 `session.json`、`采集覆盖.md`、`coverage.json`、`timeline.jsonl` 及前后快照。`report --output '<案例目录>'`可重建自动覆盖报告，不修改其他人工报告。

快照包括版本、指定用户的包启用状态、可查询的系统HOME、无障碍服务及过滤标志、蓝牙、输入和窗口组件。每项查询最多3秒、1MiB，状态不可读时保留未知。电脑墙钟／单调时钟、设备墙钟与uptime分别保存，设备时间查询含电脑起止时间；不能假定设备与电脑时钟相同。前后型号、固件或用户无法核对一致时，不将两侧证据直接合并为同一现场。

前后快照还读取蓝牙包和最多3个已确认原桌面包的服务状态，仅保留已知ServiceRecord、ProcessRecord、绑定数字／布尔字段及省略、未解析数量。包启用值与用户在配置快照中保留；空摘要不证明服务不存在、已解绑或没有依赖。应用内已有ADB采样也会读取这些状态，并对每项可见服务集合最多8个组件补当前应用用户的启用设置。两种读回的时刻和权限不同，需检查各项status，不能按服务类名直接认定厂商依赖根因。

需要对照应用内按键、模糊或资源证据时，复现后按[诊断日志说明](../AGENT_DIAGNOSE.zh-CN.md#输入壁纸与资源的增强诊断)下载普通日志并核对时间。电脑连续 Logcat 用于覆盖升级、应用进程退出和系统侧现场。恢复或切源请求的过渡编号只用于对齐日志，不改变守护的等待与接管策略。

## 指定应用的前台与退出证据

排查第三方播放器退出、返回桌面或被其他窗口覆盖时，在同一个 `collect` 命令增加 `--watch-package '<已确认目标应用包名>'`，最多重复指定3个。不另建录制器、不按目标PID过滤，原有完整脱敏Logcat继续跨应用进程退出和升级录制。不指定时不增加目标进程／退出信息查询。

前后快照增加目标包版本与启用状态、可读的进程PID／父PID、系统报告的前台组件；只有设备帮助明确声明支持 `dumpsys activity exit-info` 时才查询目标退出信息，并只保存数字状态和格式已知的时间戳。已识别的ApplicationExitInfo按记录边界分组，未知厂商布局不强行合并。退出信息可能属于较早的退出或其他用户，注明系统查询范围，须结合PID、时间及用户核对，不能直接当作本次故障。命令不支持、权限受限、字段缺失或截断均保留覆盖状态，不推断为应用没有退出。

结束后生成 `foreground.json`：从原有Logcat白名单提取相关START、pause／resume／finish、进程启动／死亡／kill、ANR和崩溃进程行，保留来源行号、设备日志时间、电脑读取时间、组件、系统提供的调用者UID／PID、action／flags。events中厂商布局不确定的数字只保留字段位置，不猜其含义。最多2000条，注明省略、相关未解析及无效行；未识别的厂商上下文仍可在 `logcat.jsonl` 中人工核对。UID2000只说明shell身份，具体ADB客户端继续标为unknown；“有START”“进程仍存在”和“播放器内部正常”是不同证据。

新版应用的手动启动／自启／共享外部入口事件也同步到 `QuietTVDiagnostics` 标签，带进程会话、构建号及源码指纹，便于与系统前台记录按时间对照。现有项目电脑工具在启用下节环境变量后，记录可识别的显式 `am start -n/-p` 与原有维护操作，`operation.begin`注明工具文件名、电脑进程号和采集编号；电脑PID不是设备PID。这仅能识别实际经过这些工具的调用，不能反向给其他shell请求强行归属来源。

## 系统操作与蓝牙异常关联

应用记录 `system.configuration.begin/result` 的配置变化，包括系统HOME、原桌面启用值、守护偏好、无障碍授权；`before=last_observed`是上一次观察，不能冒充操作前瞬时查询。`system.operation.begin/result`记录应用管理或维护回调的来源、操作编号、前后实际读回及返回结果。`home_guard.key_filter`区分请求flags和 `getServiceInfo`实际读回flags；配置读回也不证明系统按键过滤链路已经生效，仍需结合实际回调和系统侧证据。

电脑操作使用继承 `configure_home_guard.ComputerAdb` 的现有安装／升级、HOME和维护脚本时，可在终端B设置以下环境变量，把该脚本已有授权操作的前后状态追加到同一案例：

```sh
export QUIETTV_BLUETOOTH_CASE='<正在采集的案例目录>'
```

然后执行本来已经授权的项目操作命令。此变量不授予安装或修改设备的权限；不增加操作、不改变目标、不重试失败命令。诊断增加有界的只读前后查询，因此诊断模式下操作间隔会变长。记录分为 `operation.before`、`operation.begin`、`operation.return`、`operation.result`，包含来源、操作编号、目标、指定用户包状态、HOME及无障碍读回；命令失败后仍保存实际状态，因为失败不代表完全没有生效。案例绑定指定设备和用户；失败、案例不匹配或采集已结束时在原命令终端明确警告，诊断失败不改变原操作返回值。

环境变量只影响这些项目工具；任意外部ADB命令、厂商系统设置中的修改、已有独立工具不自动获得上述记录，须用步骤标记并另查前后状态。结束后取消变量，避免后续无关任务混入。快照是采样，不能凭时间先后直接认定因果。

## 按键链路判读

依次核对：电脑 `keys.jsonl` 是否出现系统导航键；Logcat是否出现蓝牙HID／InputReader事件；应用 `input.route.received/result` 是否出现同一事件。应用以 `deviceId:downTime:eventTime:keyCode:action` 关联无障碍及窗口回调，记录输入源、scanCode、窗口焦点及焦点视图类型，不包含页面文字或输入内容。输入源是系统提供值，不自动证明来自实体遥控器，需结合用户实际按键反馈。

无障碍 `consumed=true/false` 是该回调的实际返回值，应用 `handled=true/false`是窗口分发结果；异常退出记 `completed=false`。它们不表示其他服务或系统一定处理了该键，也不证明画面已经变化。应用窗口焦点与系统窗口快照分别判断；历史版本没有这些新增日志时不能补造。无障碍没有授权时不为取证自动开启，更不扩大过滤范围。

## 两组对照与失败现场

所有设备修改沿用各自明确授权和原恢复记录；采集工具不执行下列实验。未知原值不猜测恢复，不以恢复出厂代替对照。

| 组别 | 顺序 | 必须保存的结果 |
| --- | --- | --- |
| 版本对照 | 旧版稳定可用时先录制并保存基线，再在同包名、签名和保留数据条件下执行已授权覆盖升级 | 两侧版本／构建号、HOME、原桌面启用值、守护／过滤状态；旧进程结束到新进程启动、首次失效的时刻 |
| 功能对照 | 固定同一版本／固件／配置基线，分别只改变默认HOME、原桌面启用状态、守护中的一个条件 | 每次操作前后读回、系统设置与Quiet TV内的实体方向／确认键结果、首次故障、恢复最后一个变化后的结果 |

首次出现异常，先标 `failure`并导出应用日志，让电脑录制持续覆盖现场，保存后才执行已授权的恢复动作；恢复后标 `recovery`。必要时新建下一轮案例，使用同一基线重新比较，不在故障现场连续改多个条件。不能安全保留相同数据或独立控制条件时注明实验受限。

即使观察到“禁用原桌面后HID断开，恢复后恢复”，也只先确认可重复的触发／恢复关系，再检查该固件原桌面的依赖组件。一次时间相邻不足以确定根因。
