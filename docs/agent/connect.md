# 连接、检测与工具准备

[统一入口](../AGENT.md)。只在任务进入本阶段时读取；本页只做连接、检测与准备，实际操作后遵守[验收要求](acceptance.md)。下方是底层工具示例；Agent 应按[任务记录说明](session.md)通过 `agent_session.py run` 调用，由任务分配新记录路径。

## 当前交付范围

配套APK的版本、构建号、最低API及架构以同次实时索引和实际包元数据为准，不在说明中固定“当前构建”。先检查已安装APK的接口与能力，不能把仓库源码能力视为下载包能力。旧包继续其支持的安装、HOME、守护和恢复路径；缺接口的操作说明所需能力，不改写私有文件或临时构建替代。ADB保持未获支持时单独报告未完成，不将整体接管标为通过。


## 检测与保存基线

以下保留各操作的检查要求，后续安装或恢复只按用户目标进入对应分支，不能把这些步骤当作必做安装清单。

1. **确认目标**：检查电脑工具、现有 ADB 连接和 mDNS，必要时仅在电脑当前局域网扫描常用 ADB 连接端口，不跨网段或做全端口扫描。无论发现一台还是多台，都让用户确认目标；未发现时再指导用户提供实际地址和端口或 USB 设备标识。后续 ADB 命令始终指定同一设备。根据电视实际入口选择 USB、传统网络 ADB 或无线配对；配对端口与连接端口分别核对，授权由用户现场确认，不把投屏码当作配对码。无授权通道时停止依赖 ADB 的步骤；如果电视允许手动安装，继续提供普通 App 试用路径。
2. **只读检测**：读取品牌、完整型号、Android/API、系统支持的 ABI 列表、固件指纹、当前用户、Quiet TV 安装及启用状态、版本和签名，以及 HOME 候选和实际解析结果。先读取 `pm help` 和可用的 `cmd package help`，不预设用户 0、端口 5555 或现代子命令存在。分别判断 ADB 连接与授权、应用扫描、安装、HOME 切换、禁用及恢复能力；型号和 Android 版本不能代替实际能力检查。没有可靠查询结果时标明“未确认”，不能当作未安装。
3. **识别安装场景**：按[统一入口](../AGENT.md)的意图与状态分流。当前用户已禁用、仅其他用户安装或当前用户已卸载但系统仍保留包的情况单独说明，询问是否恢复使用，不自动启用、恢复安装或当作首次安装。实验专用包名与普通包不混为覆盖升级。
4. **保存恢复基线**：在安装前保存可读取的旧版本、签名、实际 APK、当前 HOME 和应用启禁状态；首次启动或切换前补齐原主页组件、原始启用状态、目标用户及本机可用恢复路径。更新时保留原有恢复记录，不用当前 Quiet TV HOME 覆盖原桌面记录。保存在电脑私有目录；不上传设备标识、地址、密钥、完整转储或应用清单。系统选择器不能当成原桌面，记录不等于应用数据备份；无法读取的私有设置不能声称已备份。
5. **选择与校验安装包**：读取[兼容说明](../COMPATIBILITY.md)，按上方版本与分包规则选包；安装前告知 Release、实际下载地址、`versionName`、`versionCode`、架构及选包理由。核对实际 APK 的包名、签名、最低 API、原生库架构及 GitHub 对应 APK 附件的 SHA-256；历史版本另有同名校验文件时可使用其记录，记录中的文件名须与实际下载名一致。不因新版本未上传独立校验文件而改选旧版本。签名冲突、降级或缺少匹配包时按[升级说明](update.md)处理。
6. **安装并核对**：保留数据安装，读取目标用户的实际安装路径，拉取已安装 APK，核对包名、`versionName`、`versionCode` 和 SHA-256 与选定目标一致。已有多 APK 安装逐项核对，单个 base.apk 不能证明整个集合。核对不符报告“版本验证失败”，无法核对报告“结果未确认”，不能仅凭安装命令成功声称已更新。TCL／雷鸟遭遇安装校验拒绝时，转入[TCL 安装说明](tcl.md)，不重复普通安装。
7. **分项交付**：按所选分支验证结果，提供根据本次记录生成的恢复步骤。重启、断电冷启动、待机唤醒分别验证；重启和设备电源操作需有明确授权和可用恢复路径。失败或连接丢失时按[验收与失败报告](acceptance.md)报告，先查询现状，不自动重放安装、切换或禁用；TCL 分支中尚未恢复的安装器，按该分支优先恢复并读回。


## 下载并固定本次工具包

使用官方 Android Platform-Tools；检查 Python 3、ADB，只有安装/核验 APK 时才按需准备 Android Build-Tools 的 `aapt2`、`apksigner` 和 Java，不要求下载整套开发工程。连接按实际 USB、网络 ADB 或无线配对入口操作，不预设 5555，也不把配对端口当连接端口。

AI 在电脑私有位置创建全新工具包目录，实时读取 `https://beatsad.github.io/quiet-tv/latest.json?check=<本次时间>`，禁用缓存，保存原始索引。按 `tools` 与 `guides` 的实际 URL 下载全部文件并逐个校验 SHA-256：工具放在该目录根部，说明按索引键保存，如 `guides/install.md`。缺项、非官方 HTTPS URL 或哈希不符就停止，不执行混合版本。说明全部下载只是为了固定版本；AI 每次只阅读当前分支文件。

不要通过搜索摘要判断版本，也不要因为 `/releases/latest` 不含测试版就退回旧包。下载最新适配 APK 的过程仍使用[安装说明](install.md)和实时 Release 索引；说明与工具快照不等于签名 APK 更新清单。

建立[任务记录](session.md)后，后续阅读固定目录中的 `agent.md` 和 `guides/`，不要中途重新下载覆盖它们。工具和说明路径由任务保存；正常流程可通过新任务使用新版本，恢复记录始终保留。

## 应用管理首次配置（仅支持 daily-app-management-v1 的 APK）

用户需要在电视直接禁用、卸载和恢复应用时，先检查快照的 `capabilities`。117/118 发布包没有此能力，不调用新接口。新开发包只包含传统本机 TCP ADB 客户端，不包含 SPAKE2／Conscrypt 无线配对库。核对端口、当前用户和固件能力后保存：

```sh
python3 device_maintenance.py management-config --serial '<目标>' --user <用户> --port <已核对的TCP端口> --record '<新记录目录>'
# 用户已授权首次配置后，用新的记录目录加 --apply 保存。
```

这只保存连接信息，不自动开启端口，不代表应用已获授权。引导用户打开“应用管理 → 连接管理”，在系统授权弹窗确认 Quiet TV 自己的连接；不能复制电脑私钥或绕过系统授权。验证连接成功后，电脑可离线，日常操作由应用执行。重新启动后须分别检查 ADB 开关、TCP 端口、授权与应用管理，不能以开关开启代替可连接。仅提供无线配对/TLS 或阻止本机 TCP 的固件应报告此通道不可用，不承诺重启永久可用。

AI 按完整机型和固件核对应用用途后，通过现有 `device_adaptation.py --action rules-set --rules <本机规则>` 下发数据。只给已核对包授予 `DISABLE/ENABLE/UNINSTALL/RESTORE` 中实际支持的操作；原桌面与关键依赖不从日常按钮放行。禁止下发任意命令。禁用要求恢复原启用状态；预装卸载要求系统 APK 仍保留且支持当前用户恢复安装，明确不恢复已删除数据。固件变化重新核对规则。
