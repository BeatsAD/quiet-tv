# 验证、失败报告与交付

[统一入口](../AGENT.md)。只在任务进入本阶段时读取；先完成[连接与任务记录](connect.md)。下方是底层工具示例；Agent 应按[任务记录说明](session.md)通过 `agent_session.py run` 调用，由任务分配新记录路径。

## 失败时直接在 AI 对话显示

下载、连接、授权、安装、HOME、应用管理、恢复和验证中的失败，均立即显示在当前 AI 编程工具的对话中；不能只显示“失败”、只记录在文件、只让用户去电视找日志，或等待最后统一报告。

```text
失败步骤：<正在执行的操作与目标>
相关命令：<必要命令，设备地址、序列号等脱敏；界面操作则写操作路径>
退出状态：<本机退出码及可取得的远端退出状态；未取得写“未知”>
原始错误：<相关标准输出、标准错误或工具异常；无输出也明确说明>
原因判断：<已经确认的原因；可能原因和待确认项分别写明>
当前状态：<已完成、已修改、未执行、已核对或结果未确认>
下一步：<可继续的独立检查、用户需做的操作及本机恢复办法>
```

- 保留必要的原始错误码和错误文本，不隐藏错误输出或只给通用结论。原始内容只摘录相关脱敏片段，不输出配对码、令牌、密钥或完整设备转储。工具缺失、无权限、无法访问文档或无法取得日志也直接说明。
- 命令返回成功但版本、哈希、HOME 或包状态不符时，明确报告“验证失败”及预期、实际差异。超时、断连或缺少可靠输出时报告“结果未确认”，不推断成功或完全没有修改。
- 停止失败步骤及依赖它的后续修改，继续已授权且不依赖该结果的只读检查。重新读取实际状态后再决定后续；不自动重复修改、卸载重装、清数据或扩大到无关系统包。
- 原因无法确认就说明缺失证据；连接超时不等于固件封锁，HOME 查询正确不等于实体按键成功。用户的电视画面和实体反馈须单独记录。


## 结果要求

| 项目 | 应报告的证据 |
| --- | --- |
| APK | 选定 Release、来源、目标与实际版本及构建号、系统档位、架构与选包理由、签名、下载与已安装文件校验 |
| 安装 | 指定设备和用户上的实际安装结果 |
| 系统 HOME | 真实查询结果；不支持查询则为未知 |
| 遥控器校准 | HOME、信号源、菜单的键码或系统处理记录、所选动作、用户实际反馈、按机型/固件/用户保存的读回结果；见[逐键校准](remote.md) |
| 实体 HOME | 用户实际按键后的画面；ADB 注入只算单独证据 |
| 重启、冷启动、待机唤醒 | 各自完成、失败或未执行，不能互相替代 |
| 原桌面与恢复 | 是否保留、本机恢复步骤、依赖条件和私有记录位置 |
| 可选应用管理 | 用户确认的选择、规则依据、每项原状态、执行与读回结果；未选择则未执行 |
| 失败 | 失败步骤、脱敏命令、退出状态与原始错误、原因判断、当前状态和下一步 |

`Success`、应用已打开、HOME 已解析、服务已绑定及实际按键行为是不同证据。只贴必要命令的脱敏输出，不公开完整日志。无障碍或通知监听写入配置不代表已绑定、收到事件或能接管 HOME。

本流程不root、不刷机、不恢复出厂、不清数据、不卸载原桌面；禁用仅限用户明确选择且符合规则的项目，包括TCL专项中单独授权及可恢复的一次安装器操作。支持时按目标配置ADB保持，基础检查阶段及仅更新保留已有选择。安装和源码同步不授权发布APK。

安装、HOME 或运行异常需要取证时，使用[Agent 问题排查](../AGENT_DIAGNOSE.zh-CN.md)，排查不自动重复安装或修改系统。


## 主动场景自检

以下参数可单独选择或组合，必须同时加 `--apply`，只执行一次有副作用的动作，不重放失败的重启或切换。

| 参数 | 自动检查 | 仍需人工确认 |
| --- | --- | --- |
| `--home-tests` | 桌面模拟 HOME、从实际设置应用模拟 HOME，观察 8 秒前台 | 实体遥控器 HOME 与实际画面 |
| `--inputs` | 枚举可见信号源，调用桌面同一打开路径，记录请求回执和截图 | 输入名称、物理接口、真实视频与返回行为 |
| `--standby` | 发送睡眠、等待 70 秒、唤醒并观察前台 | 固件实际待机深度、遥控器唤醒、HDMI／播放不被打断 |
| `--reboot` | 整机重启、最多等待 150 秒重连和开机完成，再观察 60 秒前台 | 实际电视画面和之后的冷启动 |

```sh
python3 device_selftest.py --serial "$TV_SERIAL" --user "$TV_USER" --record "$SCENE_DIR" --home-tests --reboot --apply
```

重启后先核对硬件、固件、用户、启动标识和开机完成，再读取 ADB 开关与前台时间线，之后才查询应用接口，避免查询先启动应用而掩盖开机恢复缺陷。仅向用户选择的原 IP:端口重连，不扫描、猜端口或重新配对。动态无线标识、USB、模拟器连接不作为传统网络重连证据。ADB 断连时如实记录失败；待机后会提示用户遥控器唤醒，最多等 90 秒，不反复切电源。冷启动由人工断电验收，脚本不模拟。

`PASS`仅针对该行证据，`FAIL`表示失败，`SKIP`表示未测或证据不足。自动HOME必须匹配目标用户的HomeActivity，仅包名前台不通过；字段缺失记SKIP。信号源dispatched只证明请求发出，画面声音仍由用户确认。

APK中当前有效的HOME／冷启动等人工记录可读取复用，标明source=user；缺失时通过任务工具accept登记，不要求用户回电视重复填写。恢复路线的实体HOME指向原桌面，不能使用Quiet TV的旧场景通过记录。

按[任务记录](session.md)用plan确定必要项，工具自动归集实际APK核验及自检报告；用户和Agent观察分别登记。设置、网络应从Quiet TV真实按钮打开，再核对页面；外设从实际相关现场选择，不限品类，连接或搜索到型号不算实际可用。完成后finish汇总：必需项全通过才complete，缺证据pending，能力受限partial，失败failed。自检返回0只表示没有执行失败，不代表目标完成。

## 外设现场发现与实际验收

device_environment peripherals只读采集系统开放的输入、USB、蓝牙、音频、HDMI、电视输入、显示、路由和存储等通道；这是证据来源，不是设备品类白名单。候选保留原名称、来源及证据位置，同名多设备也保留；可能包含内置设备或同设备的多个视图，由Agent结合用户现场确认。未知服务、权限不足和未解析格式分别记录，不将“系统没看到”判为没有该设备。

设备ID标识本次观测，不作为永久硬件身份。按实际相关设备增加peripheral:ID验收；用户或Agent可补充任何未被系统枚举的设备。只在真实操作后记录画面、声音、按键或设备对应功能；发现、连接、可用分开。无设备在场或无法操作时保持SKIP／待确认，不自动模拟通过。
