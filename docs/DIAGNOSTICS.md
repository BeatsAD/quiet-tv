# 2.0 诊断与问题反馈

2.0 的电视导出和手机扫码设置导出使用同一份证据结构：`QuietTV-diagnostics.zip`，内含 `diagnostics.txt`、`diagnostics.json` 和记录文件大小与 SHA-256 的 `manifest.json`。两种入口均包含设备、显示、HOME、守护与允许的功能状态；手机没有诊断窗口，窗口信息明确标记为未采集。较早安装包的内容和格式保持其原有行为。

日常关键事件随应用进程自动记录。在导出页选择“标记刚才的问题”，保留最近历史并采集后续 30 秒；随后重新生成诊断包。标记表示用户报告时刻，不是自动识别到故障。进程退出时不继续录制，下次启动标明中断。导出与标记不安装软件、不修改 HOME 或系统权限，也不自动发送资料。

## 身份、操作与证据边界

软件版本、数字构建号、源码摘要与诊断格式版本分别记录。当前事件携带进程会话、匿名启动周期、PID、单调时间和构建来源。无会话字段的历史日志仍标为身份未知，不能赋予当前安装包版本。源码归档无法识别 Git 时保留未知提交及实际源码摘要。

手机设置请求、异步任务及嵌套操作通过 `attempt`、`parent` 和匿名请求/任务标识关联。记录图标刷新与批量提交、备份保护与恢复回滚、家长验证、学习记录、天气请求、每日壁纸、预览同步、配置保存与通知、屏保状态及远程播放来源。现有更新安装和应用管理事件继续保留，并关联到手机任务。

`ACCEPTED` 只表示操作受理；`SAVED` 表示设置处理返回；`COMPLETED` 以各操作明确记录的证据为准。通知、首帧及配置回调均不证明电视物理画面正常。`UNKNOWN` 是结果未确认，不能自动重试有副作用的操作。缺少结果、没有错误或没有某通道事件，均不能推断成功或用户没有操作。JSON 的操作摘要只统计导出的结果事件，不推断根因。

导出时状态、近期历史、用户标记窗口和当前进程采集质量分别列出。系统日志、实体遥控器行为、无响应及原生崩溃，仍需按 [Agent 问题排查](AGENT_DIAGNOSE.zh-CN.md) 补充现场证据；模拟器结果不代表厂商电视验收。

## 容量与隐私

- 日志队列 32 条，普通记录限额 24 条；关键结果优先，并报告各通道的拒收、淘汰、重复合并和写入失败。
- 日常日志轮转上限约 2 MiB。最近一次用户标记的前后窗口各限 512 KiB，后续采集限 30 秒。
- 增强资源、主线程调度和渲染摘要仅限短窗口或受控异常采样。主线程延迟不是 ANR 证明，渲染完成耗时不是 GPU 执行时间或实际呈现时间；不启用常驻逐帧 GPU 查询。
- 快照超限会明确截断。JSON 保留最近最多 1000 条、最多 1 MiB 的事件尾部，并标明省略。诊断 ZIP 上限 16 MiB，进程内最多保留最近四份独立导出；更早链接需重新生成。
- 新增功能快照和事件采用字段允许列表，不导出便签/问候语正文、家长凭据与恢复码、Cookie、连接令牌、精确坐标、用户文件名或备份原配置。异常只保留有界类型与调用位置；常见地址和凭据继续脱敏。

诊断包仍可能包含设备固件、组件及应用相关信息，应检查后私下反馈，不自动上传或作为公开完整设备转储。
