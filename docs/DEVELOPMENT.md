# 工作目录、设备连接与模拟器细则

本页承接 [AGENTS.md](../AGENTS.md)；进入对应任务时读取相关章节。电视安装、接管、维护、升级及恢复从[设备操作统一入口](AGENT.md)分流，APK 构建与发布遵守[版本规则](VERSIONING.md)。

## 工作目录与存储

- 电视各兼容档位共用本地 `main` 的公共源码，手机仓库保留自身常用目录；独立测试包用于明确的专项测试。未完成任务复用原目录及原分支，不为整理存储合入未完成功能。
- 新建隔离目录前核对已有 worktree 的任务、分支、基线、未提交及忽略资料和占用，说明已有目录为何不能复用；告知用途并记录路径、分支。收尾记录提交是否保留、本地资料、占用和外部引用，不把临时目录长期作为通用任务目录。
- 任务开始及收尾运行 `python3 scripts/workspace_storage.py`，默认对照本地 `main`；仅核对明确独立的任务基线时传 `--target <分支>`，需要占用明细时才加 `--sizes`。区分活动目录、已移入“待删除文件”的目录和失效登记；报告不执行删除、移动、分支清理或 Git prune。
- 完成的临时 worktree 列为退役候选。闲置、Git 干净或提交已合入均不足以确认可清理；先保护提交、私钥、配置、测试证据和 APK 历史，核对运行进程、其他任务、脚本/软链接依赖及嵌套仓库。按用户授权移入“待删除文件”，由用户手动删除，保留分支和恢复记录；临时 AVD 的删除例外不扩展到 worktree、分支或共享环境。
- 电视构建入口按 worktree、生产/独立包及完整配置复用 `output/build-cache/`；同配置锁覆盖编译至归档，不按构建号或源码哈希复制全套中间产物。绕开入口的 Gradle 调用不得使用这些受管缓存，不同 worktree 不共用构建输出；手机 Gradle 沿用本仓库固定默认目录。
- `dist/apk/` 原件、签名、校验、构建号预留及归档元数据保留；可变编译缓存不是交付备份。退役目录中的归档须转入仍可被全局构建号扫描发现的归档目录，新增构建脚本输入纳入生产源码摘要。
- 日常截图、日志和普通测试运行以最近 3 次为保留目标，多余部分仅列为核查候选。唯一故障证据、发布验收、设备恢复点及不同内容的数据备份继续保留；离线存储先校验异盘副本，再由用户决定本机原件去留。SDK、AVD、签名、源码及 Codex 历史不属于普通缓存。
- 可用空间低于 25 GB 时只提醒，日常争取保留 40–50 GB，不自动删除或阻断开发。同盘移入“待删除文件”不释放空间；用户删除并清空废纸篓后重新读取可用空间。

## ADB 连接与电脑端服务

- 区分设备端 ADB 开启状态与电脑端服务连接状态。`adb devices` 只反映当前服务持有的连接；单个服务报 `No route to host`、`offline` 或未列出目标，不能据此认定设备离线、IP 变化或 ADB 未开启。已确认目标优先沿用本地登记及会话记录，先核查电脑端；仅在目标不明或存在冲突时询问。
- 异常时先核对目标 TCP 端口可达性、现有 ADB 服务端口及连接，再检查异常服务的 PID、启动时间、程序路径和启动应用归属。macOS 宿主应用退出或更新后遗留进程的局域网权限上下文，只在有直接证据时认定为根因，否则列为推断。
- 同一操作链固定 ADB 程序、服务端口和 serial，使用 `adb -P <明确服务端口> -s <明确 serial>`。优先复用健康的既有服务；临时服务先核对任务归属并记录端口、PID 和目标，不抢占其他任务，不因每次失败不断新增后台服务。临时服务连接成功不等于默认服务已恢复。
- 服务修复须在授权范围内；修复前记录其他需保留服务的 PID 和连接。只对确认异常的服务使用明确 `-P` 端口的 `kill-server`、`start-server` 及连接命令；禁止 `killall adb`、按进程名批量终止或不指定端口重启。不顺带重启健康服务，不擅自重开设备 ADB、撤销授权、重启设备或修改全局网络与隐私权限。
- 修复后确认目标服务发现正确设备并完成只读身份查询；修复默认服务时，普通不带 `-P` 的命令也须正常。核对其他需保留服务的 PID 和既有连接未变。报告事实、推断及未验证项；未测宿主退出、重启或长期运行，不承诺永久不再复发。

## 模拟器与交接

### 复用与运行

- 先盘点已有及运行中的 AVD，按 API、镜像类型、架构、分辨率和测试权限复用；新截图/日志目录不等于新 AVD。默认同时运行一台；新增或多开前告知用途、数量、配置、真实路径及预计空间，记录本次临时实例，不抢占其他任务。
- 默认使用 1080p，TV 横屏为 `1920×1080`；专项测试另有要求时按其配置。核对 AVD 配置、实际 `wm size` 和显示缓冲区，不能只凭配置判断实际分辨率。
- 默认开启硬件键盘及触摸输入：`hw.keyboard=yes`、`hw.screen=multi-touch`。启动后开启并连接 Wi-Fi，优先 `AndroidWifi`，核对已连接且可联网；开关开启或以太网可用不能代替。新建和复用实例均须检查，明确的无键盘、无触摸或离线专项测试除外；不修改宿主机 Wi-Fi。
- 同一 Wi-Fi 下的手机访问模拟器或扫码设置页时，默认使用宿主机当前的 Wi-Fi 局域网地址作为转发入口，模拟器保留自身的虚拟网络地址。新建或复用实例时先核对宿主机 Wi-Fi 地址、转发端口及服务归属，优先复用正常的转发服务。地址变化时按实际 Wi-Fi 地址更新测试入口并说明。改用有线网络入口或调整宿主机 Wi-Fi 配置须由用户明确要求。

### 主包安装与交接验收

- 日常验收固定一个 Quiet TV 主包身份，通用档为 `home.quiet.tv`；厂商专项另行明确包名、用途及环境。同一环境沿用包名和签名，以覆盖升级保留数据，不为小改动另装独立桌面或更换包名绕过保护。
- “最新”以约定的已完成源码提交及生产源码指纹为准，默认核对本地 `main`。未合入任务分支、文件时间、应用名称或最大构建号均不足以证明最新；安装前比对 APK 的 `assets/diagnostic-build.json` 与不可变归档，需要更新时从确认基线构建，不以旧包改名交付。
- 安装前记录 AVD 名称及真实路径、服务端口及 serial、相关包的版本/构建号、签名、启用状态、默认 HOME 和数据目录标识，并核对任务占用。主包构建号沿全局序列递增；同包同签名使用 `adb -P <服务端口> -s <serial> install -r <APK>`，不得降级、先卸载、清数据或恢复出厂。
- 日常验收只保留一个启用的 Quiet TV 主桌面。独立桌面、旧厂商包、HOME 验证组件和带启动入口的测试夹具，仅在确有需要并明确用途时启用；对照及破坏性试验优先专用环境，不把多个同名桌面留作日常交接状态。
- 已授权整理旧入口时，先确认主包可启动且为默认 HOME，再按明确清单逐包执行 `pm disable-user --user 0 <包名>`，保留 APK 和数据，记录恢复命令 `pm enable --user 0 <包名>`。不自动卸载，不改变原生桌面的既有恢复状态，不操作其他模拟器或项目应用；命令沿用固定的 ADB 服务及 serial。
- 交接前读回已安装 APK，核对 SHA-256、包名、版本、构建号、签名及源码身份；验证 HOME 实际进入主包，应用列表和 HOME 候选无启用的旧测试桌面。对比升级前后 UID、首次安装时间、数据目录标识及可读配置/文件；私有数据无法直接核验时说明限制，不把安装成功等同于数据或功能验收通过。
- 交接说明设备、唯一入口、准确版本/构建号、源码提交、默认 HOME、停用包与恢复命令、数据保留证据及未完成项。确需并存的验收包须在可见名称标明用途、版本和构建号；工具未支持时先适配，不只用长期不变的“Quiet TV 2.0 测试”区分。过程记录保留本地，安装不授权远程同步或发布。

### 临时 AVD 清理

- 唯一删除例外：测试后关闭本次启动的实例，通过官方 `avdmanager delete avd -n <确切名称>` 删除本次新建且已提前告知的临时 AVD 及其自身数据。先核对名称、真实路径、未运行及无其他任务占用；禁止递归 shell、删除循环或通用删除脚本。
- 历史临时 AVD 须有明确清理授权并先列清单及影响。保留长期环境、其他任务实例、共享镜像、SDK、密钥、源码和截图日志，不以清空数据或恢复出厂代替清理。
- 官方工具失败或归属不明时保留并报告，不扩大范围；清理后核对保留实例及前后占用。非必需清理不阻断交付。
