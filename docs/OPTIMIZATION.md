# 包体、内存与兼容性优化

本页记录 b21—b23 优化验证；2026-10-20 集成源码已升级为 b24、默认 API23、targetSdk36，详见[兼容记录](android-compatibility.md)。下文的 API31 默认值、API26 实验范围和实测数据均属于当时构建。

本轮保留首页、首次设置、Dock、壁纸和本机 ADB 功能。默认最低系统仍为 Android 12 / API 31；API 26 是单独命名的实验候选，模拟器结果不等于旧电视验收。正式发布与安装到日用电视不包含在本轮交付中。

## 构建与归档

使用现有 JDK 17/21、AGP 8.12.2 和依赖版本，不运行 clean，不清理历史归档。

```sh
python3 scripts/build_apk.py --variant debug --summary "同源码对照"
python3 scripts/build_apk.py --variant benchmark --summary "通用优化验证"
python3 scripts/build_apk.py --variant benchmark --abi arm64-v8a --summary "ARM64 优化验证"
python3 scripts/build_apk.py --variant benchmark --abi armeabi-v7a --summary "当前 ARM32 电视的 API31 优化验证"
python3 scripts/build_apk.py --variant benchmark --abi armeabi-v7a --min-sdk 26 --summary "旧系统 ARM32 实验候选"
```

`benchmark` 关闭调试、启用 R8 和资源裁剪，使用原测试签名以验证保留数据的升级；它不是正式签名的稳定版。`release` 已配置裁剪，但需要另行提供持久正式签名；签名验证失败或未签名的产物不归档。正式签名与既有 Debug 不同，不能直接覆盖安装，不能用卸载或清数据替代迁移设计。

构建前后核对生产源码 SHA-256，构建期间输入变化时拒绝归档；同一源码的不同类型／ABI 候选保留同一生产输入哈希。

输出隔离在 `output/candidate-builds/<类型>-<ABI>-api<最低版本>/`。同一源码的构建类型、ABI、最低系统候选共享代码构建号，以文件名区分。通用 API31 包沿用既有名称；架构包追加 ABI，API26 实验包再追加 `_api26`。实际 SDK、ABI、签名、版本、哈希均核对后写入不可变归档；优化包另存映射文件。不同源码的新交付递增构建号，不覆盖历史包。

包体检查：

```sh
python3 scripts/analyze_apk.py dist/apk/<安装包>.apk --output output/<新的报告名>.json
python3 scripts/validate_profiles.py
python3 -m unittest discover -s scripts/tests -v
```

## 内存与首页刷新

- 壁纸保持 ARGB 色彩、现有图片、900ms 过渡和正式 5 分钟间隔；按显示尺寸选择解码采样，缩略图按需加载。
- 壁纸入口封面复用，过时预览任务在解码前退出；不手动回收仍可能被 View/GPU 使用的 Bitmap。
- 首页在存活期间接收包变化。普通返回复用当前列表；Dock 变化或包变化触发刷新。
- 封面缓存按组件与包更新时间匹配，仅保留本次扫描的应用；刷新失败保留当前列表，并允许后续返回或包事件重试。

## 测量方法与边界

`measure_home.py` 必须显式指定设备。默认只读；`--exercise` 仅允许专用模拟器，会强停／重开桌面、打开设置作为返回场景，但不清数据。时间指标是 `am start -W` 的 WaitTime，不是首个可操作帧。需要先统一 ART 编译状态，再按相同设置、应用清单、壁纸、硬件与负载测量。不能据包体大小推算运行内存。

`check_emulator.py` 按场景串行运行现有 TV 仪器检查：需要第一屏的场景先布置系统 HOME，其余场景使用原基线；结束核对恢复 HOME 和禁用集合，仅允许专用模拟器用户 0。

仪器场景 `memory` 对默认光晕、固定壁纸、轮播分别采样，结束恢复原壁纸偏好；测试进程本身会占内存，结果只适合相同测试条件的对照。该场景只采稳态，不证明峰值内存；另有 `rotation` 场景，按正式五分钟间隔实测并恢复壁纸偏好。

## 机型与 HOME

`setup-presets.json` 的 `devices` 仍只允许经过核验的精确固件规则；新增 30 份 `references` 来自固定上游快照，仅保留公开机型、来源、限制和五项未验证状态。参考记录不得含有可执行设备规则，不能按品牌自动获得操作权限。

HOME 检查记录实际解析结果及候选，识别系统选择器和 Google TV 设置向导。切换前保存记录，失败时只在原连接仍有效、当前用户和旧组件可核验时尝试恢复并读回；取消／断连不重新连接或重放。原桌面本次禁用后如最终 HOME 检查失败，核验包版本和禁用状态后恢复原来的精确启用设置。恢复或默认 HOME 未确认时继续保留未完成记录。

## API26 候选

默认 APK 保持 API31。实验候选隔离 API29 的 RoleManager，兼容 API28 之前的字体与版本号读取，并移除旧依赖隐式附加的电话／存储权限。无线配对仍要求 API33 和可用 JNI，不因最低系统降低而开放。本机身份优先比较 boot_id；应用被旧系统 SELinux 拒绝读取时，以本次随机文件挑战核对同一设备，失败则不开放操作。挑战不含密钥，只清理由本次创建的一个明确临时文件。

Android 8/9/11 的通用 AOSP 模拟器用于 API 与启动链检查，不证明电视固件、遥控器、信号源或 HOME 接管兼容。Android TV 12/13 模拟器及已有真实设备记录分别报告。旧 ARM32 电视和低于 1GB 设备需要单独实测。

### 已执行检查

- Python 归档检查 7 项通过：不可覆盖／重复复用、签名、ABI、最低 SDK、实验包命名、构建输入变化拒绝及包体计算。
- JVM 11 项通过，包含未知固件／权限不继承、参考记录隔离、HOME 解析／冲突、取消和转发期限；最终 API26 Lint 0 错误、24 条警告，未将警告表述为安全扫描通过。
- Android TV 13 的 8 个 Debug 仪器场景通过：HOME 真优先级冲突与恢复、两步设置、焦点、原型还原、连接 UI、实际 TLS 握手取消、Dock、关于页；专用测试 HOME 和禁用集合恢复。
- API26/28/30 通用 ARM64 AOSP 镜像的优化包：首页／原生关于页／Dock／JNI／实际 ADB／设置入口通过，并核对已安装 APK 哈希。旧镜像通过测试专用反向转发连接同一模拟器，不证明厂商本机 TCP 开放能力。
- API26 Debug 负向检查：boot_id 不可读且 shell 不能读取私有挑战时，连接拒绝，不执行系统包写入。
- Android TV 12 新环境的优化包首次密钥生成、ADB 与原生入口通过；已安装哈希匹配。实际五分钟壁纸轮播通过，结束恢复原壁纸偏好。
- Android TV 13 优化包已有密钥连接、实际 TLS ClientHello／取消、JNI 和原生入口通过；已安装哈希匹配。最终原生桌面截图已检查，保留原布局和焦点。

### 性能观察的口径

同一 TV13 ARM64 模拟器、同一生产源码，统一 ART speed 编译后，各测 5 次冷启动和 20 次设置返回。实际壁纸为海岸、index=0、轮播开启但单次停留不足五分钟。初始 Debug 报告标签误写为默认光晕；保留原报告和带更正说明的新报告，原始数值未改写。

Debug／ARM64 优化包的冷启动 WaitTime 中位数均为 670ms；返回中位数为 42／46ms，P95 为 80／130ms。小样本与虚拟机有明显波动，不能声称已证明提速。该次内存快照 PSS 为 57793／44368 KiB，不能外推为日用 ARM32 电视的收益。此前相同仪器方法的 b16／b17 默认、固定、轮播稳态快照有所下降，均保留原记录；未测量完整峰值曲线。

### 边界与失败记录

测试中的 HOME 初始状态假设、仪器任务重叠、旧 AOSP 系统界面／无障碍窗口和调试端口差异均保留失败记录；最终使用串行场景、明确 HOME 前置状态、原生视图回退和专用转发复验。旧的 Dock 检查依赖原保存配置恰好有四项，已改为独立构造不可用占位快捷入口，最后恢复原配置。

尚待：日用电视 ARM32 更新安装与数据保持、其他品牌真实固件、旧 ARM32 设备、低于 1GB 设备、成功六位码配对、长期运行与真实响应时间。正式签名密钥及既有 Debug 用户迁移另行处理；未推送或发布。
