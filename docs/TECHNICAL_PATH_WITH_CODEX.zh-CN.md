# 用 AI 编程工具实现电视桌面：技术与操作流程

[首页](../README.md)  [安装与构建](INSTALL.zh-CN.md)  [兼容范围](COMPATIBILITY.md)

面向已经会使用 Codex、TRAE 等 AI 编程工具的用户。本教程以现有 Quiet TV 源码为基础，带你完成环境准备、设备识别、界面定制、构建安装、默认桌面设置与真机调试；无需先掌握 Android 开发。

**实现路径：获取源码 → AI 阅读与修改原生桌面 → 构建 APK → ADB 安装试用 → 设置默认 HOME → 遥控器验收。** AI 工具在电脑上工作，电视运行 APK；无需 root 或刷机，日常使用无需电脑在线。

用户负责提供目标、操作电视菜单、确认连接授权及反馈遥控器体验；AI 负责阅读代码、检查环境、修改、构建和执行已授权的命令。使用工具中能够访问项目文件和终端的模式；只有聊天能力时，让 AI 给出命令，由你执行并回传结果。各工具界面名称不同，以下提示词通用。

只想安装现成桌面，可直接看[安装指南](INSTALL.zh-CN.md)，无需先完成界面开发。

## 一、准备条件

| 条件 | 要求 |
| --- | --- |
| 电视 | Android 系统，允许安装 APK 和切换第三方桌面；具体能力取决于固件。 |
| 局域网 | 电脑与电视连接同一路由器，可一台用网线、一台用 Wi-Fi；关闭阻止互访的网络隔离。 |
| 调试权限 | 开启开发者选项及可用的 ADB 调试，在电视上确认电脑授权。 |
| AI 编程工具 | Codex、TRAE 等，能够读取项目、修改文件和执行终端命令。 |
| 构建工具 | Git、Python 3、JDK 17 或 21、Android SDK Platform 36、Build Tools 36.0.0、Platform Tools。 |

当前 [1.1.2 测试版](https://github.com/BeatsAD/quiet-tv/releases/tag/v1.1.2) 提供标准档 34（Android 5.0 / API21 起，含 ARM32、ARM64、x86、x86_64）与安卓4.4兼容档 35（API19，无原生库）。按电视系统选包，具体机型与功能仍需真机验证。设备适配状态见[兼容说明](COMPATIBILITY.md)。

## 二、连接电视，读取真实设备能力

**先找到开发者选项。** 常见入口：

- Google TV：设置 → 系统 → 关于 → Android TV 操作系统版本号（Android TV OS build）。
- Android TV：设置 → 设备偏好设置 → 关于 → 版本号（Build）。

选中 **Build／编译版本号**，连续按遥控器确定约 **7 次**，看到开发者模式提示后返回，在“系统”或“设备偏好设置”中进入“开发者选项”。打开总开关（如有）及 USB／ADB 调试。菜单因品牌、固件而异，找不到时按完整型号查询官方说明。参考 [Android 官方开启方法](https://developer.android.com/studio/debug/dev-options)。

**再确认网络调试方式：**

| 可用入口 | 操作 |
| --- | --- |
| 网络 ADB／TCP 调试 | 开启后记录实际 IP、端口，在同一局域网连接并授权。 |
| 无线调试／配对码 | 按页面要求在同一 Wi-Fi 网络配对；配对端口与连接端口可能不同。 |
| 只有 USB 调试 | 不保证网络 ADB 可用；按固件说明确认是否支持 USB 数据连接或其他调试方式。 |

IP 通常在“设置 → 网络 → 当前连接详情”查看。连接后运行 `adb devices -l`：`device` 表示已连接，`unauthorized` 表示需在电视授权；`offline` 或无设备时检查网络、地址、端口和调试开关。USB ADB 不要求同一局域网。

连接、配对与指定目标设备的命令参考 [Android 官方 ADB 文档](https://developer.android.com/tools/adb)。

连接成功后，让 AI 读取系统版本、CPU 架构、应用列表和实际默认 HOME，并保存原桌面状态与恢复方法。多设备连接时明确指定目标电视。

## 三、核心技术

| 功能 | 实现与主要源码入口 |
| --- | --- |
| 首页与应用列表 | `HomeActivity.java` 使用 Java 原生 View、RecyclerView 和 PackageManager 展示、启动应用。 |
| 遥控与焦点 | `HomeActivity.java` 处理方向键、焦点与滚动；Canvas 和动画绘制焦点框、卡片缩放。 |
| 壁纸与配置 | `WallpaperController.java` 管理图片、光晕和轮播；它与 `DockStore.java` 分别用 SharedPreferences 保存壁纸和常用应用偏好。 |
| 默认桌面 | `AndroidManifest.xml` 声明 HOME 入口；`HomeController.java` 检查、切换和读回默认桌面状态。 |
| 应用管理 | `AppRepository.java` 读取应用状态；`AppOperations.java`、`AdbController.java` 等按权限及保护规则逐项操作。 |

上述 Java 文件位于 `app/src/main/java/home/quiet/tv/`；清单位于 `app/src/main/AndroidManifest.xml`。定制时让 AI 先沿这些入口阅读，复用已有功能。

电脑 ADB 用于开发和安装；Quiet TV 内置 ADB 用于电视端应用管理，两者分别授权。未知固件的系统包保持只读，详见[应用管理说明](APP_MANAGEMENT.md)。

## 四、操作流程与分阶段提示词

按顺序在项目会话中发送以下提示词，每步核对结果后再进入下一步。方括号内容替换为自己的信息；设备地址、包清单与恢复记录仅保留本地，不放入公开提交。界面开发和构建可先离线于电视进行，连接设备是安装、适配与真机验收的前提。

### 第 1 步：获取源码，确认环境

**你来操作：** 在终端获取源码，再用 Codex、TRAE 等工具打开 `quiet-tv` 项目根目录。已有克隆直接打开，不覆盖现有工作。

```sh
git clone https://github.com/BeatsAD/quiet-tv.git
cd quiet-tv
```

**发送给 AI：**

```text
请协助我基于当前 Quiet TV 源码定制 Android 电视桌面。
先读取 AGENTS.md、README.md、安装指南、兼容说明和构建配置。
检查 Git 状态，保护已有修改；按贡献指南从最新本地 main 创建开发分支，不以远程同步为前置。
检查电脑上的 Git、Python 3、JDK、Android SDK 和 ADB，按项目要求配置环境。
缺少工具时说明官方获取方式；配置路径使用本机实际值，不写入公开源码。
梳理首页、应用列表、遥控焦点、壁纸和 HOME 切换的现有实现。
本步只完成环境检查和代码阅读，不修改功能、不操作电视。
告诉我哪些条件已满足、哪些缺失，以及下一步需要我做什么。
```

**完成标志：** 项目根目录可访问；AI 能指出真实源码入口，并报告各工具及 SDK 的检查结果。构建环境要求以当前仓库配置为准。

### 第 2 步：连接电视，保存恢复基线

**你来操作：** 按[第二节](#二连接电视读取真实设备能力)开启开发者选项和实际支持的调试方式，查看设备地址，并在电视上确认电脑授权。多台设备连接时指出目标电视。

**发送给 AI：**

```text
现在只进行目标电视的连接与只读检查。
我的电脑系统是 [系统]；电视型号是 [型号或未知]。
电视调试页面显示 [调试方式、实际地址与端口；不清楚时指导我查看]。
根据实际入口选择网络 ADB、无线配对或可用的 USB 连接，不预设端口。
只在需要连接授权或关键缺失信息时让我操作；不要猜测设备。
连接后列出 adb devices -l，确认唯一操作目标，后续命令指定该设备。
读取系统版本/API、CPU 架构、屏幕尺寸、当前用户、HOME 候选与默认 HOME。
记录原桌面的真实组件、启用状态和适用于该固件的恢复步骤，仅保存本地。
不安装、不切换 HOME、不禁用或卸载任何应用。
报告这台电视的适用性、已确认能力和仍需验证的限制。
```

**完成标志：** 目标设备在 `adb devices -l` 中为 `device`；有本次设备的能力记录和原桌面恢复基线。`unauthorized` 需电视端授权；无法连接时先处理网络或固件限制，不继续安装。

### 第 3 步：描述目标，让 AI 定制界面

**你来操作：** 提供参考截图和希望改变的部分，例如布局、配色、常用应用数量或焦点效果。可使用首页截图作为视觉参考；没有额外需求时可跳过修改，直接构建现有功能。

**发送给 AI：**

```text
请基于现有原生实现完成以下定制：[写出具体需求，并附参考截图]。
先说明现有界面与目标的差异、计划修改的文件，再实施最小必要改动。
已有功能直接复用，沿用项目 Java 原生 View 和 RecyclerView 结构。
以参考图为视觉基准，保留未要求修改的文字、布局与交互。
保留当前首页布局、最多五个常用应用、桌面布局设置与方向键导航，
再按我的需求调整壁纸、主题色和动画；不写死他人的应用列表。
应用与信号源从本机实际能力读取，设置保存在电视本地。
验证方向键边界、滚动、确定打开、返回及回到首页后的焦点恢复。
保留首次设置、HOME 状态核验、原桌面恢复和系统包保护规则。
不要顺带升级依赖、重构其他模块或执行设备精简。
本步完成代码修改和对应的本地检查，暂不安装电视。
报告修改内容、实际检查结果与待真机验证项。
```

**完成标志：** 修改范围与需求一致，AI 给出源码差异和实际检查结果。电脑预览或截图比对仅作辅助，遥控体验留到真机验证。

### 第 4 步：构建 APK，安装并临时试用

**你来操作：** 确认目标电视可用，发送安装授权。构建可在电视未连接时完成。

**发送给 AI：**

```text
请先按项目说明构建当前源码，执行与本次改动匹配的检查。
构建成功后报告 APK 路径、包名、版本、最低 API、ABI、签名与 SHA-256。
源码构建与已发布下载包分别核对，不将开发源码版本当作已发布版本。
核对目标电视 API、架构、可用空间和现有安装状态。
如果存在旧版，先检查签名和版本能否保留数据覆盖更新。
我授权把兼容的 APK 安装或覆盖更新到第 2 步确认的目标电视，
并启动 Quiet TV 临时试用；连接目标变化时先核实。
发生签名冲突、版本降级或不兼容时停止安装并说明原因，
不要卸载、清数据、强制降级或改包绕过限制。
首次设置先选“暂不设置，临时使用”，保留原桌面与原默认 HOME。
核对实际安装版本，协助我检查方向键、应用启动和系统入口。
分别报告构建、安装与实际试用结果，不把安装成功当作验收通过。
```

源码默认 Debug 构建命令：

```sh
./gradlew :app:assembleDebug --console=plain
```

Windows 使用 `gradlew.bat`。APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。生产代码修改的构建、Lint 和配置检查要求见[贡献指南](../CONTRIBUTING.md)；安装命令见[安装指南](INSTALL.zh-CN.md)。

**完成标志：** 已生成并核对 APK；目标电视安装版本正确，能启动和临时使用。安装失败或遥控不可用时，先解决问题，再进行默认桌面设置。

### 第 5 步：设置默认桌面，核验 HOME

**你来操作：** 在系统弹窗中完成必要选择，实际按遥控器 HOME 键并反馈进入哪个桌面。

**发送给 AI：**

```text
Quiet TV 临时试用已确认可用。我授权将它设置为目标电视的默认 HOME。
先核对第 2 步的原桌面记录与恢复途径是否仍适用。
优先使用系统默认桌面选择或 Quiet TV 首次设置入口，
需要电视确认时指导我操作；如需 ADB，先确认当前固件支持的命令。
设置后查询实际默认 HOME，并让我按真实遥控器 HOME 键验证。
Success、应用已启动或模拟按键都不等于真实 HOME 验证通过。
若固件拒绝切换，记录限制并保留原桌面，不通过禁用原桌面试错。
本次只设置默认桌面，不禁用、卸载或精简任何系统应用。
提供基于本次真实组件与状态的恢复步骤，分别报告查询与遥控器结果。
```

**完成标志：** 默认 HOME 查询结果正确，实际遥控器 HOME 键进入 Quiet TV。固件阻止切换时记录为未完成，仍可继续以普通应用方式试用。

### 第 6 步：真机验收与问题迭代

**你来操作：** 使用真实遥控器逐项检查，将操作顺序、预期、实际表现和截图发给 AI。需要时授权一次整机重启，检查重启后的默认桌面。

| 检查项 | 通过依据 |
| --- | --- |
| 方向键与焦点 | 首尾卡片、跨行、滚动无焦点丢失；确定与返回行为正确。 |
| 应用与系统入口 | 自己常用的应用能打开；系统设置、网络和实际信号源可用。 |
| 配置保持 | 常用应用顺序和壁纸在退出重进后保持。 |
| HOME 与恢复 | 真实 HOME 键进入 Quiet TV；原桌面可访问，恢复步骤有明确前提。 |
| 整机重启 | 单独授权并实际重启后，核对默认 HOME 与配置；待机唤醒单独记录。 |
| 播放与长期运行 | 使用自己的影音、投屏场景实际测试，未测试的项目保留待验收。 |

**遇到问题时发送：**

```text
真机出现以下问题：
操作顺序：[从哪个页面开始、按了哪些键]。
预期表现：[期望结果]。
实际表现：[现象、截图或视频]。
请核对当前安装版本，结合目标应用的相关日志与代码定位原因。
只修复该问题及直接相关行为，保持其他已确认的界面与功能。
完成对应本地检查并重新构建；沿用前面已授权的目标电视安装范围，
核对设备和升级条件后覆盖更新，让我重测原问题和直接受影响的操作。
未经授权不扩大到系统包操作；日志和设备资料只保留本地。
结束时分别列出源码修改、本地提交、构建、安装、HOME 查询、
真实遥控器、重启和长期运行的状态，未实际验证的项目明确标记。
```

**完成标志：** 验收表有真实结果和待办，原问题已复测。系统应用精简属于额外范围，确有需要时再按[应用管理说明](APP_MANAGEMENT.md)逐项评估和授权，不作为桌面安装的前提。

```text
我会使用 AI 编程工具，希望基于当前 Quiet TV 源码定制自己的 Android 电视桌面。
请阅读 AGENTS.md、README.md 和 docs/TECHNICAL_PATH_WITH_CODEX.zh-CN.md，
遵循其中“操作流程与分阶段提示词”推进，复用现有原生功能。
我的目标是 [描述界面或功能；也可填写“先构建并试用现有桌面”]。
先检查环境与代码，告诉我需要在电视上完成的准备和授权。
随后按设备只读检查、界面定制、构建安装、默认 HOME、真机验收逐步完成。
当前只授权本地准备与开发，安装和 HOME 切换在我发送对应阶段提示词后执行。
不要 root、刷机、清除数据或擅自禁用系统应用。
从实际设备读取型号、地址、应用和恢复信息，不套用其他人的设备资料。
常规已授权步骤连续完成；需要我在电视上授权或提供关键缺失信息时再询问。
无法执行命令或观察真实电视时如实说明，让我执行并回传结果。
代码、构建、安装和真机验收分别记录，设备资料不进入公开提交。
```
