# 电视桌面的技术实现路径：以 Codex 为例

[首页](../README.md) · [文档索引](README.md) · [安装与构建](INSTALL.zh-CN.md) · [兼容范围](COMPATIBILITY.md)

以当前 Quiet TV 项目为例，核心实现路径是：**在电脑上使用 Codex 开发 Android 原生电视桌面，通过同一局域网内的 ADB 连接安装到电视，再利用 Android 的 HOME 机制设为默认桌面，最后结合真实遥控器、截图和日志持续调试。**

Codex 在电脑上完成代码编写、构建和辅助调试，电视运行最终生成的 APK。安装完成后，日常使用无需电脑或 Codex 持续在线。本方案无需 root 或刷机，但具体设备仍需提供可用的 APK 安装、调试和桌面切换能力。

## 一、需要准备哪些条件

| 条件 | 具体要求 |
| --- | --- |
| Android 电视 | 允许安装第三方 APK；当前源码最低 Android 6.0，具体功能仍需核对厂商固件。 |
| 同一局域网 | 使用网络 ADB 时，电脑和电视连接同一台路由器，或处于同一个可互访的局域网。 |
| 网络互通 | 可以一台接网线、一台连 Wi-Fi；访客网络、AP 隔离或防火墙不能阻止两者通信。 |
| ADB 调试 | 电视开启实际支持的网络调试功能，并在电视弹窗中确认电脑授权。 |
| 默认桌面能力 | 固件允许选择第三方默认桌面，或提供可用的 HOME 切换方式。 |
| 开发电脑 | 能运行 Codex、Android 构建工具，并通过网络连接电视。 |
| Codex | 已安装并完成登录，能够访问服务，具备项目文件读写和终端执行权限。 |
| 构建环境 | Git、Python 3、JDK 17 或 21、Android SDK Platform 36、Build Tools 36.0.0、Platform Tools。 |
| 项目与素材 | Quiet TV 源码，以及需要的界面参考图、图标、字体和壁纸；素材需具备使用许可。 |
| 真机验收 | 电视和实际遥控器，用于确认画面、焦点、应用启动和 HOME 返回行为。 |

**同一局域网是本项目采用网络 ADB 时的准备条件。** 电脑和电视不必都连接 Wi-Fi，使用网线与 Wi-Fi 混合连接也可以；关键是能够相互访问。使用 USB ADB 时不依赖这一条件。电视的调试地址和端口应从实际设备获取，不能预设所有电视都开放相同端口。

电脑还需要能够访问 Codex 服务，并在首次配置或缺少依赖时下载 Android SDK 和构建依赖。桌面本身的本地功能不依赖云端账号，第三方影音应用的联网要求由各应用决定。

源码与下载包的系统要求不同：本文记录的源码基线为 **1.1.0 / b24，最低 Android 6.0 / API23**；已发布的 **b23 ARM32 测试包最低 Android 12 / API31**，且需要电视支持 `armeabi-v7a`。源码最低系统要求不等于所有厂商固件均已验收，最新范围以[兼容说明](COMPATIBILITY.md)为准。

## 二、连接电视，读取真实设备能力

在电脑上打开项目目录，让 Codex 检查开发工具，再调用 ADB 连接电视。电视端需要由用户开启调试并确认授权；如果同时连接多台设备，先明确目标电视，后续命令指定对应设备。

连接成功后，读取：

- Android 版本与 API 等级。
- CPU 架构，如 ARM32、ARM64。
- 屏幕尺寸、可用空间和当前用户。
- 已安装应用及其启动入口。
- 实际默认桌面、HOME 候选组件及原始启用状态。
- 固件提供的 HOME、电视信号源和包管理能力。

这些信息用于确定最低系统版本、打包架构和适配范围。例如，ARM32 电视需要兼容对应架构；厂商没有开放的默认桌面能力，需要单独研究适配方式。

操作前记录原桌面的包名、启动组件和启用状态，作为后续恢复依据。设备配置、授权密钥和恢复记录仅保存在使用者本地，不写入公开源码。

## 三、把界面需求实现为原生 Launcher

用文字、截图或设计稿描述首页效果，例如：顶部显示时间、日期和系统入口，中间放四个常用应用，向下浏览全部应用，焦点使用白色圆角框。

Codex 在本地项目中编写和修改 Java 代码，使用 Android 原生组件实现：

| 功能 | 核心实现 |
| --- | --- |
| 时间、日期、网络状态 | 原生 View、系统广播与网络回调。 |
| 常用应用和全部应用 | RecyclerView 与四列网格。 |
| 应用名称、图标和封面 | PackageManager 读取应用资料，缺少电视 Banner 时使用图标生成卡片。 |
| 遥控器导航 | 处理方向键，维护当前行、列和选中项目。 |
| 焦点移动和卡片放大 | Canvas 绘制与属性动画。 |
| 壁纸和主题光晕 | 本地图片、渐变绘制、颜色提取与动画。 |
| 常用应用配置 | SharedPreferences 保存有序包名列表。 |
| 系统设置和信号源 | Android 设置 Intent 与 TV Input 接口。 |

其中最关键的是遥控器交互：上下左右移动到哪里、边缘是否停止、返回后恢复哪个应用，都需要明确规则。首页会保存当前应用标识和位置，返回时恢复选中项目。

核心源码见 [HomeActivity.java](../app/src/main/java/home/quiet/tv/HomeActivity.java)、[WallpaperController.java](../app/src/main/java/home/quiet/tv/WallpaperController.java) 和 [DockStore.java](../app/src/main/java/home/quiet/tv/DockStore.java)。

## 四、构建 APK，修复编译和检查问题

Codex 可以读取和修改项目文件，并运行本机已安装的开发工具；具体能力受所选权限控制，参见 [OpenAI 官方 Codex CLI 文档](https://learn.chatgpt.com/docs/codex/cli)。

按[安装说明](INSTALL.zh-CN.md)配置 Android SDK 后，在项目根目录执行：

```sh
./gradlew :app:assembleDebug --console=plain
```

Windows 使用 `gradlew.bat`。默认 Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

Codex 读取编译结果，修复报错，再执行与改动范围匹配的验证。生成 APK 后，核对包名、版本、最低系统、CPU 架构和签名。

当前项目也支持按架构打包，并通过代码裁剪与资源压缩缩小优化构建的安装包。归档和签名约定见[版本规则](VERSIONING.md)。升级需要保持签名一致，不通过直接卸载或清除数据解决签名冲突。

## 五、通过局域网 ADB 安装，形成真机反馈闭环

获得安装授权后，Codex 调用电脑上的 ADB，将 APK 安装到已经确认的目标电视并启动。具体连接、安装命令见[安装说明](INSTALL.zh-CN.md)，其中示例设备地址需要替换为实际地址。

随后通过截图检查布局，通过日志定位崩溃、权限或启动问题，再根据结果修改代码、重新构建和安装。

```text
提出需求或提供参考图
        ↓
Codex 修改代码
        ↓
构建 APK
        ↓
通过 ADB 安装到电视
        ↓
检查截图、日志和真实遥控器表现
        ↓
针对问题继续调整
```

截图适合检查字体、间距、卡片和焦点位置；真实遥控器用于确认连续移动、长按、确定、返回和 HOME 等行为。模拟按键检查与人工按遥控器检查分别记录。

## 六、通过 Android HOME 机制设为默认桌面

桌面 Activity 在 [AndroidManifest.xml](../app/src/main/AndroidManifest.xml) 中声明 HOME 入口：

```xml
<action android:name="android.intent.action.MAIN" />
<category android:name="android.intent.category.HOME" />
<category android:name="android.intent.category.DEFAULT" />
```

系统由此识别它为可选桌面。随后通过系统默认桌面选择入口，或固件实际支持的 ADB 命令，将 Quiet TV 设为默认 HOME。

设置后查询实际默认组件，并由用户按真实遥控器的 HOME 键确认能返回 Quiet TV。应用已经打开或命令返回成功，均不能替代默认桌面及实际按键验证。

这一步依赖厂商固件的开放程度。能够安装 APK，并不自动代表能够完整接管默认桌面。实现见 [HomeController.java](../app/src/main/java/home/quiet/tv/HomeController.java)，操作和恢复流程见[首次设置说明](SETUP.md)。

## 七、按需要加入电视端应用管理

开发阶段与电视端管理使用两条不同的 ADB 链路：

| 链路 | 用途与条件 |
| --- | --- |
| 电脑上的 Codex → 电脑 ADB → 电视 | 安装、查询、截图和调试；网络方式要求电脑与电视处于同一可互访局域网，并完成电脑授权。 |
| Quiet TV → 电视本机 ADB | 用户直接在电视上管理应用；需要本机开放调试服务，并单独确认 Quiet TV 的授权。 |

Quiet TV 已集成本机 ADB 客户端。应用连接本机调试服务后，核对设备身份、当前用户、命令能力和应用保护规则，再执行单项操作并读取实际结果。

默认桌面替换可以先保留原桌面。预装应用处理作为独立需求，只针对已经核实的应用执行；未知固件中的系统包保持只读。禁用保留安装和数据，卸载会删除当前用户数据，恢复安装不能恢复此前删除的数据。

详细行为和待验收范围见[应用管理说明](APP_MANAGEMENT.md)，实现见 [AdbController.java](../app/src/main/java/home/quiet/tv/AdbController.java) 和 [AppOperations.java](../app/src/main/java/home/quiet/tv/AppOperations.java)。

## 八、完成真机验收与交付

最后核对实际安装版本和 APK 哈希，验证首页、应用启动、壁纸、遥控导航、HOME 返回，以及原桌面恢复路径。重启、长期运行、投屏和完整影音播放，需要分别实际测试。

交付时保留源码提交、版本化 APK、校验文件、变更说明和适用于目标电视的本地恢复记录，分别说明源码、构建、安装和真机验证结果。当前系统版本要求及已有验收边界见[兼容说明](COMPATIBILITY.md)。

本说明记录实施路径，阅读或保存文档不代表已执行安装、切换桌面或系统包操作。
