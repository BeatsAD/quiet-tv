# 桌面配置与恢复

[首页](../README.md) · [应用管理](APP_MANAGEMENT.md) · [兼容范围](COMPATIBILITY.md)

当前源码的新安装和覆盖升级均直接打开桌面，不再自动弹出设置向导，也不要求补写引导完成记录。AI 已完成的系统 HOME、代理或中转配置继续沿用；只安装 APK 尚未配置桌面替换时，也可先作为普通应用试用。

需要调整时，从“应用管理 → 更多 → 桌面配置”主动进入原生设置页；预装应用在“应用管理”中按需处理，同一“更多”菜单保留“恢复原桌面”。电脑侧安装和授权按 [Agent 安装说明](AGENT_INSTALL.zh-CN.md)执行，用户仅完成必要的系统确认和真实遥控器验证。已发布旧包可能仍显示“首次设置”及自动引导，新源码不会改变旧包行为。

## 问题排查

开发源码提供“应用管理 → 诊断日志”标签：Quiet TV 启动后自动记录关键事件与错误，手机同局域网扫码下载，无需手动开始或结束。导出包含设备与 Quiet TV 版本、默认及原桌面、ADB/USB 调试观测和桌面守护状态快照；权限受限或未记录的项目明确标注，调试开关无法确认时不判定为关闭。设备快照包含品牌、制造商、型号、设备/产品代号、硬件平台、Android 版本/API、固件显示版本、系统构建号、增量版本、固件指纹、安全补丁日期、架构及应用版本/包名；同时导出带 `schemaVersion=1` 的“设备统计 JSON”，可与同文件的桌面配置、HOME 解析及用户分场景结果关联汇总。空值或不可读值为 `null`，不推断机型与固件。使用系统 Build 信息，厂商商品名、HyperOS/MIUI 界面版本若未反映在这些字段中，需用户补充；不读取用户自定义设备名称、序列号、Android ID、MAC 或账号，不自动上传。扫码页显示文件名、生成时间和实际字节大小。应用日志不足以定位系统或厂商问题时，可使用电脑侧 [Agent 排查助手](AGENT_DIAGNOSE.zh-CN.md) 采集只读系统日志。已发布旧包不会随源码变化自动更新。

## 两步流程

以下流程仅在主动打开“桌面配置”后使用，不是安装后的必经步骤；已完成桌面替换时无需重复进入，也无需处理预装应用才能使用桌面。

1. **设为默认桌面**：检测可用的系统 HOME 设置入口，进入页面会自动检测并尝试连接本机 ADB，用户主动断开后暂停自动连接。返回后查询实际默认 HOME，确认 Quiet TV 组件可用且已成为默认，再进入第二步。
2. **管理预装应用**：清单来自当前设备扫描。已匹配规则且状态允许的推荐项可选择，在点击执行后按需授权；连接后重新核对当前用户和整组选择，再执行。可选择“不处理，进入桌面”。

第一步保留“暂不设置，临时使用”和退出路径；临时使用不保证 HOME 或重启后仍回到 Quiet TV。右侧是固定桌面示意图，不读取用户真实 Dock 或应用图标；设置页外层壁纸沿用本地配置。

首次打开桌面不读取或改写 `setup-state.json` 来决定是否引导，不清除已有恢复基线、操作记录或应用选择。电脑保存的恢复记录仍由 AI 交付；未核对应用内恢复记录与操作资格时，不承诺应用内“一键恢复”可用。系统 HOME 读回、实体 HOME、重启、冷启动和待机唤醒分别验收。

## 桌面守护（实验）

本地开发更新：无障碍权限区分未授权、已授权等待连接和已连接；界面当前状态与日志中的历史状态分开。原主页为本机有效系统组件 `com.jamdeo.tv.vod/...` 时，标准档在较新安卓上也启用获准后的用量统计补偿，仍只响应精确主页且服从暂停、息屏和其他前台应用。额外检测两个不声明 HOME 的系统组件：`com.skyworth.panasonichome/com.skyworth.panasonichome.MainActivity`、`com.coocaa.aigc.home/com.coocaa.aigc.home.home.rootpage.HomeActivity`。仅加入候选，不按品牌直接选配或开放系统包操作；多候选仍需用户选择。

酷开原主页还会从 `persist.service.model.pkg/cls`、`persist.service.homepage.pkg/cls` 读取，并核对本机已安装且启用的系统组件；属性不可读时额外核对已知的 `com.tianci.movieplatform/com.coocaa.homepage.vast.HomePageActivity`。属性包名和 Activity 的 Java 命名空间可以不同。只有有效目标唯一时才自动选择；冲突时保留选择步骤。系统 HOME 已指向 Quiet TV 也不代表酷开实体 HOME 接管完成，检测到私有主页后仍继续配置原主页中转和必要授权，不自动禁用原桌面或改写主页属性。

电脑配置在执行授权前向新版应用只读核对候选与已选目标；旧包不支持查询时保留兼容配置入口，需明确核对原主页。TCL 的电脑与内置 ADB 配置均按命名 AppOp 探测自启动权限，写入后必须读回对应操作的 `allow`，不使用跨固件不稳定的数字 ID；不支持的操作跳过，拒绝或无法读回时停止并保留已完成授权。电脑记录额外保存 `.results.jsonl` 回执。读回只证明当前值，重启保持需另测。

旧安卓的补偿配置支持帮助命令返回非零但包含有效用法的情况，以及旧版 `appops` 的帮助入口和输出格式；这只适用于只读能力检测，实际授权失败、断线或超时仍停止，不自动重放写操作。电脑脚本也核对远端命令退出码，不能以旧 ADB 的电脑端退出码代替。配置失败会标明步骤，已完成的授权保留；应用再次配置先读回已有权限，只补缺项。权限已配置、守护已连接和开机／唤醒已验证分别判断，配置成功不代表厂商真机验收通过。

标准 HOME 入口补充 Direct Boot 处理：系统未解锁时只显示等待页，不读取桌面偏好、媒体或数据库；解锁后重建首页并正常初始化。等待页不会记为正常首页前台。该代码路径已经过编译与静态检查，锁定启动、解锁、遥控、代理和厂商真机场景仍需验证；不承诺冷启动必定进入桌面。安卓4.4档不因此获得守护能力。

当前开发源码的桌面配置优先使用系统默认桌面；已经可用的配置直接复用，不为可选接管方案重复连接 ADB。需额外排查实体主页路由时，可从“高级与诊断 → 启动方式 → 检测直接接管方案”主动检测，仍须确认清单后执行。系统明确拒绝或不支持切换时，才检测适用的竞争 HOME 和厂商私有路由方案，展示操作清单并由用户确认执行；选择“保留原桌面并继续”后继续兼容配置。预装应用不自动卸载或清空数据。取消系统授权、连接中断、HOME 查询或恢复结果未知时停止，不将异常当成固件不支持。检查修复保留所选路径，只补缺失配置；打开设置页不重新选配。原桌面优先复用有效选择、当前系统桌面及本地恢复记录，确有多个无法判定的候选时才询问。安卓4.4档仍禁用守护、通知恢复、开机跳板和新增接管方案。

### 直接接管与固件专项（开发源码，尚未交付）

| 检测结果 | 可执行方案 | 限制 |
| --- | --- | --- |
| 系统初始设置已完成，原桌面为 Google TV／Android TV 系统包，包状态和恢复命令可核对 | Google TV 仅在 `setupwraith` 参与 HOME 时先禁用它，再禁用 `launcherx`；经典 Android TV 仅处理 `tvlauncher`；最后重新绑定 Quiet TV | 用户确认清单后执行。专用遥控键、语音、投屏、播放和信号源需一并验收；包名相同不等于本固件验收通过 |
| 精确规则已允许禁用原桌面，如现有 Sony 规则 | 暂停旧中转，禁用原桌面，重新绑定 HOME | 可从正在观察的守护切换为直接接管；明确要求保留的依赖仍受保护 |
| 主用户下存在系统 JM 路由组件及 `HOME.JM` 声明 | 保存并写入 `persist.sys.home.selectpkg`，保留原桌面，再绑定标准 HOME | 空原值也准确保存。HY300／txhd2／Android13／t950s_be311／C201_PRO 的工厂 root 接口可连接，不扩大为任意 root |
| 主用户下原桌面为聚好看，`persist.vt.use_home_pkg` 非空且格式有效 | 保存并改写私有 HOME 路由，保留原桌面 | 上游 Android11 实测解决实体 HOME 绕过标准设置；不代表开机首屏也已解决 |

应用方案保存当前用户、固件、原 HOME、包版本和原始启用值，写入前核对，写入后读回。失败时尝试逆序恢复，先恢复真实原桌面，再恢复竞争设置向导，最后恢复操作前的 HOME 和原中转；明确“恢复原桌面”时则切回原桌面。连接取消、换用户或断线时停止，不自动重连重放。通过“恢复原桌面”读取记录继续恢复。其他操作修改过相关状态、固件或原桌面版本变化时停止覆盖，重新排查。直接接管成功后停止旧观察、代理和补偿，之后可按实际开机问题单独配置需要的中转。

TCL 的内置 ADB 授权流程补充自身开机接收组件恢复，以及已识别 `TGuardMemoryManager`、`BackgroundProcess`、`StandbyProcess`、`AppBootPolicy` 结构的自身包条目调整。仅在主用户和预期系统 Provider 下操作，保存原始策略、保留其他应用条目；更新带原值条件，避免覆盖并发变化。未知结构或不可用权限跳过，连接异常停止。日志记录读回数量和不适用数量。读回不证明 OEM 已加载策略，不能把已知忽略白名单的固件标为保护成功。电脑侧旧授权脚本不会自动获得此 Provider 写入功能。

Fire OS 6（API25）检测到系统原桌面 `com.amazon.tv.launcher` 时，获准的用量统计可在无障碍未绑定期间由前台服务观察；无障碍接通后替代服务退出，接管共用同一入口。仅响应最新、精确的原主页事件；仅首尾均为 Quiet TV 首页的已有任务可提到前台。暂停、息屏、锁屏、系统屏保、主动放行原桌面和其他前台页面均受约束。未修改全局 AlarmManager 参数或加入透明覆盖窗口，未向 Fire OS 7／8 泛化。系统屏保期间 HOME 放行，按下和抬起保持配对。

以上是代码支持范围，新路径的 Quiet TV 真机验收尚未完成。能力检测、上游实测、源码已移植、系统读回和本机实体场景通过分别记录。

当前开发源码的“桌面设置 → 桌面配置”普通页面只保留“使用 Quiet TV 作为桌面”、当前状态、“检查并修复”、“恢复原桌面”和“高级与诊断”。开启后自动选择适用方式，缺少必要授权时才引导操作；已授权项目不重复要求选择。“配置已完成”只说明必要配置已核对，不代表实体 HOME、重启、断电开机或待机唤醒已经验收。

启动方式、原桌面、各项权限、同步恢复、保持 ADB 调试、开机跳板及诊断工具收纳到“高级与诊断”。HOME、重启、断电开机和待机唤醒的人工结果从“高级与诊断 → 启动方式 → 记录实际验证结果”查看或记录，不作为日常设置的必填步骤。手动记录标记为用户验证；固件、包形态、应用或相关组件版本变化后显示待验证。关闭总开关持久暂停主动中转和自动恢复，明确提示系统默认桌面保持原状；“检查并修复”不会绕过暂停，须先明确开启。真正切回电视桌面使用独立的“恢复原桌面”入口。

创维／酷开开机跳板接收 `com.skyworth.noriceguide.show`。安卓5及以上的标准档在识别到创维／酷开品牌或制造商，并已选择本机有效系统原主页后，可通过“桌面配置 → 高级与诊断 → 开机跳板”启用，也会在用户执行自动桌面配置的适用路径中尝试启用，不再要求先收录精确固件规则。打开页面、重新检测和升级不会自行启用。若已有精确规则，仍核对该规则的原主页及系统组件版本；无精确规则的路径在日志标为 `runtime_candidate_unverified`，仅表示开放试用，不表示已确认固件会发送此动作。

入口不依赖无障碍连接，不授予权限，不禁用或卸载原桌面，不接受外部指定目标；仅在解锁后、开机3分钟内尝试一次，并与守护共用启动去重和前台确认。已有动作处理者、独立助手冲突、暂停、息屏、锁屏或配置身份变化时不接管。可关闭“开机跳板”单独停用；暂停自动中转也会停用。固件、所选原主页或相关版本变化后需重新配置，单纯记录验证结果不会重新授权旧跳板。仍须分别实测重启与断电开机；它不保证待机唤醒，也不修复系统窗口冻结。

酷开主程序的包名限制已从安卓8下放到现有两种兼容档位，构建参数及能力如下。这是源码支持范围，不表示已发布对应新安装包或已完成酷开真机验收：

| 形态 | 构建参数 | 桌面能力 |
| --- | --- | --- |
| 普通安卓5+主程序 | 默认 `home.quiet.tv`，minSdk21 | 创维／酷开也可使用，支持上述跳板与适用的桌面守护 |
| 酷开安卓5+主程序 | `-PquietApplicationId=com.coocaa.quiettv -PquietMinSdk=21` | 与普通标准档共用功能，支持上述跳板与守护；包名前缀是否获厂商豁免需本机验证 |
| 酷开安卓4.4主程序 | `-PquietApplicationId=com.coocaa.quiettv -PquietCompatibility=legacy19` | 使用现有API19兼容源码和平台播放器；支持普通应用入口及系统允许的默认HOME，不启用守护、开机跳板、HOME代理和新增直接接管方案 |

普通包与酷开包为不同应用，不自动迁移数据。酷开各最低系统档使用同一包名，不能并存；同包升级仍需一致签名、递增版本及数据保留验证。独立的 `coocaa-home-shim` 助手继续按其[目标固件说明](../coocaa-home-shim/README.md)使用，不因主程序下放而扩大适配范围，更不能安装到安卓4.4。发布、选包和更新清单仍按真实包名、兼容档位及最低API区分。

### HOME 代理中转（本地开发，未交付）

自动选配优先主程序直接 HOME。确认不能直接切换后，若已安装与主程序同签名、目标匹配的 HOME 助手，则先准备原桌面回退，再设置助手为系统 HOME 并回读；助手缺失、不适用或系统明确拒绝且原 HOME 已确认保留/恢复时，继续配置原主页识别中转。取消、连接中断和 HOME 未知时停止。小米／Redmi 当前优先使用主程序改包名路线：同源构建时传 `quietApplicationId=com.ts.launcher`，主程序自身声明 HOME，不搭配 HOME 代理；型号及固件不作入口限制。普通包 `home.quiet.tv` 保留历史代理方案，已有配置不自动迁移。同一台设备的改名主程序与同名助手不能并存，安装前核对来源和签名，不覆盖其他同名应用。主程序不会自行安装助手，不覆盖同名的其他来源应用；固件仍可能拒绝助手安装或 HOME 设置，支持尝试不等于该机型已验收。

代理属于“保留原桌面中转”路线，不要求无障碍连接。它只将 HOME 转给主程序受签名保护的入口，主程序再检查当前配置和暂停状态。原桌面及规则中的必要依赖保持保护，暂停后仍不能禁用或卸载。暂停先持久写入 OFF，再通知助手转向独立保存的原桌面；未收到确认会显示待确认，不能宣称暂停操作已全部完成。重新启用恢复原来的代理来源，不会同时打开桌面守护；代理身份或实际 HOME 已变化时保持暂停，可通过“高级与诊断 → 启动方式 → 重新启用并自动配置”明确重新选配。

助手不依赖主程序进程保存回退。主程序缺失、组件不可用、固件或目标版本变化时回原桌面；一次启动未收到前台回执时，短时间内去重，5 秒后下一次 HOME 停止重试并回原桌面。零界面代理无法保证主程序异步崩溃后立即唤起回退；原桌面也不可用时显示恢复页。恢复系统原桌面会先暂停代理，再切换并读回实际 HOME；助手仍是系统 HOME 时不能直接停用。前台回执是软件观测，不等于实体键、画面、重启或待机验收。

标准形态和无 HOME 形态共用这一机制，安卓4.4档不启用代理。独立构建、签名关系及限制见 [HOME 助手说明](../home-proxy/README.md)。

### 无 HOME 兼容形态（本地开发，未交付）

默认构建保持标准形态，声明 HOME，可参与系统默认桌面选择。对于拒绝安装 HOME 应用的固件，可在同一份源码中显式选择 `-PquietHomeMode=relay`；最终合并 Manifest 不声明 HOME，保留普通应用及电视应用入口。兼容形态跳过默认 HOME 请求，先检查 HOME 代理，再配置原主页识别中转，共用保护、暂停恢复、跳板和分场景验证；不新增另一套守护。它与标准形态使用相同包名，覆盖切换仍须核对签名和版本，不能同时安装，也不通过卸载清数据切换。

本地编译检查示例：`./gradlew :app:compileDebugJavaWithJavac -PquietHomeMode=relay`。安卓4.4不提供该形态；未知固件不能因此自动启用厂商跳板。当前没有 TCL p331 的无 HOME 安装对照，不能宣称已解决该机安装限制；TCL 安装、实体 HOME、开机和待机仍待真机验收。本次不归档交付兼容 APK，现有标准归档脚本默认行为不变。

“高级与诊断 → 诊断与恢复工具 → 配置自动恢复”优先复用已授予的系统权限，缺少权限时通过前台本机 ADB 配置写安全设置、写系统设置、通知访问、适用的后台启动权限，以及安卓5／6的用量统计权限；首次系统调试授权仍须由用户完成。自动恢复会重新加入被系统清理的本应用无障碍条目，保留其他服务；系统设置中关闭无障碍与厂商清理仅凭条目无法区分，需要停止恢复时请关闭应用内守护开关。通知访问或写安全设置权限被撤销后不自行重新授予。无 ADB 时可使用无障碍和通知访问系统设置入口，授权后自动继续；没有写安全设置授权时无法自行恢复被移除的无障碍配置。

普通精确原主页窗口事件尽快接管，开机、唤醒和已知切源过渡等待约 1500ms 再复核。开机阶段前台未知时允许一次有界尝试；识别到其他应用、输入播放器、息屏或锁屏则取消。直接 HOME 路线也保留原桌面观察，默认 HOME 正确不阻止实际原主页接管；自动配置继续核对补偿权限。旧 DIRECT 配置在 AUTO 模式下同样保留补偿，明确 OFF 不变。已选 HOME 代理仍维持独立转发和回退，不同时启用观察中转。

开机窗口内在守护连接后约30秒、45秒各复查一次原主页，补偿厂商启动页晚覆盖且未产生新窗口事件的情况。前台未知、其他应用、用户主动打开原桌面、息屏或锁屏时不执行这两次复查。其他品牌的安卓5／6服务已绑定却20秒没有有效窗口事件时，每次系统启动最多请求一次仅本服务的重绑，保留其他无障碍服务。

通知监听只利用系统连接回调恢复，不读取通知内容。首次授权后还配置本应用专用的本地恢复账号与系统同步适配器，通过系统绑定恢复进程，不登录、不读取或传输设置和账号内容；不改变系统总同步开关或其他账号配置。通知监听不可用时可使用此路径，实际恢复时机受系统同步和厂商调度限制，不保证30秒内恢复。总同步关闭时该路径不就绪；暂停停止本账号自动同步，显式重新启用后恢复。不在后台连接 ADB或启用全局按键过滤，ADB调试恢复仅按下文选项执行。安卓4.4仍禁用这些新增组件并移除同步配置权限，不创建恢复账号。

ADB 支持纯数字及旧 toolbox 的完整 uid 输出。额外兼容用户日志对应的海信 VIDAA_TV、API22、MSD6A828 / LVY48C 生产固件：本机核对后，还需身份为 uid=0、SELinux 为 u:r:hshell:s0、ro.secure=1、ro.debuggable=0。其他 root／工程固件继续拒绝；不执行 root、unroot 或属性修改。内置与电脑配置使用同一身份边界，仍核对实际前台用户、组件和命令能力；尚不代表海信真机验收。

海信 MSD6A828 的 Android 5.1.1／`LVY48C/01.02.40.01` 固件另有[上游同固件记录](https://github.com/pengchujin/aerial-tv/issues/285)：无障碍写入可能无报错但读回仍关闭。当前源码在“配置自动恢复”的前台 ADB 流程及电脑配置工具中先写入并读回；只有该完整固件指纹、主用户和原本已隐藏且仍安装启用的 `com.hisense.vidaaassistant` 全部匹配，才临时 `pm unhide` 触发包状态刷新，合并恢复本应用无障碍条目，再 `pm hide` 还原原来的隐藏状态。其他服务条目保留；包未隐藏、缺失、禁用或状态不明时不改变厂商包，不通过先隐藏来制造条件。成功和失败均尝试恢复并读回，应用保留按用户／固件隔离的恢复记录；连接中断时不报成功，下一次明确连接配置先核对并恢复遗留隐藏状态。电脑工具在私有结果记录中保留原状态及恢复命令。

此路径只修复明确连接 ADB 时的无障碍恢复，不常驻或在后台连接 ADB，不禁用原桌面，不修改私有 HOME 属性。普通后台恢复会核对设置读回；若固件仍拒绝写入，提示连接 ADB 修复。权限写入、守护绑定及实体场景分别确认，不承诺消除开机先显示原桌面的约10秒延迟，也不保证下一次开机仍保留无障碍。当前为源码适配，目标海信真机验证待完成。

小米／Redmi 标准档按品牌及 Android 版本补充开机恢复，不要求型号或固件指纹匹配。开机前 3 分钟内安排 30、45 秒两次延后复查，处理首次接管后又被原厂开机页覆盖的情况；每次都重新检查可见条件与前台证据，设置、儿童模式及输入播放器不会仅因属于原桌面包而被当作主页。暂停、息屏及服务断开会取消待执行检查。原主页识别中转只要求所选系统 HOME 组件仍然可用，固件更新本身不会关闭守护；专用厂商跳板和 HOME 代理保留各自的身份核验，场景验收记录仍会在基线变化后失效。

Android 5／6 的小米／Redmi 在守护连接或恢复后等待 20 秒，若没有收到窗口事件、已有写安全设置权限且守护仍启用，会在每进程最多一次的范围内短暂关闭并于约 1500ms 后恢复无障碍总开关。这会短暂中断其他无障碍服务，但不修改它们的服务列表；即使期间暂停守护，也会恢复总开关。该处理参考上游针对“已绑定但没有事件”的恢复机制，其他品牌、新安卓及安卓4.4档不执行。恢复限次只计本次开机，息屏时的进程恢复不累加，以免上次开机或多次待机阻断新的开机补偿。

服务暂时断线不会关闭用户的自动策略。主动桌面配置在系统 HOME 无法修改、但兼容守护已连接时可以完成“兼容守护已配置”路径，保留原桌面并跳过系统包修改，不宣称默认 HOME 已改变。从应用列表主动打开原桌面临时放行；系统投递 HOME 动作时尝试返回 Quiet TV，固件不投递该动作时依赖主页窗口事件，安卓5／6另有获准后的前台统计补偿；“暂停并打开原桌面”及恢复原桌面会持久停用。选择临时使用或取消桌面配置时不继续自动接管。旧版明确暂停的状态保留；无法判断旧关闭来源时也保留关闭。

守护不读取屏幕内容，不修改系统 HOME，不自动禁用或卸载原桌面，不建立后台 ADB 会话或修改厂商属性。ADB 调试恢复仅在用户单独启用下文的选项后执行。启用前停用独立小米助手；检测到独立酷开助手时保持互斥，不自动卸载。进入 Quiet TV 后以页面实际前台焦点回报确认；只发出启动请求或超时不显示成功。

切换速度取决于绑定、系统调度和界面绘制，不承诺所有电视毫秒级切换。实体 HOME、重启、断电冷启动、短长待机、HDMI/播放和恢复原桌面须逐固件验收；通用模拟器结果不替代厂商电视验收。

### 小米／Redmi 同步恢复与 KEEP_ADB（本地开发）

针对 Xiaomi MiTV-MFTP0 / alita、Android 9 固件 `xiaomi/alita/alita:9/PPR2.180905.006.A1/6129:user/release-keys`，当前用户 0、原桌面 `com.mitv.tvhome/com.mitv.tvhome.MainActivityUserMode` 构建号 1621，已加入用户实测的直接接管规则。2026-10-26 用户反馈禁用原桌面并保持 ADB 后可用；诊断确认原桌面为 disabled-user、系统 HOME 指向 Quiet TV、ADB 已连接。这是该固件的反馈，未分别记录实体 HOME、冷启动及待机唤醒验收，不扩大到其他固件或原桌面版本，也不开放卸载。

首次配置仍从“自动配置”进入。已有正常中转在常规检查中保持原方案；需要切换时，可从“诊断与恢复工具”显式尝试直接接管。标准设置未生效时会提供直接接管方案，可选“仅直接接管”或“接管并保持 ADB”。后者仅使用已连接并核对的 TCP 端口，保存并设置 `persist.adb.tcp.port`，在需要时授予写安全设置权限，启用应用内调试恢复。先保存原状态，再禁用原桌面、绑定 Quiet TV 并读回；属性或 HOME 未生效会进入原有回滚流程，断线不重试写入。恢复原桌面时还原本次记录的端口属性、保持选项及新增授权；撤销新增权限放在 HOME 恢复之后。已有权限不撤销，已有 TCP 会话不会被主动关闭，不把属性读回当作重启验收。

按用户明确要求，MiTV4-ANSM0 / xmen、Android 6.0.1 固件 `Xiaomi/xmen/xmen:6.0.1/MHC19J/2035:user/release-keys` 也开放相同的实验接管流程，仅匹配用户 0 和上述原桌面组件、构建号 1621。该机日志记录按 HOME 先到小米桌面，约 5 秒后守护返回 Quiet TV；这是试验授权，不是该机禁用、恢复或开机验收通过的记录。已有中转配置不会因升级自动禁用原桌面，须从“诊断与恢复工具”选择“接管并保持 ADB”。不匹配机型、固件、原桌面版本或用户时不执行这项接管，不开放卸载。

如果同一规则下原桌面已经被用户禁用且 HOME 已指向 Quiet TV，再次自动配置只确认直接启动并保留当前禁用状态，不重复禁用，也不伪造之前的启用状态。禁用原桌面后，保持 ADB 和本地同步可独立工作，不需要重新开启无障碍中转；诊断区分选项开启、恢复条件就绪、当前 ADB 连接及待验证的重启持续性。该开发改动尚未打包、安装或完成新增代码的真机验收。

标准档在启用守护（包括直接HOME补偿和原主页识别中转）后注册“Quiet TV 桌面守护”本地账号，以系统 settings 同步通知恢复进程和守护，作为通知监听不可用时的替代入口。同步适用性按Android及系统账号/同步能力判断，小米特有恢复和KEEP_ADB另按品牌选择，不限制具体型号或固件；Android9低内存设备无需强行授权通知监听。该账号没有登录、密码、令牌或远程数据传输，卸载后由系统移除。暂停中转关闭本账号的自动同步并取消待执行同步，保留空账号；重新启用时恢复，不修改其他账号。

系统总自动同步须开启，网络须满足系统同步调度条件；即使本账号不传输数据，Android也可能要求已验证的网络连接。应用不会打开总同步或绕过系统限制。状态显示在“桌面配置 → 高级与诊断 → 同步恢复”，可从中进入系统同步设置。系统调度、息屏及固件限制会影响恢复时间，不能保证30–60秒内完成。同步回调只在配置有效时恢复守护；没有前台证据时仍检查之前是否处于Quiet TV首页，避免拉走播放器。息屏恢复、启动/刚升级和同进程多入口回调不重复累计为频繁被杀。

“保持 ADB 调试”（KEEP_ADB）默认关闭，需用户单独选择开启，并已持有写安全设置权限；上述精确固件的“接管并保持 ADB”也属于明确选择。开启后通过设置变化、开机/解锁及同步回调尝试恢复被关闭的 `adb_enabled`，不进行配对、授权握手或后台ADB连接。保持条件独立于原桌面是否启用及无障碍是否连接；自动恢复暂停或关闭选项后停止恢复，不主动关闭已有调试连接。Android10及以下仅在开机3分钟内，对应用中已明确配置的TCP端口做一次本机探测；端口不通时最多一次短暂关闭后恢复ADB。未知端口、USB单独调试及Android11+无线调试不会套用5555。缺少授权时后台不自行授权；只有用户明确选择的前台配置可以授权并记录原状态。

安卓4.4档禁用账号、同步服务及KEEP_ADB，Manifest不申请新增的账号/同步权限。标准、无HOME及独立包名共用实现，账号类型随实际包名隔离。是否具备上述功能须核对选定发布 APK 的实际组件与能力；模拟器验证不能替代小米真机待机验收。

## 原桌面与安全范围

原桌面提供保留、禁用、卸载选择，但实际资格由当前 HOME、包状态、系统能力和固件规则决定。必须保留的固件、原桌面依赖和未验收的原主页在执行层受到保护，暂停中转不解除保护，无 HOME 兼容形态始终保护所选原桌面。只有原有已验收机型的独立手动管理路径保留原资格；自动配置不选择禁用或卸载。卸载涉及数据后果确认；未开放的原桌面卸载／恢复安装仍不可用。

`app/src/main/assets/setup-presets.json` 的可执行规则按固件指纹及可选品牌／机型精确匹配；参考资料不授予操作权限。未知设备可查看应用，系统包保持只读，不套用其他电视的清单。

每次操作核对本机连接、前台用户、系统 HOME 和包状态。原桌面禁用或卸载成功后重新设置 HOME，因为 HOME 候选变化可能清除原偏好；设置失败时，禁用操作沿用原状态恢复流程。命令返回 Success 不代表 HOME 已切换，必须读回组件；取消、超时或断连后不自动重放修改命令。失败停止后续包操作，不将已经成功的多项操作当作可自动回滚事务。

“系统 HOME 已指向 Quiet TV”仅说明系统解析结果。请另外按实体遥控器 HOME，并分别确认重启、断电冷启动和待机唤醒。厂商可能绕过系统 HOME；这些实际结果不能由解析查询替代。

## 恢复与记录

应用私有 `files/setup-state.json` 保存设备／用户基线与运行状态，`files/app-operations.jsonl` 保存单包操作记录。记录不是应用数据备份；中断后重新查询，不自动续做。恢复原桌面先确认安装、启用及组件可用，再切回 HOME；恢复安装不恢复已删除数据。

## 遥控与连接

白色外框表示实际焦点，底色和勾选表示当前选择。方向键覆盖原桌面选项、推荐卡片、底部操作和返回；只读项可聚焦查看原因。弹窗有独立焦点，关闭后回到来源控件。连接端口框按确定打开输入法，返回先结束输入，再用上下键移出。

无线配对仍为实验功能，要求 Android 13+、可用原生库及设备实际提供配对服务。Android 11 / 12 有系统无线调试时，可先在电脑使用官方 ADB 配对；电脑授权与 Quiet TV 本机授权分别处理。配对码不写入偏好或日志；取消或超时关闭传输。连接过程中离开页面，最多保留 60 秒供系统授权确认，原先待执行的设置操作仍取消，返回后须重新确认。开发者入口隐藏时可尝试 Activity Launcher 打开系统页面；调试开关被锁定且无可用配对入口时，本项目不能解锁，仍可选择临时使用。连接超时不等于已确认固件封锁。历史验证不等于所有设备与完整流程已通过验收，具体边界见[兼容范围](COMPATIBILITY.md)。

## 通过电脑配置守护

1.2.4 标准版已包含基本电脑配置入口；1.2.5 候选补齐开机恢复与同步配置。安卓4.4不提供桌面守护，厂商实体 HOME、重启和待机唤醒仍待验收。

电脑已经能够执行授权后的 ADB shell 时，可独立完成守护配置。Quiet TV 内置 ADB 使用另一份密钥，内置握手超时不代表电脑不能配置。无需导入电脑密钥，也无需先把系统默认 HOME 改成 Quiet TV；此流程保留原桌面，不禁用系统应用；默认保持原 ADB 选择，仅显式使用下文参数时改变调试恢复选项。

先核对实际安装包包含 `home.quiet.tv.HomeGuardSetupReceiver`，并记录设备、当前用户、原主页及已有权限。历史 1.2.0 APK 不会因文档更新获得该入口。脚本需要本修复对应的 APK、Python 3 和电脑上已经授权的 ADB；不负责连接、安装或更新。先按[电脑侧检测说明](../skills/quiet-tv-switch/references/operations.md)确定目标和用户，再在仓库根目录预览：

```sh
python3 scripts/configure_home_guard.py --serial "$TV_SERIAL" --user "$TV_USER"
```

用户明确授权首次配置并启用守护后执行；`TV_SERIAL`、`TV_USER` 必须换成本次核对值。`--record` 为新的本机私有 JSON 路径，不覆盖现有记录；其中包含设备标识、原有服务列表和权限状态，不提交或公开。

```sh
python3 scripts/configure_home_guard.py --serial "$TV_SERIAL" --user "$TV_USER" --apply --record "$GUARD_RECORD"
```

原主页无法唯一确定时，先在电视选择原桌面，或以 `--home "$ORIGINAL_HOME"` 指定本机检测到的真实组件。脚本核对用户和命令能力，先保存授权前状态，再授予必要权限，通过受 `WRITE_SECURE_SETTINGS` 保护的入口启用守护。Android 7.1及以下由应用合并通知监听列表；新系统按实际命令能力配置。失败停止后续步骤，已完成的授权保留，不自动回滚或清除数据。再次执行需另建记录。

返回结果分别提供 `accessibilityAllowed`／`accessibilityBound`、`notificationAllowed`／`notificationBound`、`usageRequired`／`usageAllowed`；`configured=true` 只表示所需权限已配置，服务绑定可能稍后完成，不代表实体 HOME 或开机已经验收。低内存固件不支持通知监听时明确记录该限制，不能宣称待机后必然恢复。

新版返回值另含 `desktopRoutes`：区分标准／无 HOME 包形态、真实系统 HOME、中转就绪及分场景用户验证结果。电脑工具仍专门配置中转，不会修改默认 HOME。需要暂停时使用同样的 `--serial`、`--user`，加 `--pause` 预览；明确执行时加 `--apply --record <新的私有记录路径>`。暂停不授予权限、不修改系统 HOME，旧 APK 不支持暂停入口时报告未确认；不能将广播发出当成暂停成功。

Android 5／6 标准档以及上文限定的 VIDAA、Fire OS 6 路径获准后，每秒读取最近10秒中最新的前台 Activity 事件，只在精确原主页出现时补偿接管，同一次事件只处理一次。读取内容仅用于本机判断，不记录其他应用的逐次操作。暂停、息屏、锁屏、系统屏保和主动放行原桌面时不接管；直接接管且未启用观察时也不接管。原厂儿童模式、设置、播放器及开机引导页不会仅因包名相同而被识别为主页。其他新安卓不泛化该补偿，安卓4.4档保持禁用守护。

完成后分别测试：内置 ADB 失败下的电脑配置、实体 HOME、重启、断电冷启动、BootActivity 覆盖后的返回、短／长待机、HDMI／播放不中断、暂停及重新启用。记录返回耗时；ADB 注入按键不能代替实体遥控器。需要暂停时关闭电视中的守护开关；撤销本次授权需结合私有记录逐项恢复本应用状态，不覆盖后来新增的其他无障碍或通知服务。

### 一键安装与 ADB 选择

电脑安装统一使用 [Agent 安装说明](AGENT_INSTALL.zh-CN.md#统一安装入口)及 `scripts/install_quiet_tv.py`，复用当前守护接收器，不要求再走内置 ADB 或设置向导。选择 `takeover` 才配置接管；`trial`、`update` 保留已有守护和 ADB 选择。当前公开包是否具备接收器，以实际 APK 核验为准，本文不把源码存在当作已发布或真机验收。

直接运行 `configure_home_guard.py` 时可显式添加 `--keep-adb`（小米／Redmi）或 `--no-keep-adb`；省略两项保持原选择。参数传给已有 `HomeGuardSetupReceiver` 的 `keep_adb` 字段，并核对应用读回。权限配置和调试设置恢复均不证明 TCP 端口持续可用，Android11+不套用5555。只读验收使用 `verify_install.py`，不注入按键、不启动应用、不重启。
