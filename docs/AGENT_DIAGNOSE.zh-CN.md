# 使用 Agent 排查 Quiet TV 问题

[首页](../README.md)  [桌面配置与恢复](SETUP.md)  [Agent 安装与恢复](AGENT_INSTALL.zh-CN.md)

开发源码支持从“应用管理 → 诊断日志”标签扫码下载 Quiet TV 自身的关键事件和错误，无需 ADB。用户照常按遥控器操作，完成后导出日志即可，不需要另行开启、停止或配置采集。该日志不包含完整系统日志，已发布旧安装包不会随源码变化自动更新。

2.0 可从电视导出页或手机扫码设置生成同结构的诊断包，也可标记刚才的问题并继续记录 30 秒。格式、覆盖、性能与隐私边界见 [2.0 诊断说明](DIAGNOSTICS.md)。

## 记录问题与完整诊断包

故障出现后，在诊断页点击“记录刚才问题”。这会保留标记前最近最多512 KiB的应用事件，并继续保存之后30秒最多512 KiB的应用事件。等待30秒后点击“完整诊断包”，再扫码下载 `QuietTV-diagnostics.zip`；“重新生成”仍导出原有TXT。页面原先生成的下载内容不会随标记自动更新，需要重新生成。每次新标记只保留最近一次窗口，正在录制的30秒内重复点击沿用同一标记。窗口不包含标记后进程停止期间的事件，重新启动会注明中断而不续录；标记时间是用户记录时间，不是自动识别的故障起点。未标记也可导出普通日志与完整包。

生成期间暂停三个导出按钮，重复操作不排队；离开页面或息屏后，旧任务在后续采集、打包阶段前停止。返回页面时，等待未结束的旧阶段退出后再生成一份新日志。

完整包固定包含三项：`diagnostics.txt`（当前快照、轮转历史、标记窗口及可用的蓝牙系统摘要）、`diagnostics.json`（会话身份、当前进程采集质量、最近最多1000条／1 MiB应用事件、窗口覆盖信息），以及 `manifest.json`（前两项大小和SHA-256）。ZIP最大16 MiB，不收集任意文件、媒体或数据库。JSON是有界摘要，不能代替TXT中的窗口和系统证据；TXT与JSON分别注明采集时刻，不宣称完全相同的截面。蓝牙系统摘要依旧遵循下节的权限与数量限制。

新版事件带诊断格式版本、进程会话、匿名开机会话、构建号、源码指纹、PID及设备单调时间。导出头另外记录当前版本、签名摘要及安装／更新时间。跨升级历史按每条事件的身份归属；没有会话字段的旧记录标为身份未知，不能套用导出时的版本。源码指纹来自构建时的生产输入，构建脚本归档时核对APK内指纹，并在本地构建记录中关联源码及可用的混淆mapping；没有对应归档时不保证能还原混淆堆栈。源码归档不含Git时提交号可为unknown，仍保留内容指纹。

采集质量按通道保存当前进程的入队、重复合并、拒收、淘汰、写入成功／失败数量，以及最近观察和缺失时间；JSON另外注明轮转序号、摘要省略和解析失败。没有出现的通道不等于该功能正常，也不证明已经注册观察器；它仍可能受权限、版本、进程生命周期或系统日志可见性限制。较早轮转覆盖的总量无法补算，当前质量也不代表上一个进程的质量。比较耗时前应先核对进程／开机会话和时间基准，不跨重启相减。

## 应用退出与安装诊断

首页手动打开、自启应用和共享外部入口会记录自身请求的来源、目标组件、action、系统categories、flags及操作编号，不记录Intent数据、extra值或页面文字。`dispatched_unverified`只说明启动调用返回，不证明第三方应用已正常播放，也不表示Quiet TV读取了其他应用的生命周期。第三方退出、被其他前台请求覆盖、进程死亡或崩溃的区分，需要升级前开始的[电脑采集与指定应用观察](agent/bluetooth.md#指定应用的前台与退出证据)。

在线更新和接收APK新增统一 `install.evidence.*` 记录：来源、attempt／session、安装路线、已有的APK哈希与签名摘要、目标包版本，以及校验、准备、写入／fsync、提交、确认和返回阶段。系统有提供时保留公共status、legacyStatus和固定白名单原因；缺失保留unknown，不保存任意系统错误消息。`package_installer`状态码与`activity_result`返回码分别命名，不能直接混用。系统报告成功仍记为待核对；读取实际包版本、签名和更新时间后另记readback，查询失败也明确标记。新诊断字段不修改原有配对、按键消费或安装结果策略，不能凭一个公共状态7确定根因。

## 输入、壁纸与资源的增强诊断

“记录刚才问题”现在也开启30秒增强观察。需要排查焦点乱跳、重复按键或模糊不显示时，可以先标记，再在30秒内重复原操作，结束后重新生成完整包。标记前的冻结历史仍是当时已有的普通记录，不能补回此前未采集的重复键、摇杆或性能现场。进程退出后不续录；重复标记不延长正在进行的窗口。

| 内容 | 可以检查的证据 | 判断边界 |
| --- | --- | --- |
| 输入 | 导航键flags、重复次数、取消／长按标志、窗口分发返回、按下／抬起焦点、窗口内未配对回调；窗口内摇杆X/Y/HAT_X/HAT_Y数值、MotionRange和观察范围 | 回调缺失可能是窗口边界、采样或系统未投递，不自动判为卡键；同逻辑设备的轴与按键只作时间关联，不宣称系统合成关系 |
| 输入设备与服务 | 设备ID、加盐描述符、source、虚拟属性、适用的厂商／产品编号；已有ADB下读取蓝牙与已记录原桌面的服务、进程、绑定字段、包启用状态，以及可见服务的组件设置 | 不按名称、event节点或逻辑ID猜测蓝牙设备；未显示服务不等于服务不存在或未绑定，不扫描未知厂商服务 |
| 壁纸与模糊 | 首页／第二屏保存及内存读回、桌面／预览实际使用值；取帧来源、PixelCopy原始状态、generation、排队／处理／提交耗时、空帧、过期丢弃、缓存及最终图层状态 | 保存读回不证明磁盘持久化完成；View或API返回不证明电视实际显示；位图和RenderEffect后端按实际适用路径记录 |
| 设置／恢复／切源 | 设置请求、观察和返回共用操作编号；恢复确认、暂停回执、实际选择的路由、HOME／原桌面可用性读回；切源与守护决策的过渡编号及实际可读稳定期 | 派发、默认HOME变化、临时打开和用户确认分别记录，不自动确认画面、声音或恢复成功 |
| 短时性能 | 标记窗口的主线程调度延迟摘要、关键异步阶段耗时；窗口开始／结束或限频失败时的自身PSS、Java堆、原生分配和内部剩余空间 | 有排队时间和采集耗时；不持续采线程栈或逐帧性能，不据此单独认定ANR、GPU或厂商硬件故障 |

增强按键和焦点记录沿用现有窗口与无障碍回调，不增加过滤、按键注入或消费规则。只观察已有KeyFeedback窗口及首页／相关弹窗收到的输入，不保证覆盖所有第三方窗口。摇杆范围最多跟踪8个逻辑设备，只记录四个指定轴，不采集触摸位置或文本；每类细节在30秒内最多准入120次，轴细节至少间隔250毫秒，焦点至少间隔50毫秒，模糊阶段至少间隔1秒。窗口内可能存在更多回调，范围摘要与`extraProbes`的`sampledOut`帮助辨别缺失；次数是观察次数，不是实体操作次数。

普通运行保留设置、状态变化及首次空帧／丢弃等关键记录；连续捕获／提交耗时只在增强窗口展开。增强诊断使用有界缓存和限频，资源采集在独立线程，最多排队4项，主线程延迟采样最长30次。主线程或进程被阻塞时，结束摘要可能延后；检查导出时的`active`、采样数和完成事件，不将“30秒已过”当成完整采集证明。窗口结束摘要写入普通历史，可能在冻结后窗口的截止时刻之后。

输入eventTime、模糊阶段、守护剩余等待和主线程调度延迟使用uptime；资源采集排队使用elapsedRealtime，网络耗时使用独立nanoTime。墙钟与这些基准各自保留，只在相同基准内比较，不跨重启或把深睡时间混入另一种计时。

壁纸服务转发的事件另带`originRole`、`originSession`、`originPid`、原构建／源码及原始时间；导出主进程字段继续独立保留，不能把转发者PID当成解码进程PID。未知旧事件不补造来源。服务断连、死亡与释放继续沿用已有事件；来源、Surface代次和最后成功帧用于对照，仍不代表持续播放正常。

各档位使用同一套诊断代码，字段按实际系统能力保留：

| 能力 | 适用范围与替代路径 |
| --- | --- |
| 操作关联、流指纹、窗口导航／四轴、主进程资源摘要 | Android 4.0及以上共用；只观察实际收到的事件与可读取资源 |
| 输入设备变更、匿名描述符、虚拟属性 | API16及以上；API14–15以窗口及导出时查询为主，相关字段写unsupported／unknown |
| 输入设备厂商／产品编号 | API19及以上；低版本不猜硬件身份 |
| 原生视频PixelCopy与RenderEffect | 分别API24、API31及以上；其他情况沿用原有TextureView／海报／位图处理分支并记录实际来源，不为了诊断切换后端 |
| 系统服务、绑定与组件读回 | 依赖已有ADB、可见组件及厂商输出，不以最低API承诺字段齐全 |

## 文件、存储与网络对照

文件接收和壁纸导入在原有流读取中计算内容摘要，导出时用本机盐保护；接收编号、导入编号和素材编号关联保存与使用。旧素材没有指纹时保持unknown，不在导出时自动重扫媒体。图片可能经过转换，指纹明确指向导入源字节，使用事件注明当前文件未重新校验；不能把源指纹当成转换后文件哈希。不同安装或设备的加盐指纹不能直接比较，也不等于APK的公开SHA-256。APK安装继续复用已有校验哈希，并关联已验证的接收编号。

空间记录使用原检查的incoming、available、reserve、maximum、已用量、文件数和配额，不改变准入条件。接收区有现行文件数／总量限制，壁纸没有总量配额时写`not_applicable`；可用量为0时注明`zero_or_unknown`，不自行断言真实磁盘已满。内部媒体、接收目录和安装副本分开记录，不能将某处空间不足套用到另一处。

在线更新及每日壁纸网络增加父request和每源attempt，记录连接／响应头／读取／校验阶段、HTTP状态、读取字节、重定向数和独立计时；原有DNS／TLS／HTTP分类继续保留。镜像失败、后续源成功、APK校验通过和安装器拒绝是不同事件。每日壁纸HTTP正文读取完成只标为`body_received_unverified`，不等于媒体解码成功；缓存复用也不冒充网络下载。新记录不包含完整URL、请求头、令牌或服务端正文，不调整回退顺序、超时、断点续传或校验策略。

## 蓝牙配对与连接诊断

本次源码新增的蓝牙诊断随普通日志一起导出，保持原有配对逻辑。应用进程存活期间，被动记录配对状态前后值、系统提供的失败原因原值、ACL与HID主机连接变化，以及输入设备增加、移除和变化；不会扫描、配对、解绑、重连、切换蓝牙开关或扩大按键过滤。Android 12及以上需要先在诊断页点击“允许读取蓝牙状态”，由用户授予附近设备权限后再复现；拒绝时仍能导出，并标记状态读取受限。Android 4.0／4.0.3不支持输入设备变化监听，其余可用蓝牙观察仍保留。

导出包含当前适配器状态、已配对设备匿名编号和本进程最近连接事件。已配对不代表已连接，ACL连接不代表遥控按键通道可用；缺事件或查询受限均记为未知，不能解释为断开或没有故障。设备以本机加盐摘要关联，不保存名称、MAC、配对码或密钥。

已有管理ADB连接可用时，蓝牙事件和导出操作会触发独立只读采样，复用当前已验证端口、用户和已有授权，不新建密钥、不要求新的授权、不修改系统设置，也不占用普通管理命令的连接。采样读取蓝牙、输入、无障碍状态，以及系统实际支持的近期Logcat缓冲区。每项最多3秒、512 KiB原始输出；原始内容只在内存中解析，保存状态码、固定事件、相关服务类名、进程信息等结构化摘要，每项最多64条。系统记录另用两个固定文件轮转，总计最多2 MiB。受限、超时、未解析和省略情况随日志导出，摘要不是完整原始系统日志，不能保证自动确定根因。

采样不会持续录制系统日志，进程退出、升级替换、权限缺失和ADB不可用期间可能缺失；诊断页会等待采样最多12秒，尚未结束时导出已保存部分并明确标记。排查安装后立即发生的异常，应在电脑上从重装前开始持续采集，覆盖升级中应用进程退出的时间。以上为源码能力，厂商电视的广播、HID服务、权限及日志可见性仍需实机验收。

升级专项现提供[电脑连续取证与对照验收](agent/bluetooth.md)，包含独立采集工具、现有电脑操作脚本的可选前后读回、用户步骤标记及两组对照流程。新版应用日志增加 `system.configuration`、`system.operation` 和 `input.route`，同步到 `QuietTVDiagnostics` 系统日志标签；实体按键经过已有无障碍回调及应用窗口时，以原事件身份关联接收、消费／分发返回值及焦点状态。观察不扩大按键过滤、不记录文本键，也不保证固件会投递其他应用中的按键。新增能力不会自动出现在历史安装包中。

## 系统设置与按键记录

自动记录首页、应用管理以及已有无障碍回调实际收到的方向、确认、返回、主页和菜单按键，不记录数字、字母、页面文字或密码，不消费或改变按键事件。按键记录标明来源；系统设置内部的所有实体按键并不一定会投递给 Quiet TV，不能把未记录解释为用户没按键，也不新增无障碍授权或扩大按键过滤范围。

需要连续观察系统设置页面时，先在诊断页点击“记录刚才问题”，再在30秒内从 Quiet TV 打开网络或系统设置。普通打开设置只保留现有操作和按键记录，不启动连续系统查询。连续观察还要求已有本机 ADB 密钥、未暂停自动连接且使用 TCP，沿用应用管理保存的端口（未设置时5555）；不创建新密钥、不扫描其他端口、不自动开启调试或修改权限。条件不足、连接失败或单项查询不可用时写明原因，设置入口仍可使用。

通过只读 [dumpsys](https://developer.android.com/tools/dumpsys) 提取当前用户的 Activity、焦点窗口组件、匹配启动 action、Fragment 类名候选及系统暴露的状态，记录组件启用、导出及权限信息。观察仅在这次标记的30秒窗口内运行，每次快照后间隔两秒；窗口结束、进入诊断日志导出、息屏或连接失效时停止，不自动重连。不保存原始系统转储、网络列表、窗口标题、Intent URI 或 extra 值。

Fragment 候选及状态不保证实际可见；普通 View 内切页、短暂页面或后台暂停可能无法识别，未知不等于没有操作。进程停止后不自行续录，只有 begin 而无 result 时应标为未完整结束。每条原始查询限制512 KiB，受限查询不当作完整结果；观察到组件不代表第三方能直接打开对应子页，也不代替真机验收。

海信网络入口会先尝试固件声明的海信网络/无线网络页面；没有可调用的专用页面时，优先使用已确认的海信设置首页 `com.android.tv.settings/com.hisense.systemsettings.MainActivity`，再回退到原有通用入口。此调整依赖实际组件存在、系统应用身份、启用状态、导出及权限检查；不会猜测无线网络子页类名或启动参数，也不改变其他厂商已有的候选顺序。

## 开始排查

需要一台电脑、能执行终端命令的 Agent，以及电视实际允许的 ADB 连接。已安装 `quiet-tv-diagnose` skill 时，输入：

```text
请使用 $quiet-tv-diagnose 帮我排查 Quiet TV 问题。
问题现象：<描述你遇到的问题>
请每次只指导我完成当前必要的一步，等我反馈后继续，最后生成可发给开发者的问题报告和反馈包。
```

Skill 由独立本地技能包交付，不属于 APK，也不参与主应用构建。安装技能包时将其中的 `quiet-tv-diagnose` 目录放入 Agent 的 skills 目录。没有安装 skill 或 Agent 不支持 skill 时，可以使用下列独立提示词；没有执行工具时，AI应逐步指导用户手工操作，不能声称自己已操作。

## 无 skill 的复制提示词

```text
你是 Quiet TV 排查助手。请在我的电脑上进行只读排查，并逐步指导我操作电视。
问题现象：<描述你的问题>
```

## 海信开机与 HOME 异常

海信／VIDAA Android 电视出现开机先进入聚好看／原厂首页、实体 HOME 回原桌面或历史停用后黑屏时，读取[海信开机接管排查](AGENT_INSTALL.zh-CN.md#海信开机接管排查)，按其中证据项采集 HOME 候选及有效优先级、厂商启动路由、API24+ 用户解锁状态和实际 APK 的 Direct Boot 能力。Android 4.4／5／6 不套用 Android 7.0 的解锁机制；黑屏、一次设置失败或启动后单次快照都不足以确认根因。

只读诊断仅提出候选方案，不执行该安装规范中的设备修改或电源测试。轻量临时 HOME、停用原桌面及动画替换分别判断，不能把未取得 APK／源码的教程写成已经实现或真机通过；报告具体证据和缺失项，不提前结论为“无法改造”。

## 反馈与限制

开发中的新版诊断技能增加 `--home` 专项快照：按实际 Android 用户查询无障碍授权、系统服务绑定和 AppOps，补齐固件 fingerprint／incremental 等字段；命令不可用或采集截断时保留未知。支持核对 `home.quiet.tv`、`com.coocaa.quiettv` 与 `com.ts.launcher`，同名 HOME 代理通过组件区分，不能仅凭品牌选包。组件识别不代替签名核验。只有明确的 Build 字段保留四段数字版本，普通日志继续脱敏网络地址。

新版技能的本地案例登记工具按 SHA-256 保存附件副本、每次提交清单和追加索引；人工案例卡与反馈报告不会被重新采集覆盖。收到后续日志时，先核对设备、固件、实际安装包及触发场景，再明确关联已有案例；相同哈希不自动表示同一设备或根因。结论分为“已有方案可用／需要专项修复／证据不足／当前固件受限”，每案记录证据、下一步、源码与真机验证边界。技能需独立更新，现有 APK 或旧技能不会自动获得这些能力。

桌面问题还需区分以下证据：

- 系统默认 HOME、厂商私有 HOME 路由、实际前台组件和用户看到的首屏分别记录。新版 `--home` 在基础快照之后，只读查询 `HOME.JM`；确认 JmLauncher 包记录后才读取 `persist.sys.home.selectpkg`。属性为空或不可读均不自动修复，也不自动选择它作为守护目标。
- 应用导出的诊断补充自身开机接收组件状态、可见 TCL 管理组件版本，以及 Android 11+ 最近最多5条自身进程退出记录。自启动授权、组件启用和后台清理豁免分别判断；退出原因码、信号或空历史都不足以确认厂商清理。旧系统明确记录接口不可用。该历史接口见 [Android ActivityManager 文档](https://developer.android.com/reference/android/app/ActivityManager#getHistoricalProcessExitReasons(java.lang.String,int,int))。
- 后续每个场景单独记录默认 HOME 是否保持、首次可见页面、最终页面、原桌面闪回、切换耗时和待机时长；恢复原桌面单独验收。新版技能提供结构化场景模板，随每次证据提交追加保存。上游报告、自动化测试、设备日志与用户观察保留各自来源，不自动生成固件执行规则或“已解决”状态。

应用开发源码已补充可恢复的 Google HOME 顺序处理、JM/VIDAA 私有路由、TCL 自身后台策略和 Fire OS 6 替代观察入口，适用条件和用户操作见[直接接管与固件专项](AGENT_ADAPT.zh-CN.md)。新日志中的 `takeover` 是操作及读回记录，`usageObserverBound` 是替代观察服务状态，`tclPolicyStatus` 是策略读取/写回结果；三者都不能替代实体场景验收。`incomplete` 表示需核对恢复，`rolled-back` 表示本次失败后恢复了操作前状态，`restored` 表示明确恢复原桌面。

电脑诊断与案例登记仍然只读，不会因为识别到适用方案而自动执行。固件全局调度参数、透明覆盖窗口、root 修改系统启动文件不作为通用修复。上游实测、源码已实现、自动化通过、系统读回与 Quiet TV 对应固件实测分别注明；不能将“上游已解决”误写为“未知方案”，也不能直接扩展为所有机型支持。

用户检查后私下发送报告和相关证据。没有复现成功、缺少连接或没有明显报错，也要记录缺失项并交付现象报告。AI输出是排查结论，不代表已修复。

电脑采集不依赖诊断页面保持打开；只要电脑和 ADB 连接仍正常，Quiet TV 退出后仍可继续采集系统日志。Logcat不等于每次遥控器按键记录，不能读取其他应用的私有日志；固件权限和日志缓冲区会影响完整性。收集方式应依据设备帮助以及 Android 官方 [ADB](https://developer.android.com/tools/adb) 和 [Logcat](https://developer.android.com/tools/logcat) 文档。

MiBOX3直接HOME补偿开发日志增加 `home_guard.key_observed`，记录实际投递到无障碍的标准HOME按下/松开、keyCode/scanCode、单调时间、过滤请求与拒绝原因；`home_guard.home_trigger` 通过 observation 关联后续启动 attempt。广播、启动请求和首页生命周期回报均不等于实体键上屏成功。服务未连接或系统未投递时可能没有该事件，不能据此认定用户没按键；不记录任意文本输入。具体配置见[配置说明](SETUP.md#桌面守护实验)。

需要统一只读快照时使用[适配指南](AGENT_ADAPT.zh-CN.md)中的 `device_selftest.py` 默认模式；不要为排查自动开启主动场景。用户明确要求修复后沿用该指南的预览、执行和复测流程。
