# 首次设置焦点反馈与遥控导航修复方案

日期：2026-10-19。状态：已实施，b14 构建与专用模拟器验证通过，电视已覆盖安装并核对哈希；真机方向键检查记录见 SETUP_VERIFICATION.md，实体遥控体验仍由用户复核。

## 1. 目标和范围

修复默认桌面页“管理预装应用”、预装应用页“保留／禁用／卸载”及关联主按钮的焦点识别与方向导航。同步检查首次设置内部的连接、确认、恢复弹窗。

沿用现有两屏布局、按钮大小、文案、字体、壁纸和通用桌面示意图。修改限定在首次设置及其弹窗；不修改首页、关于页或通用应用管理的样式。所有设备检测、按需授权、HOME 核验及包操作继续使用真实实现。

## 2. 已确认的问题

- `SetupActivity.setupButton()` 的浅色主按钮在未聚焦时已有浅底和近白描边，聚焦后仅略微提亮；“管理预装应用”“完成设置”难以辨识当前焦点。
- 原桌面的当前处理选项也复用浅色主按钮样式，业务上的“已选中”与遥控器“当前聚焦”混在一起。
- 原桌面当前已禁用，代码因此禁用“禁用”按钮；卸载规则未开放，“卸载”同样不可用。两项被跳过时没有充分解释。
- 真机记录出现焦点落在不可操作的 ScrollView 上且没有高亮；从“保留”向右会跨区跳到“完成设置”。尚不能据此认定持续焦点死循环，但可确认路径和反馈不符合区域关系。
- 原检查以六项可操作应用为主要场景，未覆盖真实电视上五项已禁用、一项未安装、原桌面已禁用的组合。测试也未对聚焦前后视觉区别作验收。

证据：本地忽略目录 `evidence/focus-investigation-20261019-192323/`；其中 `arrow-trace.json` 记录“保留 → 右 → 完成设置”，`final-focus.xml` 记录 ScrollView 获得焦点，`keep-focused.png` 显示浅色按钮反馈。后续连续记录已切换到第一屏，不能用于证明第二屏持续卡死。

## 3. 视觉状态规范

状态按两个维度处理：业务状态决定是否已选／可执行，真实 View 焦点决定外框。方向键移动不改变处理选项、勾选、持久化选择或设备状态。

| 状态 | 显示 | 确定键行为 |
| --- | --- | --- |
| 普通可操作项 | 沿用当前按钮或卡片底色，无焦点外框 | 执行原交互 |
| 当前已选项 | 用底色或勾选表达已选，无焦点外框 | 保留原选择逻辑 |
| 当前聚焦项 | 独立、完整的白色外框，与原底色之间留出间隔 | 按该项真实能力处理 |
| 不可执行但可解释项 | 内容降亮；聚焦外框保持清晰，同时显示具体原因 | 只反馈原因，选择及设备状态不变 |
| 正在执行时暂不可用的控件 | 沿用忙碌态，不进入操作焦点路径；停止／取消入口可达 | 保留现有取消语义 |

外框沿用首页风格：与控件外缘间隔 2 个现有 960 宽设计单位，线宽 2 个设计单位；1920 宽画面分别约为 4 个物理像素。焦点以外框识别，不依赖轻微提亮或缩放。

所有首次设置按钮、三选一选项、推荐卡片、可聚焦清单项和弹窗控件使用一致的外框规则。同一活动窗口只显示一个外框；模态弹窗打开时隐藏背景窗口外框。预览图内的装饰描边不参与操作焦点。

实现采用首次设置专用的轻量焦点绘制组件，挂在页面或弹窗的顶层，不参与布局、触摸和焦点获取。外框由实际 `hasFocus()` 及控件在窗口中的可见位置驱动；滚动、布局变化和输入法显隐后更新位置。这样不改变按钮尺寸，也避免浅色底掩盖描边。需要检查弹窗、分段按钮、卡片边缘和滚动区域的裁切；只读内容的透明度不影响外框亮度。

## 4. 不可执行选项的解释

“保留／禁用／卸载”三项始终可用方向键聚焦。逻辑上的可执行能力与 View 是否可聚焦分离，不通过放开操作权限解决焦点问题。

- 聚焦“保留”：显示“保持原桌面当前状态”；原桌面已禁用时，保留不自动启用它。
- 聚焦“禁用”且原桌面已禁用：显示“原桌面已禁用，无需重复禁用”。按确定只反馈该原因。
- 聚焦“卸载”但规则未开放：显示“当前设备尚未开放原桌面卸载”。按确定只反馈该原因。
- 原桌面身份未知、Quiet TV 非实际 HOME、组件不可用等情况，按实际阻断条件提供原因。
- 推荐卡片可只读聚焦查看“已禁用／可恢复安装／未适配”等真实状态；不可操作项按确定不切换勾选。

聚焦只更新当前说明，不调用 `persist()`、`confirm()` 或包操作。确认可执行选项时再次核验其条件，再进入现有授权和预检链；不可执行项不得改变 `originalChoice`、已选数量或生成执行任务。按钮看起来可聚焦，不代表获得执行资格。

## 5. 明确方向导航

不让装饰、预览、空白占位或 ScrollView 本身成为操作焦点。滚动容器仍负责将子控件滚动到可见位置；清单项自身可以获得焦点。

| 区域 | 导航规则 |
| --- | --- |
| 默认桌面页主区域 | 初始聚焦“管理预装应用／设为默认桌面”；上下依次到可见辅助按钮和底部操作；左右不进入装饰预览区 |
| 默认桌面页底部 | 左右按“返回 → 暂不设置，临时使用 → 退出设置”移动；上返回主区域上次焦点；边界停留 |
| 原桌面三选一 | 左右固定为“保留 ↔ 禁用 ↔ 卸载”；两端停留，不斜跳到底部按钮；下进入推荐区对应列，推荐区无控件时直接到底部 |
| 推荐双列卡片 | 左右在同一行相邻移动，上下保持所在列；首行向上返回原桌面选项，末行向下进入底部操作；不足两列时选择存在的邻项 |
| 预装页底部 | 左右为“查看全部预装应用 ↔ 不处理，进入桌面 ↔ 完成设置”；上返回推荐区记忆位置，无卡片时返回原桌面选项；下到“返回” |
| 返回按钮 | 上回到该页底部／主区域上次焦点；系统返回键继续使用原页面返回语义 |
| 弹窗 | 焦点限制在当前弹窗内；关闭按钮、输入框、折叠设置和操作按钮均可达；关闭后回到打开弹窗的控件 |

原桌面三项和双列卡片保留各自最后聚焦位置，跨区时恢复；没有记录时使用当前已选原桌面项或所在列的首个控件。第二屏首次进入优先聚焦当前原桌面选项。全部推荐卡片只读或推荐列表为空，均不能把焦点落到容器上。

连接输入框保持“确定打开输入法、返回收起、随后上下移出”的交互；编辑时左右用于光标。恢复页、加载页与执行中至少有一个明确可达的操作入口。

页面重建后在布局完成时按稳定 tag 恢复真实焦点。原目标消失或暂不可用时，按上述区域规则选择回退项；不得只设置 selected 标志模拟焦点。刷新、选择切换、连接模式切换和弹窗返回后均检查该行为。

## 6. 实施文件与顺序

1. 在 `SetupActivity.java` 及一个首次设置专用焦点绘制组件中实现状态分离、完整外框及窗口切换处理；不直接改写 `ManagementUi` 的全局样式。
2. 为原桌面选项及只读推荐卡片加入能力原因反馈，保留所有真实操作预检和权限条件。
3. 在 `SetupActivity.java` 中设置区域间确定的导航关系，并排除容器焦点；动态列表重建后重新绑定路径。
4. 对 `AdbConnectionPanel.java` 只做所需的焦点外框、路径与恢复接入，保留取消、连接成功继续和输入法语义。
5. 扩展 `SetupPrototypeChecks.java` 及必要的场景入口，覆盖不可执行状态、视觉反馈与从真实初始落点出发的连续方向导航。
6. 根据最终源码构建新候选，构建号取当时归档最大值之后的新值；验证通过后明确路径创建本地中文提交，再按安装授权更新电视并核对哈希。

## 7. 验证与验收

### 必测状态

- 默认 HOME 未设置与已设置两种第一屏。
- 六项可操作、部分可操作、六项全部不可操作、没有推荐卡片。
- 原桌面已启用、已禁用、身份未知，以及卸载能力未开放。
- 尚未授权、连接弹窗折叠／展开、输入法开启／收起、连接取消与失败返回。
- 选择后重绘、刷新后恢复焦点、弹窗关闭回到来源。

专用模拟器使用受控测试元数据和专用测试包构造状态；不为测试恢复或启用日用电视上此前已禁用的应用，不放宽生产设备规则。

### 通过标准

- 每次方向键移动，都能明确看到当前操作位置；当前活动窗口没有丢失或重复外框。
- “管理预装应用”“完成设置”“保留”各保存未聚焦和聚焦截图，外框完整可见，尺寸、文字、布局不变。
- 三选一可连续左右到达三项，且不会斜跳到“完成设置”；不可执行项聚焦和按确定都不改变选择或设备状态。
- 从页面真实初始焦点出发，用连续按键到达每个预期目标，保存方向键和实际焦点轨迹；不能仅靠程序直接 `requestFocus()` 作为可达性通过依据。
- 全只读／空列表场景，焦点不落在 ScrollView 或空白容器；跨区可往返。
- 视觉验收与焦点属性验收分别执行；`focused=true` 不能替代截图检查。触摸点击也不能代替遥控确认验收。
- 专用模拟器回归授权取消、执行前核验与恢复流程；既有安全边界继续通过。
- 真机先保存状态，仅用方向键、返回键及只读原因反馈复测；不触发禁用、卸载、恢复或 HOME 切换。对比前后包状态和原生选择记录，保存截图及轨迹。实际实体遥控器体验由用户复核，ADB 按键结果单独记录。
- 构建、模拟器、电视安装／哈希、真机界面及实体遥控验收分别报告。其他品牌和固件不能据此自动标记为通过。
