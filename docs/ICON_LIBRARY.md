# 图标库素材接入

图标库位于电视设置的「管理应用」之后。原生页面支持预览、替换、恢复、备份兼容和手动刷新。已验签在线清单提供当前可用素材与风格，图片按需下载。普通构建不依赖本机图库、AI 服务或联网下载。

## 添加正式素材

清单位于 `app/src/main/assets/icon-library/catalog.json`。`version` 是清单格式版本，当前为 1；`revision` 是素材版本，替换同一主题素材时递增。每个主题和风格的组合只能出现一次，例如：

```json
{
  "version": 1,
  "revision": 1,
  "items": [
    {
      "id": "cinema",
      "name": "影视",
      "nameEn": "Cinema",
      "style": "apple",
      "foreground": "icon-library/apple/cinema.png",
      "background": "icon-library/apple/background.png",
      "source": "对应素材来源与许可说明"
    }
  ]
}
```

正式接入时提交清单实际引用的 PNG 及相应来源、许可证；示例文件名不代表素材已经制作。素材路径仅接受 `icon-library/` 内的小写英文数字和连字符路径，不接受目录回退、绝对路径或网络地址。前景固定 512×512 px，可选背景固定 720×720 px，单张源图不超过 512 KiB；其余要求见下文。设计原稿可以更大，导入 APK 前须按规范导出，不把原稿作为运行时素材。

风格标识为 `apple`、`google`、`flat`、`skeuo`、`soft`、`3d`、`pixel`。这些历史标识继续兼容；当前可选风格及名称由在线清单的 `styles` 数组决定。页面按下表组合前景与背景，不从效果图裁切或拉伸图标。横向图文形式的中英文标题由系统字体实际排版。

| 形状 | 标识 | 比例 | 可选形式 |
| --- | --- | --- | --- |
| 圆角矩形 | `rectangle` | 16:9 | 文字＋图标（`text`）、纯图标（`icon`）、透明背景（`transparent`） |
| 圆角正方形 | `square` | 1:1 | 纯图标（`icon`）、透明背景（`transparent`） |
| 圆形 | `circle` | 1:1 | 纯图标（`icon`）、透明背景（`transparent`） |

方形与圆形不提供文字＋图标选项。横向图文切换到方形或圆形时，候选自动改为纯图标；纯图标与透明背景在切换形状时保留。恢复旧页面状态时也按此规则调整候选，不主动替换已保存封面。

一键替换图标在电视和手机端均按桌面显示设置的当前形状匹配、预览及保存，不使用图库筛选栏的形状，也不修改桌面形状设置。桌面为圆角方形或圆形时，文字＋图标自动改为纯图标；纯图标与透明背景保持原选择。匹配后若桌面形状已改变，须重新匹配后再替换。优先使用对应形状的素材；仅有同形式长方形成品时，方形与圆形等比保留完整图案，延展背景并裁切外轮廓，不拉伸标识或截断横向文字，不由带背景素材生成透明背景。

## 图标设计规范

形状规定外轮廓，风格规定绘制语言，形式规定图文与背景的呈现方式。三者分别定义，同一主题在不同组合下保留相同的核心识别元素。

| 风格名称 | 标识 | 制作要求 |
| --- | --- | --- |
| 苹果风格 | `apple` | 简洁主体、细腻渐变和克制高光；同套素材统一层次与光照。 |
| 谷歌风 | `google` | 清晰的几何构成与色块层次；同套素材统一配色、圆角和叠放规则。 |
| 扁平化 | `flat` | 以纯色色块表达主体，避免材质纹理与明显立体光影。 |
| 拟物化 | `skeuo` | 用材质、光影和细节表达真实物体；统一透视与光源。 |
| 轻拟物 | `soft` | 简化物体细节，以浅层厚度和柔和阴影表达层次。 |
| 3D 风格 | `3d` | 以明显体积、统一视角和立体造型表达主体；同套素材统一光源、厚度与投影，区别于轻拟物的浅层效果。 |
| 像素风格 | `pixel` | 同套素材采用统一像素网格和有限色板，保留清晰阶梯边缘；图层合成缩放采用最近邻采样，避免插值模糊。 |

- 横向为 16:9，方形与圆形为 1:1；前景保持等比与视觉居中，圆形关键内容不得进入裁切区。
- 同套素材统一主体占比、安全留白、轮廓粗细、配色与细节密度，缩小到实际桌面尺寸后仍能辨认。
- 文字＋图标仅用于横向长方形，使用左图右文；圆角方形与圆形只制作纯图标、透明背景版本，不在素材中排入标题。
- 前景与背景分别提供，透明形式保留 Alpha；在深色、浅色和复杂壁纸上检查主体边缘与文字辨识度。
- 新风格须有真实素材及来源记录后才能作为可用图库交付；仅增加分类不代表素材已完成，未提供素材的风格不显示在可选列表中。

## 尺寸、格式与视觉占比

以下均为图片实际像素尺寸，不按 DPI 元数据或文件名判断。面向当前桌面卡片与 1080p 电视布局制定；提高电视输出分辨率不等于需要为每个图标加载整张 4K 图片。

| 用途 | 固定尺寸 | 格式 | 文件体积 |
| --- | --- | --- | --- |
| 图标前景 | 512×512 px | 8 bit/通道 RGBA PNG，保留透明区域 | 建议 ≤256 KiB，硬上限 512 KiB |
| 可选背景 | 720×720 px | 8 bit/通道 RGB 或 RGBA PNG | 建议 ≤256 KiB，硬上限 512 KiB |
| 横向合成成品 | 720×405 px | RGBA PNG | 建议 ≤256 KiB，硬上限 1 MiB |
| 方形、圆形成品 | 512×512 px | RGBA PNG，圆形外围透明 | 建议 ≤256 KiB，硬上限 1 MiB |
| 图库缩略图 | 按实际控件宽度生成，宽度不超过对应成品 | 内存位图，保持对应形状比例 | 复用 4 MiB LRU 缓存，不落盘生成整套缩略图 |

- 源图导出为 sRGB、无交错静态 PNG；不接入 JPEG、WebP、SVG、GIF、APNG、16 bit/通道或索引色 PNG。DPI 元数据不用于改变解码尺寸，不嵌入字体或文字截图。
- 旧本地分层合成输入的核心主体最长边为 448–480 px，约占 512 px 前景画布的 88%–94%，每侧参考留白 16–32 px；投影、发光不计入核心主体尺寸。该范围只约束旧合成输入，不套用到在线完整成品。
- 旧本地分层合成保留约 14% 的短边留白，得到约 63%–68% 的主体比例。在线完整成品不再进行这次缩放；其主体比例、中心和安全区按已确认的同类视觉基准标定。Clash 校准后矩形主体为 326×298 px，方形和圆形为 370×338 px。不同造型须人工比较视觉重量，不能只比较文件宽高或统一套用一个占比。
- 在 512 px 前景上，重要轮廓和间隙一般不小于 12 px；避免依赖细碎纹理传达含义。使用原始矢量或高分辨率设计导出，禁止把低分辨率小图插值放大成 512 px 交付。
- 像素风格统一以 64×64 逻辑网格绘制，按整数 8 倍导出为 512×512 px，关闭平滑插值；其他风格正常抗锯齿，不用模糊掩盖边缘问题。
- 背景只承载底色、渐变和非关键纹理，按目标形状等比填满并居中裁切，不能拉伸。标识、文字及需要完整保留的细节放在前景。

## 加载与性能要求

- 清单只加载元数据，图片按可见图库项及当前候选加载；解码、合成和 PNG 写入在现有单个后台工作线程执行，主线程只更新视图。
- 解码先读取图片宽高和类型，运行时单边上限 720 px；按前景实际绘制区域、背景目标尺寸采样，禁用密度自动缩放，使用 ARGB_8888 保留 Alpha 和渐变。
- 缩略图根据网格实际可用宽度生成，最小生成宽度为 160 px，最大为对应成品宽度；尺寸加入缓存键，避免复用较小缩略图后再放大。标准布局优先匹配显示像素，不统一预解码整套成品。
- 缩略图缓存上限保持 4 MiB；切换分类或页面时跳过过期任务，离开页面释放引用。该数值只限制缓存，不等于整个页面的位图内存上限。
- ARGB_8888 像素内存按宽×高×4 字节计算，与 PNG 文件压缩体积分别约束。512×512 约 1 MiB，720×720 约 1.98 MiB，720×405 约 1.11 MiB；单次最大合成的前景、背景、结果、遮罩像素合计约 5.3 MiB，不包含缓存、解码器及其他视图，实际峰值在设备验收时记录。
- 新生成成品限制为 1 MiB。历史上传封面的 2 MiB 限制及旧尺寸、备份读取路径保持兼容，不因新增规范修改原件。

实现依据：[Android 按目标尺寸解码位图](https://developer.android.com/topic/performance/graphics/load-bitmap)、[BitmapFactory 解码选项](https://developer.android.com/reference/android/graphics/BitmapFactory.Options)。

## 素材接入与验收

`python3 scripts/validate_icon_library.py` 检查生产清单实际引用的文件：路径、文件体积、精确尺寸、PNG 位深与颜色通道、无交错、静态格式、块校验及像素数据完整性。标准版和兼容版构建的 `preBuild` 均自动执行；不符合要求时停止构建。校验脚本纳入生产源码摘要，构建归档会检查其变化。空清单合法，但不代表图标素材已经验收。脚本只使用 Python 标准库，新克隆不需安装图像处理依赖。

自动检查之外，正式接入每组素材还须记录：sRGB 导出设置、核心主体占比、视觉居中、原稿分辨率、最小显示尺寸下的辨识度、圆形裁切和深浅壁纸效果。每种风格都按已支持的形状、形式检查，不为方形或圆形增加图文版本。

### 在线苹果成品的制作门禁

新增和修订苹果风格纯图标按[图库制作与发布规范](https://github.com/BeatsAD/quiet-tv-icons/blob/main/tools/design/README.md)执行。使用[统一导出器](https://beatsad.github.io/quiet-tv-icons/tools/export.html)和六款确认稿（Clash、红果 TV、影视仓、蜂蜜影视、超级直播、NewBox），原稿只绘制透明主体和材质，外底板、背景和轮廓由固定模板导出。

- 前景母稿宽高至少 1024 px；核心有效框采用 Alpha ≥192 测量，Alpha ≥8 用于投影和轮廓裁切检查。人工核对玻璃或半透明物体的测量是否代表真实主体，不能把 Alpha 结果当作审美结论。
- 一批同时导出三种形状，矩形正式图 720×405、缩略图 320×180，方形和圆形分别为 512×512、256×256。模板直接写入 Alpha，不在模型生成的圆角底板外再加一层留白。
- 相对确认基准的主体最长边偏差超过 5%，或中心偏移超过对应画布边长的 2%，发布登记时须记录复核原因；主体、投影裁切和轮廓错误不能通过说明豁免。
- 每批保存深浅背景、三形状和小尺寸的并排对照稿，检查底板内缩、第二层底板、主体视觉大小、配色、材质和边缘。矩形以 314×177、方形和圆形以 176×176 作为参考显示尺寸，再查看 160×90、96×96 小尺寸；实际电视布局仍须实测。
- 图库 `tools/design_quality.py finalize` 完成无损压缩、哈希核对和对照稿生成；视觉确认后通过 `stage` 登记生产资源和复核说明。`tools/validate.py verify`、签名前检查、GitHub Validate 和 Pages 部署共用同一门禁。新增图片缺少导出与复核记录、尺寸或格式错误、轮廓不符、主体裁切时停止发布。
- 历史 850 张 PNG 仅按固定哈希复用，豁免表不得扩充。新图使用新的不可变资源路径并递增目录 revision；固定模板和制作记录不加入客户端签名目录，不增加电视下载、识图或实时裁切开销。

在目标电视上记录首次打开、连续滚动、来回切换风格的加载与内存表现；确认无明显跳帧、长时间空白和持续内存增长。低内存旧电视与标准版分别验收，模拟器或空清单不能代替真实素材的性能结论。

## 保存与显示

电视图库采用全宽六列布局，顶部选择目标应用、风格、形状和表现形式，并提供「恢复默认」。不再常驻首页／第二屏实时效果预览，也不提供单独的替换按钮。

方向键浏览只选择图标并加载缩略图；确定键或点击图库项打开 2.0 原生确认弹窗，读取当前图标与所选正式图进行对比。初始聚焦「取消」，确认替换后才保存，取消或返回不改变原图标。正式图在打开弹窗时准备，提交使用弹窗展示的同一份 PNG，并再次校验目标资格与当前封面版本；其他入口修改后须重新打开确认，不覆盖新的图标。

保存成功关闭弹窗并回到原图库项，显示 3 秒成功浮层。恢复默认同样先确认，成功显示对应浮层；恢复按钮禁用后焦点回到图库。加载或保存失败在弹窗内说明，不显示成功状态，相同图标不重复写入。

新横向素材为 720×405 PNG，方形和圆形为 512×512 PNG，圆形外围及透明形式保留 Alpha。它们在现有桌面占位内等比居中，不改变全局图标形状、Dock 顺序或应用显示状态。旧上传封面仍使用原有 720×406 路径。

新备份使用格式 v3，同时读取旧 v1/v2。v2 支持图库元信息，v3 进一步支持手机上传图标；两者均包含实际 PNG，恢复不依赖图库临时缓存或扫码会话。旧程序不支持 v3 时会明确拒绝，不能把新记录改标为旧格式。历史方形、圆形图文封面及其备份仍按原 PNG 读取，新候选不再生成此类组合。计划、测试素材和过程截图保留本地，不加入生产图库。

## 扫码上传图标

图库前两项固定为「一键替换」和「扫码上传」，不受应用、风格、形状和表现形式筛选影响，空素材清单仍可使用。入口只打开当前目标应用的二维码，聚焦不会将二维码作为图标候选；切换筛选后列表回到首行。

手机扫码后选择图片、调整形状和裁切，在手机点击「确认替换」即上传并保存。电视保存成功才返回成功结果，自动关闭扫码弹层、更新图库状态并显示成功浮层，无需遥控器二次确认。图库单张素材使用独立的电视确认弹窗。

支持 JPG、PNG、静态 WebP，选择文件与输出文件不超过 2 MB；保留透明度和图案比例。长方形输出 720×405，方形和圆形输出 512×512，圆外透明。上传图标以 `source=upload`、`fit=contain` 记录，不伪造图库主题或风格；既有 720×406 封面流程保持原样。

扫码会话绑定目标与打开时的封面版本；关闭、离开或网络变化会取消未完成请求，其他入口修改图标后旧会话不能静默覆盖。成功会话保留结果查询，重复请求不重复保存；手机传输中断时先检查保存结果。


## 在线图库与镜像下载

在线库目前提供苹果风格 69 款、拟物化 68 款纯图标，每款有圆角矩形、圆角正方形和圆形。矩形正式图 720×405、缩略图 320×180，正方形和圆形分别为 512×512、256×256，均为 RGBA 8-bit PNG。客户端直接等比显示，不重复添加背景、裁切或二次压缩；未制作的透明背景和图文组合不会使用其他形式代替。

独立资源仓库为 `BeatsAD/quiet-tv-icons`，浏览入口为 <https://beatsad.github.io/quiet-tv-icons/>。APK 只包含签名目录和公开验签密钥，不内置图库图片。进入图库先显示随包目录，后台刷新；列表按可见项读取缩略图。电视浏览仅请求缩略图，打开单张替换确认弹窗后才请求正式图，关闭弹窗或离开取消过期请求；缩略图最多两个后台任务，正式图准备独立串行，避免网络阻塞页面。手机端保留单张资源排队以预留控制请求连接，所选正式图优先于尚未开始的缩略图。

下载固定沿用在线更新的镜像顺序：`ghfast.top` → `gh-proxy.com` → `v4.gh-proxy.org` → GitHub Pages → GitHub Raw。镜像失效、超时、返回网页或校验失败时继续下一来源；不存在可用缓存且所有来源失败时提示重试，保留当前已应用图标。普通下载每来源连接超时 2.5 秒，读取超时 3 秒，读取总时限 12 秒，最多 4 次跳转；离开页面会断开尚未完成的图片连接。

`latest.signed.json` 使用独立 RSA SHA-256 签名，验签后才接受目录；低于当前 revision 的更新被拒绝，同 revision 不能替换目录内容。图片校验精确大小、SHA-256、PNG 头和尺寸；正式图硬上限 1 MiB，缩略图硬上限 256 KiB。版本化图片路径不覆盖，更新时增加资源版本与目录 revision。

下载磁盘缓存上限 32 MiB，按最近使用淘汰；列表位图缓存上限 4 MiB。已应用正式图按原 PNG 字节复制到封面持久目录，独立于下载缓存，备份继续包含 PNG 本身。因此断网、资源下架或缓存淘汰不会删除已应用图标。缓存被系统清理后，未应用素材需要重新下载。

资源生成命令：`python3 scripts/build_icon_library.py build --export <正式图导出目录> --matches <匹配规则JSON> --key <仓库外私钥> --revision <递增整数> --output <静态资源目录> --bootstrap app/src/main/assets/icon-library`。生产构建检查随包目录签名及描述符，静态资源仓库的 Validate 检查目录签名与全部图片摘要后部署 Pages。私钥不得提交或写入网页。

以上是实现和验证契约，真机网络速度、遥控滚动流畅度、低内存回收后的行为仍需电视验收。

## 一键匹配与批量替换

电视图库首位固定「一键替换」，第二位固定「扫码上传」，不随筛选隐藏。任意顶部筛选器按下直接到达首位。批量替换沿用当前风格、形状和形式，读取同一图库目录；不提供所选组合的项目保持原样。

`app/src/main/assets/icon-library/matches.json` 以稳定主题 ID 登记完整别名、已核实包名和 `autoMatch` 身份状态。匹配优先使用包名，其次为 NFKC、忽略空白及大小写后的完整名称；不做子串或模糊自动匹配，不删除 TV、Pro 等名称后缀。包名映射只有核对后才登记；名称歧义、身份待核对的图标进入「待确认」，不默认勾选。身份规则可先于在线素材登记，尚无对应素材时显示缺图并保留原图。

结果分为「可替换」「待确认」「已保留」。已有自定义图标默认保留，开启覆盖后才可选择；相同图库版本及组合不重复保存。电视和手机共用匹配计划，手机最终确认后直接保存并通知电视刷新，无需电视再次确认。

「未匹配」应用可在电视或手机的批量预览中手动从当前风格、桌面形状及表现形式的图库选图，选中后加入同一批次保存，不改写应用身份匹配规则，也不默认分配图标。已有自定义图标的未匹配项同样需要先开启覆盖；待确认项若受此限制，会明确提示所需开关。关闭覆盖会取消已有自定义图标的选择。当前组合无可用素材和已是当前图标的项目继续保留。

执行时在后台逐张准备，最后再次校验应用状态、图库版本及每个应用的封面键。索引通过一次原子写入发布，封面版本只递增一次；准备阶段取消、缺图或某个应用并发变化均不发布半批结果。手机重复批次凭据返回现有任务，在任务记录保留期间不重复执行。提交阶段不可取消。保存异常会提示重新读取核对。

沿用原有桌面备份，自动备份开启时在批量替换前记录 `before` 状态；关闭时不主动开启。批次保存不删除旧图文件，备份引用保留机制仍然有效，不增加独立撤销管理页。图标元信息继续使用现有 v3 备份格式。

## 在线匹配规则与目录同步

签名目录的 `matches` 保存完整匹配规则（version、revision、items），每项包含 id、aliases、packages、autoMatch。规则必须覆盖目录所有主题，图片和规则一同验签、一同更新。新增主题无需升级客户端即可被识别；未核实身份继续标为待确认。目录未提供规则的旧版本沿用包内 matches.json，兼容旧目录。

目录 revision 随任意发布变化递增，规则内容变化时另递增 matches.revision。仅更新规则可运行 `python3 scripts/build_icon_library.py sign --catalog <现有目录JSON> --matches <匹配规则JSON> --key <仓库外原私钥> --revision <新目录版本> --output <静态资源目录> --bootstrap app/src/main/assets/icon-library`，复用既有图片路径，不重传或改写历史图片。

已验证目录版本及规则版本纳入手机 icons 同步域；现有轮询检测到变化后重新读取元数据，手机无需重新扫码或刷新页面。此状态读取复用内存目录，不在每次轮询发起下载。

批量保存除开始时验证外，完成全部下载后、正式写入前再次验证目录及规则。最终核对与封面索引提交期间按封面库、目录库的顺序持锁，避免目录在检查与提交之间被切换。目录或规则变化时整批取消并要求重新匹配，已准备文件不会形成半批保存。

## 在线风格与刷新

签名清单 version 2 可携带 `styles`，每项包含 `id`、中文 `name`、英文 `nameEn`，数组顺序即下拉顺序；只有已包含素材的风格显示。当前为 `apple`（苹果风格）和 `skeuo`（拟物化）。新增风格采用小写字母、数字和连字符组成的稳定 ID，登记名称并添加素材后递增 revision、签名发布，无需逐端修改风格白名单。旧目录缺少风格定义时，从素材条目推导可用风格并沿用兼容名称。

电视与手机扫码页读取同一组风格 ID 和显示名称。形状内部标识不变：`rectangle` 显示“圆角矩形”，`square` 显示“圆角正方形”，`circle` 显示“圆形”。历史已应用图标和备份保留，不要求其风格仍出现在可选列表中。

电视图标库在“恢复默认”右侧提供“刷新”。手动刷新绕过自动刷新的 15 分钟间隔，重新校验网络缓存，在后台完成签名和版本检查；提示更新、无更新或失败结果。请求串行执行，图片缓存按内容哈希复用，已应用图标独立保存。签名目录大小上限为 2 MiB，条目上限仍为 1024；旧 APK 的大小和风格限制保持其原版本行为。
