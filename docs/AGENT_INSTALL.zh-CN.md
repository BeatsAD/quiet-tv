# 使用 Agent 安装或恢复 Quiet TV

[首页](../README.md)  [安装与构建](INSTALL.zh-CN.md)  [兼容范围](COMPATIBILITY.md)

需要能在电脑上执行终端命令的 Agent。新版通过电脑 ADB 维护；历史版本的内置 ADB 属于独立授权，不要求重复连接。没有执行工具时，Agent 应逐步指导并检查结果，不能声称已操作。

## 复制安装请求

复制下面的请求交给能执行本机命令的 AI 工具。完整操作规则见下文；Agent 须先读完整说明，无法读取时告知用户，取得说明内容后再执行设备修改。

```text
请通过我的电脑安装或更新 Quiet TV 最新适配版，自动接管桌面并保持 ADB 常开。
先完整阅读并执行官方说明：
https://raw.githubusercontent.com/BeatsAD/quiet-tv/main/docs/AGENT_INSTALL.zh-CN.md
需要我操作电视时提醒我，最后给出实际验收结果。
```

页面只提供固定请求与复制按钮，不要求用户填写 IP、端口、版本、架构或选择接管方案。Agent 按下文发现并确认目标；确实缺少地址时再用普通语言引导用户查看，不将 USB 标识、配对端口或技术参数交给用户猜。

这条请求明确授权安装最新适配版（含测试版）、自动配置桌面接管及适用设备的 ADB 保持。统一入口默认采用 `takeover` 并启用 `keep-adb` 意图，首次预览后在同一授权范围内加 `--apply` 执行，不再询问是否接管或是否保持 ADB。已有可用配置沿用；用户另行明确“仅试用”或“只更新”时，分别指定 `--goal trial`／`--goal update`，保留原有守护、暂停及 ADB 选择。高级调用 `--no-keep-adb` 只表示本次不新增开启，保留已有选择。

自动接管的目标包括实际 HOME 及开机行为；配置返回成功仍须按下文验收。电视端调试授权、实体按键反馈和电源测试按实际需要提醒用户，重启／断电需单独授权。固件受限、旧 APK 缺接口或缺少 relay 发布包时，分别报告已完成和未完成部分，不把安装成功写成全部目标达成。


## 版本选择：包含预发布，避免误装历史包

默认安装适配目标电视的最新已发布主程序，包含预发布／测试版。固定入口为[安装页](https://beatsad.github.io/quiet-tv/)、[完整 Agent 说明](https://beatsad.github.io/quiet-tv/agent.md)和[最新版索引](https://beatsad.github.io/quiet-tv/latest.json)；发布流程自动更新，不需要用户填写版本号或逐版修改提示词。

安装页复制固定的简短请求，不依赖版本索引是否可达，不嵌入版本号、发布页或时间戳；手动下载链接独立读取索引。Agent 真正执行安装时必须重新读取实时版本信息，读取失败停止依赖该结果的安装，不使用旧缓存。索引的 `latestVersion` 为最新已发布主程序软件版本，`releases` 按软件版本从新到旧列出适配候选，包含 `prerelease=true`。先按兼容与升级条件过滤，再选最新适配包；不能把全局最新版本或最大构建号套到所有电视。

Agent 直接使用固定请求时，须通过本机终端读取 `latest.json`，自动添加 `?check=<本次实际时间>` 并使用 `Cache-Control: no-cache`。从 `releases[].assets[]` 读取实际 `url`、`bytes` 与 `sha256`；不要自行拼接附件名。软件版本、构建号、最低 API、ABI、包名与签名仍以下载后的实际 APK 为准。索引是公开下载发现入口，不代替 APK 校验，也不改变电视端签名更新清单。

网页读取工具的摘要不作为“最新版”依据。若索引与用户指定的版本或发布链接矛盾，直接查询 `https://api.github.com/repos/BeatsAD/quiet-tv/releases/tags/v<版本号>`，同样自动添加本次时间参数。返回 403、429、超时或无终端权限时报告无法确认；仅凭列表缺项、缓存内容或 `/latest` 的 404 不能断言版本未发布。无法核对时停止依赖该结果的安装，不改装历史包。

- 以最新版索引的实际附件为选包入口；需要核对 GitHub 原始发布详情时，读取[完整发布列表](https://github.com/BeatsAD/quiet-tv/releases)及实际附件，API 使用 `https://api.github.com/repos/BeatsAD/quiet-tv/releases`，有下一页则继续读取。排除草稿，保留预发布；不能仅依赖不包含预发布的 `/releases/latest` 或 `/releases/latest/download/...`，404 不代表没有适配版本。
- 按系统、架构和已有安装选择最新适配发布，不跨档比较最大构建号，不将搜索摘要、本机缓存或历史版本当作最新。用户明确指定历史版本时说明差异；文档中的旧链接以实时 Release 为准。读取或下载失败时停止安装并报告，不自动退回历史包，不以源码构建或未发布本地候选替代公开附件。

后续安装包命名按[版本规则](VERSIONING.md)，包含实际软件版本和构建号；历史附件保持原名。安装时仍从实际 APK 核对版本及构建号，始终使用实时附件中的实际下载地址，不按命名规律拼接链接。

## 分包选择与覆盖升级

已有安装先按下方“已有安装”核对升级条件；首次安装按设备系统与架构选择。仅使用最新适配发布的实际附件：

- 以系统支持的 ABI 为准，64位处理器可能运行32位系统，不按处理器名称或电视品牌推断；无法确认时标明未确认。
- 有对应的适配附件时，系统支持 ARM64 则优先选 ARM64，否则按支持情况选 ARM32；架构不明确或没有合适专用包时选满足条件的通用包，只发布通用包时直接使用。ABI 未读到时仍标记未确认，脚本仅接受无原生库的包或实际包含 ARM32、ARM64、x86、x86_64 的完整通用备用包，不猜测单架构；安装器拒绝时保留错误并停止。三者为替代选项，每台设备只安装一个完整 APK，不为使用较小的包而退回旧版本或低构建号。
- 普通主程序包名为 `home.quiet.tv`。安卓4.4兼容档目前无原生库，使用一个兼容包；酷开专用包及助手另核对实际适配条件，不按品牌自动替代普通主程序。

## 统一安装入口

本地源码使用 [install_quiet_tv.py](../scripts/install_quiet_tv.py)，独立 Agent 从本次实时 `latest.json` 的 `tools` 字段取得 `install_quiet_tv.py`、`verify_install.py`、`install_tcl.py`、`tcl_cast.py`、`configure_home_guard.py`、`device_maintenance.py`，下载至同一私有目录并逐文件核对 SHA-256。工具缺项或校验不符时停止，不从不明来源补脚本。站点部署前，公开索引可能尚未含新入口，应明确说明差异；不能据本地代码宣称已经上线。

Agent 先按下文确认电视、完成电脑 ADB 连接／授权并核对前台用户；安装入口不扫描、不自动选择设备、不默认端口或用户。准备现有官方 Platform-Tools、Python 3.9+、Android build-tools 的 `aapt2`／`apksigner` 及其 Java 运行环境，工具缺失时明确说明并按主机环境准备，不要求用户猜路径，不构建源码替代公开包。可用 `--adb`、`--aapt2`、`--apksigner` 指定现有工具。

变量由 Agent 从已确认目标填写。`NEW_RECORD_DIR` 是仓库外全新的电脑私有目录，父目录应存在；预览与执行使用不同目录。本页简短请求默认使用 `takeover`（配置系统 HOME，必要时配置兼容守护）及 ADB 保持；仅用户明确只试用／只更新时才使用 `--goal trial`／`--goal update`，不改已有桌面、守护或 ADB 选择。不将用户已明确选择的接管再拆成重复授权；目标仍有歧义时先澄清。

```sh
python3 scripts/install_quiet_tv.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --record "$NEW_RECORD_DIR"
```

预览通过后，沿用已授权目标，以新记录目录加 `--apply` 执行。本页请求已明确要求保持 ADB，默认传递该意图；显式 `--keep-adb` 效果相同，无需再让用户勾选。试用／仅更新默认不新增开启。当前只支持小米／Redmi 安卓5及以上的调试设置恢复，其他品牌或安卓4.4明确报告不支持，并继续独立的安装／HOME 步骤。不支持时不能改系统属性或强开端口。设置恢复不等于端口持续可用，更不等于完成配对或授权；重启／唤醒后的电脑 ADB 重连另行验收。

电脑配置会从已选定、已授权的传统网络 ADB 标识中提取真实 IP 与端口，只对安卓5～10的适用小米／Redmi包保存恢复端口；不默认5555，不将 USB 标识或 Android11+无线调试端口套作传统 TCP。应用先报告 `adbPortSupported`／原 `adbPort`，脚本把端口与 `keep_adb` 一起交给受权限保护的接收器，应用先持久保存端口再启用恢复，并读回核对。该端口复用已有 `adb` 偏好中的 `port`，不改其他连接设置、不导入密钥、不执行 tcpip 或配对。

旧 APK 缺少端口保存接口时，仅配置它已有的调试设置恢复，明确报告“端口恢复未配置，需包含修复的新包”，不声称本次已修复网络端口。新应用源码不会通过网页或脚本更新自动进入旧 APK；需要后续按发布流程交付新包。端口识别不了或系统不适用时也不猜测；新包保存及读回成功仍不等于完成重启／唤醒后的网络重连验收。私有授权记录保留应用能力、原端口、拟写端口及实际结果，不覆盖旧记录。

入口面向普通包名 `home.quiet.tv` 的标准／安卓4.4档及 relay 形态，按实时索引选择最新适配、同包名且符合覆盖条件的发布 APK，支持预发布；发现已有改包名或酷开专用 Quiet TV 时，转回既有同包名专用安装路径，不自动另装普通包。安装前保存 HOME、原包状态与可读取的已安装 APK，验证包名、系统、ABI、签名、构建号及 SHA-256，安装后拉回实际 APK 再核对。签名冲突、降级、同构建号不同文件、split APK 或普通／relay 形态迁移均停止覆盖。Agent 已核验发布来源的包可用 `--apk "$APK_PATH" --sha256 "$EXPECTED_SHA256"` 明确指定，不通过该参数绕过实际包验证。

接管优先沿用已配置的系统 HOME，或依据固件帮助和实际 HOME 候选设置；不适用时复用电脑守护配置。原桌面／恢复基线不明时停止依赖它的接管。工具不禁用原桌面、不精简应用、不接管屏保、不重启。TCL 复用现有安装助手与同版本 relay 候选，不授权临时停用安装器；公开发布缺 relay 时明确报告，不临时构建、改签或用旧包冒充。

### 原始验收输出

执行入口在安装尝试结束后（包括失败）继续采集不依赖失败步骤的只读证据，分别输出命令、标准输出、标准错误和退出状态。原始内容保存在私有 `record.jsonl`，当前对话须原样展示系统 HOME、无障碍配置和焦点输出，不只说“成功”；公开反馈另行脱敏。查询失败或超时记为未知。

安装后提醒用户用实体遥控器按一次主页键并反馈画面；确认已按后，再用新的记录目录执行以下只读采集。不得先启动 Quiet TV、注入 HOME 或把屏幕焦点人为切过去。`--physical-home` 只声明用户刚按过键，不会代按，也不代替用户对可见画面的确认。

```sh
python3 scripts/install_quiet_tv.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --verify-only --physical-home --record "$NEW_ACCEPTANCE_DIR"
```

也可直接运行 [verify_install.py](../scripts/verify_install.py)，使用相同的 `--serial`、`--user`、`--physical-home` 和 `--record` 参数。HOME 查询按本机帮助选择 `cmd package resolve-activity` 或旧系统 `pm resolve-activity`，作用于已核对用户；无障碍配置查询 `settings --user <用户> get secure enabled_accessibility_services`，焦点查询 `dumpsys window | grep mCurrentFocus`，同时记录安装版本及无障碍绑定转储。绑定只依据目标用户的 bound-services 区段及完整服务组件，不把其他用户、enabled 列表或标签计数当成运行证据。焦点必须能唯一对应目标用户的窗口；多屏有多个目标焦点、缺少用户范围或无法识别的转储均记为未知，原始输出保留。

安装入口退出 `0` 仅表示该次安装／配置流程执行完成，不代表实体 HOME 或开机验收通过。只读验收退出 `0` 表示声明的实体 HOME 后已查询到 Quiet TV 首页焦点，`1` 表示失败，`2` 表示实体 HOME 尚待确认。用户画面、系统默认 HOME、守护绑定、实体按键、重启、断电冷启动和待机唤醒分别报告。守护中转时系统 HOME 可以保留原桌面；只有前台应用包名不足以证明首页，更不能证明开机直达。所有电源测试均需相应授权，本入口不执行。

恢复以电脑保存的原 HOME、原始状态与守护授权记录为依据，按下文“请求恢复原桌面”处理；新记录中的 Quiet TV HOME 不能覆盖历史原桌面记录。工具不会自动回滚或重放变更。

## Agent 操作顺序

1. **确认目标**：检查电脑工具、现有 ADB 连接和 mDNS，必要时仅在电脑当前局域网扫描常用 ADB 连接端口，不跨网段或做全端口扫描。无论发现一台还是多台，都让用户确认目标；未发现时再指导用户提供实际地址和端口或 USB 设备标识。后续 ADB 命令始终指定同一设备。根据电视实际入口选择 USB、传统网络 ADB 或无线配对；配对端口与连接端口分别核对，授权由用户现场确认，不把投屏码当作配对码。无授权通道时停止依赖 ADB 的步骤；如果电视允许手动安装，继续提供普通 App 试用路径。
2. **只读检测**：读取品牌、完整型号、Android/API、系统支持的 ABI 列表、固件指纹、当前用户、Quiet TV 安装及启用状态、版本和签名，以及 HOME 候选和实际解析结果。先读取 `pm help` 和可用的 `cmd package help`，不预设用户 0、端口 5555 或现代子命令存在。分别判断 ADB 连接与授权、应用扫描、安装、HOME 切换、禁用及恢复能力；型号和 Android 版本不能代替实际能力检查。没有可靠查询结果时标明“未确认”，不能当作未安装。
3. **识别安装场景**：按下方“已有安装”或“首次安装”分流。当前用户已禁用、仅其他用户安装或当前用户已卸载但系统仍保留包的情况单独说明，询问是否恢复使用，不自动启用、恢复安装或当作首次安装。实验专用包名与普通包不混为覆盖升级。
4. **保存恢复基线**：在安装前保存可读取的旧版本、签名、实际 APK、当前 HOME 和应用启禁状态；首次启动或切换前补齐原主页组件、原始启用状态、目标用户及本机可用恢复路径。更新时保留原有恢复记录，不用当前 Quiet TV HOME 覆盖原桌面记录。保存在电脑私有目录；不上传设备标识、地址、密钥、完整转储或应用清单。系统选择器不能当成原桌面，记录不等于应用数据备份；无法读取的私有设置不能声称已备份。
5. **选择与校验安装包**：读取[兼容说明](COMPATIBILITY.md)，按上方版本与分包规则选包；安装前告知 Release、实际下载地址、`versionName`、`versionCode`、架构及选包理由。核对实际 APK 的包名、签名、最低 API、原生库架构及 GitHub 对应 APK 附件的 SHA-256；历史版本另有同名校验文件时可使用其记录，记录中的文件名须与实际下载名一致。不因新版本未上传独立校验文件而改选旧版本。签名冲突、降级或缺少匹配包时按下方升级规则处理。
6. **安装并核对**：保留数据安装，读取目标用户的实际安装路径，拉取已安装 APK，核对包名、`versionName`、`versionCode` 和 SHA-256 与选定目标一致。已有多 APK 安装逐项核对，单个 base.apk 不能证明整个集合。核对不符报告“版本验证失败”，无法核对报告“结果未确认”，不能仅凭安装命令成功声称已更新。TCL／雷鸟遭遇安装校验拒绝时，转入下方“TCL／雷鸟安装受限候选方案”，不重复普通安装。
7. **分项交付**：按所选分支验证结果，提供根据本次记录生成的恢复步骤。重启、断电冷启动、待机唤醒分别验证；重启和设备电源操作需有明确授权和可用恢复路径。失败或连接丢失时按下方要求报告，先查询现状，不自动重放安装、切换或禁用；TCL 分支中尚未恢复的安装器，按该分支优先恢复并读回。

## TCL／雷鸟安装受限候选方案

本分支先按 TCL／雷鸟品牌发现候选，再按本机错误和实际能力判断是否尝试；不要求用户先提供完整固件号。固件缺失记为“未确认”，不因此隐藏方案，也不能将品牌匹配写成已兼容。后续使用诊断日志补全品牌、型号、Android/API、固件显示版本、构建号和指纹，再按具体固件整理验证结果。

依据是 cleanyourtv 社区 [#683](https://github.com/Gathin23/cleanyourtv/issues/683)：`t982_ar31a8`、Android 11、固件 `RQ3A.210705.001.2024111116` 上报告了可逆的安装办法。该 Issue 的维护者将绕过安装限制列为项目范围之外，未集成到官方安装脚本；报告中的 `local.quiettv.launcher` 不是本项目的 `home.quiet.tv`，其成功记录不计入 Quiet TV 验收。

### 默认路线：relay 包与现有桌面守护

用户继续使用本页开头的原安装请求，无需更换指令或手工填写命令。Agent 识别为 TCL／雷鸟且安装受限时，优先走已发布 relay 包的多屏互动／电视端安装路线；临时停用安装器保留为用户单独选择的替代办法，不自动串联尝试。

1. **选包**：从实时 `latest.json` 的 `releases[].assets[]` 读取 `homeMode=relay`、实际 URL、SHA-256、版本、最低 API、ABI 和签名等配置。`homeMode` 来自与附件匹配的签名更新清单；`unknown` 表示历史附件尚未确认，须读取实际 APK。不能根据品牌或文件名中的“实验”推断；APK 查询声明也可能包含 HOME，必须检查 Activity 的 intent-filter。relay 复用现有主程序与守护，包名仍为 `home.quiet.tv`，不登记为系统 HOME 候选。
2. **保护更新**：首次安装可先尝试普通包，同时准备同版本同签名的 relay 候选；已装 relay 的更新只选符合升级条件的 relay 包。已有普通 HOME 包不自动覆盖为 relay，以免移除当前 HOME 入口；需要迁移时先另行说明。本次发布没有适配 relay 附件时，明确报告缺少可用包，不拿普通包冒充，也不自动重打包、改签名或退回旧版。
3. **取得工具**：从同一次 `latest.json` 的 `tools` 字段下载本节所需的 `install_tcl.py`、`tcl_cast.py`、`configure_home_guard.py`、`device_maintenance.py` 到同一私有目录，并逐文件核对所列 SHA-256。安装站点构建同时输出这些工具；缺项、下载失败或校验不符就停止依赖步骤，不让用户改用一串手工命令。源码工作区可直接使用对应 `scripts/` 文件。
4. **安装**：确认目标、电脑 ADB 授权、用户、APK 和记录位置后，先运行下面的预览；预览通过再加 `--apply`。普通包被本机 TCL 校验拒绝时，工具改用核验过的 relay；直接指定 relay 时也先尝试普通 ADB 安装。失败后使用目标电视的系统多屏互动，通过6553端口推送和仅绑定电脑 `127.0.0.1` 的 APK 服务、以及本次新建的 ADB reverse 下载；不公开电脑目录，不覆盖已有转发。电视出现提示时让用户选择“同意”。用户拒绝、已发起后的断连或结果不明时停止，不自动换渠道重装。
5. **电视端回退**：多屏互动不存在、端口不可用或目标用户不适用时，工具将 relay APK 暂存到电视 Download 的唯一新路径，尝试打开当前用户的当贝安装包管理，并等待电视端安装。让用户在当贝或文件管理器选择该文件并确认；不按固定坐标点击，不删除旧文件。超时标为未确认，保留暂存文件及记录；后续可重新核验已经安装的同一 APK，不强制重装。
6. **试用及守护**：安装后拉回实际 APK 核对版本、HOME 形态及 SHA-256，再打开 Quiet TV 试用。用户同意兼容接管后，复用[电脑守护配置](SETUP.md#通过电脑配置守护)，运行 `configure_home_guard.py` 的预览及 `--apply`。该工具检测 TCL 实际支持的自启动／关联启动 AppOps 并保存原值，不硬编码操作数字。保留原系统 HOME、其他无障碍服务和用户的暂停状态；首次启用需明确同意，普通安装或只更新不自动开启已暂停守护。服务配置、绑定、实体 HOME、重启、冷启动和待机唤醒分别验收，不顺带接管系统屏保或保持 ADB 常开。

首次安装的预览示例，变量由 Agent 从本次实际数据填写；只有普通包与 relay 候选都已核验时才提供两组 APK 参数。已装 relay 的更新直接将 `--apk` 指向相应 relay，不同时提供普通包：

```sh
python3 scripts/install_tcl.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --apk "$APK_PATH" --sha256 "$EXPECTED_SHA256" \
  --relay-apk "$RELAY_APK_PATH" --relay-sha256 "$RELAY_SHA256" --record "$NEW_PREVIEW_DIR"
```

执行时使用全新记录目录并加 `--apply`，无需 `--allow-temporary-installer-disable`。网络 ADB 自动沿用该目标 IP；USB ADB 由 Agent 读取电视地址并用 `--tcast-host` 指定，脚本会与目标实际网卡地址核对。电脑 ADB 不可用时，本工具不能完成安装后核验或守护配置；可说明电视允许的手动安装路径，不能将“APK 能装”说成“已完成桌面接管”。

### 识别实际失败（临时停用安装器的独立方案）

- 普通安装返回 `INSTALL_FAILED_VERIFICATION_FAILURE` 时保留输出，并采集该次安装前后的系统日志。若出现 `com.android.packageinstaller.verifier.strategy.LauncherStrategy`、`fetch signature info from :com.tcl.cyberui`、`The installing app not support tcl ui tab !` 或同类明确桌面校验信息，可向用户提供下方临时安装方案。仅有通用错误码时继续只读取证，不推定同一原因。
- Android 版本过低、架构不匹配、空间不足、签名冲突和降级仍按各自错误处理。旧固件的 `INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES`／`disable install launcher app not signature by tcl` 是另一类解析期限制，不能据此套用本分支。
- 不将 APK 内存在签名文件等同于满足 TCL 的厂商签名校验；不反复修改 `verifier_verify_adb_installs`、`package_verifier_enable` 或伪装安装来源试错。

### 临时安装与恢复

这是电脑 ADB 的可选安装操作，不是应用内系统包管理规则。只对本机确认承担该校验路径的 `com.android.packageinstaller` 开放一次临时处理，不扩展为其他系统包的禁用资格，不改动原桌面或固件预设。

实际执行入口为 [TCL 安装助手](../scripts/install_tcl.py)，不是手工照抄上游命令。脚本默认只读预览；`--apply` 才执行一次普通安装，只有同时提供 `--allow-temporary-installer-disable` 且本次安装日志确认本包遭遇 TCL 桌面校验时，才临时处理安装器并重试一次。使用现有 Android build-tools 的 `aapt2`、`apksigner` 核对 APK；找不到时通过同名参数指定，不自动安装 SDK。普通包及无 HOME 的 relay 包沿用同一实际包名核验，不自动改包或替换包。

下列变量由 Agent 从本次已确认的设备、用户、实际 APK 和可信发布校验值填写，记录目录必须全新且位于电脑私有位置。预览、执行使用不同目录，不覆盖已有记录：

```sh
python3 scripts/install_tcl.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --apk "$APK_PATH" --sha256 "$EXPECTED_SHA256" --record "$NEW_PREVIEW_DIR"
```

用户授权安装及临时处理安装器后执行：

```sh
python3 scripts/install_tcl.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --apk "$APK_PATH" --sha256 "$EXPECTED_SHA256" --record "$NEW_INSTALL_DIR" \
  --apply --allow-temporary-installer-disable
```

如果记录中存在“安装器恢复待确认”，先用同一设备及记录用户执行恢复预览；核对后加 `--apply`。恢复入口只处理记录中的安装器，不重放安装，不修改 HOME：

```sh
python3 scripts/install_tcl.py --serial "$TV_SERIAL" --user "$TV_USER" \
  --restore-record "$INSTALL_RECORD_DIR/record.jsonl"
```

记录目录保留 `record.jsonl`、可取得的安装前 APK 和安装后核验 APK。日志只引用本次脚本标记之后且包含本项目包名的校验信息；历史或其他应用错误不触发停用。进程被强杀或断连无法保证即时恢复，必须保留记录并优先走恢复入口。

1. **先说明并取得本次授权**：向用户展示本机匹配的错误、所选 APK，以及“临时停用安装器 → 安装一次 → 无论成败立即恢复”的流程。告知窗口内系统安装界面及校验可能不可用，恢复前不重启、不切换 HOME。普通安装请求不自动授权停用系统安装器；已有明确授权则不重复询问。
2. **核对恢复条件**：电脑 ADB 已授权、目标及前台用户已确认；APK 已按通用规则核验。保存安装器在目标用户下的原始启用值与相关组件状态，以及原 HOME 基线，核对固件支持指定用户的停用与原状态恢复命令。原始 `enabled=0` 使用支持的 `pm default-state --user` 恢复，`enabled=1` 使用 `pm enable --user` 恢复；不能把两者混为一谈。安装器已被禁用、原状态或恢复方法不明时先报告，不将其当成本次可停用对象。
3. **仅执行一次安装窗口**：每条 ADB 命令显式指定同一设备及已核对用户。用已验证的 `pm disable-user --user` 临时停用该安装器并读回；只有停用确认成功后才对已核验的 Quiet TV APK 保留数据安装一次。无论停用读回、安装、取消或超时发生何种结果，都先检查并恢复本次涉及的安装器原状态，读回确认后再启动应用或进行其他修改；执行工具须使用 `finally` 或等效的退出清理安排恢复，不以安装成功为恢复条件。
4. **恢复失败优先处理**：立即在对话显示原始错误、已知状态、目标用户和由本机原值生成的恢复命令。连接丢失时标记“安装器恢复待确认”，连接恢复后先只读检查，再仅恢复本次已授权变更；不自动重试安装、再次停用、切换桌面或重启。没有可靠读回前，不报告恢复完成或方案成功。
5. **恢复确认后验收**：拉取已安装 APK 核对实际版本、包名及 SHA-256，再进入试用。默认 HOME 按已有接管授权继续配置，缺少该授权时再询问；查询和实体遥控器仍须验证；重启、冷启动、待机唤醒分别记录。成功安装不表示开机接管已完成，也不自动添加 `directBootAware`、更改启动属性或禁用 CyberUI。

交付时分别记录“品牌候选匹配、错误依据、固件信息完整度、安装结果、安装器原状态与恢复读回、已安装包校验、HOME 及电源验收”。具体设备验证完成前，一律标为“候选方案，Quiet TV 真机待验证”，后续固件日志作为补充证据；一次成功不升级为整个 TCL 品牌支持。

默认 relay 路线参考 [Aerial 的 TCL 安装实现](https://github.com/pengchujin/aerial-tv/blob/main/docs/devices/tcl-mt5879-cn.md)，复用本项目 `quietHomeMode=relay` 及现有守护。工具代码、索引支持和具体 relay APK 是否已发布须分别确认；源码存在不等于用户的当前发布已提供对应包。两条路线均不适用时保留现场，说明剩余限制。

## 已有安装：覆盖校验与仅更新

下列规则用于覆盖安装校验；开头的自动接管请求在升级核验后继续完成接管及 ADB 配置。仅当用户明确只更新时使用 `--goal update`，不重新配置桌面、守护或 ADB。

| 检测结果 | 处理 |
| --- | --- |
| 适用档位有更高 `versionCode`，包名、签名及系统架构匹配 | 保留数据覆盖升级，保持原默认桌面、应用启禁状态及设置，不重新执行首次设置或精简。 |
| 已安装包与适用附件的 `versionName`、`versionCode`、SHA-256 均相同 | 告知无需重装；如用户有故障，另行诊断，不用重装代替判断。 |
| `versionCode` 相同但文件不同，或已安装构建号更高 | 说明差异并停止覆盖，不默认修复、换档或降级。 |
| 包名、签名、系统或架构不匹配 | 明确不满足的条件，停止直接覆盖，不通过卸载解决。 |

软件版本相同不代表构建号相同。已安装同批高号通用包时，不能覆盖安装低号 ARM 包；专用包不满足条件而通用包满足时可选通用包。无符合条件的更新包则保留现状并说明，等待更高构建号的匹配包，不卸载、清数据或强制降级。

覆盖后核对版本与已安装文件，再检查原 HOME 和启禁状态是否保持，请用户确认桌面能打开、壁纸与排序等原设置仍在。当前源码的新安装与升级均不自动弹出设置向导；已发布旧包可能仍有引导，按实际 APK 判断。如出现状态变化，报告差异，不自动重新配置。用户另行要求调整默认桌面或应用时，再进入对应可选流程。

## 首次安装：试用、默认桌面与可选管理

AI 负责按已有授权完成电脑侧安装、桌面配置、状态核对与恢复方法交付；用户只完成必要的电视系统授权、系统选择和实体按键验证。已完成的配置直接沿用，不再要求用户走完应用内两步向导、精简应用或重新选择接管方式。电脑 ADB 已完成的配置不要求通过 Quiet TV 内置 ADB 再做一次，也不通过修改应用私有记录或清数据来跳过引导。

1. **先安装试用**：启动 Quiet TV 后直接在桌面验证方向、确定、返回、应用启动、设置和信号源，试用本身不改变原默认 HOME。若实际安装的旧版 APK 仍弹出向导，使用“暂不设置，临时使用”，或在已设置 HOME 时选择“不处理，进入桌面”，不执行无关应用管理。ADB 不可用时，如果电视允许手动安装 APK，继续提供手动试用路径；不声称已经自动安装或能解锁调试。
2. **按需配置桌面**：先读取当前实际配置。系统 HOME 已指向 Quiet TV，或已选代理／中转的必要配置已就绪时，保持当前方案并直接验证使用；中转保留原 HOME 不等于配置失败，不重复切换或授权。尚未完成且用户已授权桌面替换时，AI 继续完成相应配置；只有缺少授权时才询问是否设为默认。需要电视操作时使用系统选择或电脑维护工具（历史版本可能仍有“桌面配置”或“首次设置”入口）；ADB 切换命令须在实际固件帮助中存在并支持目标用户。重新查询 HOME，再请用户按实体 HOME 并等待反馈。用户只试用、拒绝授权、固件拒绝或结果未确认时，保留原桌面，停止依赖切换成功的后续管理。系统默认 HOME 设置失败不阻断独立的兼容守护；已有自动接管授权或另行守护授权、且实际 APK 含配置入口时，按下方“兼容守护的权限与范围”处理。
3. **可选禁用原桌面**：默认保留。仅在 Quiet TV HOME 组件可用、系统 HOME 已核对指向 Quiet TV、实体 HOME 已由用户确认、本机原桌面身份及原状态明确、适配规则允许禁用且具备恢复命令与路径时，才向用户提供禁用选项；用户明确选择后执行。禁用后重新设置并核对 HOME，再验证实体按键。不通过禁用原桌面试错，不卸载原桌面。重启、冷启动和唤醒仍需单独验收。
4. **按需管理应用**：预装应用管理是独立可选操作，不作为安装或桌面替换的完成条件。仅在用户要求时，使用下文电脑维护工具处理；电视端应用管理只保留日常整理，不提供系统禁用入口。扫描当前电视实际应用，列出名称、包名、用途、当前状态、拟执行操作、影响及恢复办法，区分“可禁用”和“只读／待确认”。按发布包对应的[固件规则](../app/src/main/assets/setup-presets.json)核对指纹、品牌及规则要求的机型和操作资格；上游参考不授予资格，未知系统包和关键组件保持只读。执行前须核实具体应用及影响，取得用户选择；不把精简作为安装步骤。
5. **逐项执行**：通过已确认的电脑 ADB 连接操作，不要求应用内再次授权。选择完成后重新核对目标、用户、HOME 和整组包状态，只禁用本次明确选择且资格未变化的项目，保留安装和数据。每项执行一次并读回、记录原状态与结果；失败停止后续修改，不把多项成功操作当作可自动回滚事务。恢复仅处理本次实际发生且有记录的变更。

外部 Agent 直接执行 shell 不会自动受到应用内检查约束，也必须遵循上述资格与顺序；不能绕过只读限制。应用能安装、能设置 HOME、能禁用原桌面、能管理其他系统应用是独立能力。新源码或实验助手不等于已发布 APK 的功能，不自动部署未发布的主页守护或助手。

安装交付时提供电脑私有恢复记录及本机适用命令；“应用管理 → 更多 → 帮助与恢复”保留为主动入口。电脑记录不自动等于应用内恢复基线，使用应用内恢复前仍须核对记录、原桌面身份与恢复资格。默认 HOME、实体 HOME、重启、冷启动和待机唤醒分别记录；没有弹出向导不代表这些项目已经验收通过。

## 失败时直接在 AI 对话显示

下载、连接、授权、安装、HOME、应用管理、恢复和验证中的失败，均立即显示在当前 AI 编程工具的对话中；不能只显示“失败”、只记录在文件、只让用户去电视找日志，或等待最后统一报告。

```text
失败步骤：<正在执行的操作与目标>
相关命令：<必要命令，设备地址、序列号等脱敏；界面操作则写操作路径>
退出状态：<本机退出码及可取得的远端退出状态；未取得写“未知”>
原始错误：<相关标准输出、标准错误或工具异常；无输出也明确说明>
原因判断：<已经确认的原因；可能原因和待确认项分别写明>
当前状态：<已完成、已修改、未执行、已核对或结果未确认>
下一步：<可继续的独立检查、用户需做的操作及本机恢复办法>
```

- 保留必要的原始错误码和错误文本，不隐藏错误输出或只给通用结论。原始内容只摘录相关脱敏片段，不输出配对码、令牌、密钥或完整设备转储。工具缺失、无权限、无法访问文档或无法取得日志也直接说明。
- 命令返回成功但版本、哈希、HOME 或包状态不符时，明确报告“验证失败”及预期、实际差异。超时、断连或缺少可靠输出时报告“结果未确认”，不推断成功或完全没有修改。
- 停止失败步骤及依赖它的后续修改，继续已授权且不依赖该结果的只读检查。重新读取实际状态后再决定后续；不自动重复修改、卸载重装、清数据或扩大到无关系统包。
- 原因无法确认就说明缺失证据；连接超时不等于固件封锁，HOME 查询正确不等于实体按键成功。用户的电视画面和实体反馈须单独记录。

## 结果要求

| 项目 | 应报告的证据 |
| --- | --- |
| APK | 选定 Release、来源、目标与实际版本及构建号、系统档位、架构与选包理由、签名、下载与已安装文件校验 |
| 安装 | 指定设备和用户上的实际安装结果 |
| 系统 HOME | 真实查询结果；不支持查询则为未知 |
| 实体 HOME | 用户实际按键后的画面；ADB 注入只算单独证据 |
| 重启、冷启动、待机唤醒 | 各自完成、失败或未执行，不能互相替代 |
| 原桌面与恢复 | 是否保留、本机恢复步骤、依赖条件和私有记录位置 |
| 可选应用管理 | 用户确认的选择、规则依据、每项原状态、执行与读回结果；未选择则未执行 |
| 失败 | 失败步骤、脱敏命令、退出状态与原始错误、原因判断、当前状态和下一步 |

`Success`、应用已打开、HOME 已解析、服务已绑定及实际按键行为是不同证据。只贴必要命令的脱敏输出，不公开完整日志。无障碍或通知监听写入配置不代表已绑定、收到事件或能接管 HOME。

本流程不 root、不刷机、不恢复出厂、不清数据、不卸载原桌面；禁用仅限用户明确选择且满足上述规则的项目，包括 TCL 分支中有单独授权及恢复安排的一次安装器临时操作，不操作无关系统包；按本页明确请求在支持的设备上配置 ADB 保持，用户仅更新或试用时保留已有选择。安装和源码同步不授权发布 APK。

安装、HOME 或运行异常需要取证时，使用[Agent 问题排查](AGENT_DIAGNOSE.zh-CN.md)，排查不自动重复安装或修改系统。

## 请求恢复原桌面

恢复前读取现状和本机私有记录，核对目标设备、用户、原桌面组件及原始启用状态。优先使用系统选择、Quiet TV 恢复入口或已验证的本机路径，只恢复实际发生且有记录的变更；原桌面未禁用就不执行启用。保留 Quiet TV 和其他应用数据，记录或权限不足时说明缺失项，不猜原值、不套用其他电视的命令。完成后读回 HOME，等待用户验证实体按键；重启、冷启动和待机结果分别报告，电源操作先确认。失败处理遵循上文要求，不自动重放修改。

```text
请通过我的电脑恢复电视原来的桌面，保留应用和数据。
先完整阅读并执行官方说明：
https://raw.githubusercontent.com/BeatsAD/quiet-tv/main/docs/AGENT_INSTALL.zh-CN.md
```

## 兼容守护的权限与范围

仅当用户明确请求自动接管桌面或另行授权兼容守护，且实际安装包包含相应组件时，才配置兼容守护的无障碍、通知访问及写安全设置能力；使用实际包名和已核对用户。首次权限配置不等于开机验收。新开发版进入配置后默认为自动，后续重启无需重复确认；系统 HOME 仍属原桌面时不得报告默认 HOME 已修改，不因守护可运行而禁用原桌面。用户明确暂停后不得重启、重绑或更新替其打开。历史安装包不因本文更新而获得该能力。

本修复提供[电脑配置脚本及步骤](SETUP.md#通过电脑配置守护)：电脑 ADB 已授权即可完成首次配置，无需等待 Quiet TV 内置 ADB 认证成功。预览后，在已有守护配置授权范围内使用 `--apply`；该参数明确启用守护，含主动暂停的配置也会开启，不在只读诊断、仅试用或仅更新时执行。先核对指定电视、前台用户、原主页及实际 APK 的 `HomeGuardSetupReceiver`；旧 1.2.0 包缺少入口时先说明版本差异，未获更新授权不自行安装。脚本保留原桌面与其他服务，权限写入、服务绑定、事件可用及实体接管分别确认。Android 5／6补偿需用量统计授权；Android 4.4不开放。端口连通、ADB 开关开启、内置握手超时均不能单独证明电脑 ADB 授权状态或固件封锁。


## 电脑维护：检查、修复与恢复

新源码将守护、ADB 和系统应用禁用移出电视日常界面；旧 APK 不随文档更新获得接口。电视端“应用管理 → 更多 → 帮助与恢复”仅提供帮助、暂停接管及系统原桌面恢复入口；布局、天气、应用封面、排序和儿童模式继续在电视操作。恢复基线在安装接管前保存；历史配置缺记录时沿用电脑原记录，不能猜原值。

安装仍使用 `install_quiet_tv.py`。维护使用同一工具目录中的 `device_maintenance.py`，不重新安装、清数据或自动重启。所有命令指定已确认的电视和前台用户，`NEW_RECORD_DIR` 每次取全新的电脑私有目录。

```sh
python3 device_maintenance.py inspect --serial "$TV_SERIAL" --user "$TV_USER" --record "$NEW_RECORD_DIR"
python3 device_maintenance.py repair --serial "$TV_SERIAL" --user "$TV_USER" --record "$NEW_RECORD_DIR"
python3 device_maintenance.py restore --serial "$TV_SERIAL" --user "$TV_USER" --record "$NEW_RECORD_DIR"
```

上述三行是不同操作示例，不连续执行；除 inspect 外默认预览。已有明确修复／恢复授权时，在检查计划后用新目录加 `--apply` 执行，不反复询问同一授权。repair 复用已配置的守护、不默认更改 ADB 选择；主动暂停的接管仅在用户要求恢复后加 `--resume`。独立代理路线不自动改成内置守护。原桌面已禁用、组件不可用或固件／用户变化时，按原接管记录先恢复原组件状态；工具不猜测、不盲目启用。

单个应用禁用先预览：

```sh
python3 device_maintenance.py disable --target "$APP_PACKAGE" --serial "$TV_SERIAL" --user "$TV_USER" --record "$NEW_RECORD_DIR"
```

AI 列出返回的名称、用途、影响和恢复方法。只有用户明确选择该应用后才加 `--apply`，每次只处理一个包；失败停止后续修改。工具读取已安装 APK 内的固件规则和保护条件，拒绝原桌面、接管依赖和未确认系统包；无精确恢复命令也不禁用。此入口不卸载、不删除应用数据，不替代专用原桌面接管方案。

恢复该次禁用：

```sh
python3 device_maintenance.py restore-app --target "$APP_PACKAGE" --from-record "$DISABLE_RECORD/record.jsonl" --serial "$TV_SERIAL" --user "$TV_USER" --record "$NEW_RECORD_DIR"
```

核对后用新目录加 `--apply`。只恢复记录中的原始启用值，不能把默认启用值 0 一律改成 1。预览记录不算已执行，设备、用户、固件或版本变化时停止；中断后先读现状，不重放。所有记录留在电脑私有目录，反馈前脱敏。

维护完成后按本页验收要求分别验证实体 HOME、重启、冷启动、待机唤醒及播放／HDMI 不被打断。配置返回成功不等于这些场景通过。采用 Aerial 的 [安装](https://aerial.qust.me/agent.md)／[适配](https://aerial.qust.me/adapt.md)流程组织方式，执行仍使用 Quiet TV 的包校验、权限及固件规则；不运行 Aerial 安装脚本替换本项目配置。
