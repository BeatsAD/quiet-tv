# 极简桌面首次设置开发方案

日期：2026-10-18。状态：待实施；本文件只制定开发方案，不授权安装、重启或改变真实电视状态。

交互基线：[已确认的两屏原型](../prototypes/app-management/setup-design.md)，对应本地提交 `520ea36`。

## 1. 交付目标

将浏览器原型落地为现有 Java 原生电视应用中的设置功能：

1. **设为默认桌面**：优先使用系统确认入口；需要 ADB 时在当前页按需连接。核对实际默认 HOME 后自动进入下一屏。
2. **管理预装应用**：自动识别当前电视实际预装的应用，按已核实规则推荐可禁用项，可逐项取消；原桌面可选保留、禁用、卸载，能力核验通过时默认禁用。执行完成后直接进入桌面，短暂提示“设置成功”。

不增加欢迎、连接成功、完成总结页面。标题直接说明操作，删除营销文案与重复说明。卸载原桌面保留一次独立确认，默认聚焦“取消”。“不处理，进入桌面”跳过本屏所有待执行操作，保留第一屏已经完成的默认桌面设置。

日常使用及重启返回桌面不依赖 ADB 常驻连接。持续保留配置是目标，不承诺恢复出厂设置或所有固件升级后仍有效。

## 2. 已有能力与缺口

| 模块 | 当前源码能力 | 本次需要补齐 |
| --- | --- | --- |
| `HomeActivity` | 已声明 HOME，包含桌面、设置和应用管理入口 | 首次设置入口、完成返回、旧用户升级分流 |
| `ManagementUi` | 原生面板、按钮、焦点和弹层 | 两屏布局及操作期间的焦点、进度反馈 |
| `AdbController` | 本机 TCP、独立密钥、本机／用户校验、超时断开 | 当前页取消连接与待执行动作联动；后续无线配对 |
| `AppRepository` | 包元数据、当前用户安装／启用状态 | 通用预装识别、系统应用更新识别、扫描完整性、原始启用状态值及原桌面 HOME 组件的核验支持 |
| `AppOperations` | 单包启停、卸载、恢复安装；操作前后查询与持久日志 | 设置操作序列、原桌面专用资格规则、恢复校验 |
| `ManagementInstrumentation` | 应用管理、Dock、连接及专用测试包验证 | HOME 切换、两屏流程、中断恢复与升级场景 |

目前没有原生首次设置流程；原桌面不在可管理预装清单中，不能直接通过现有通用操作开放。无线配对的原生依赖当前被排除，原型中的配对流程不能视为已实现。

应用识别面向当前 APK 支持的 API 31+ Android 电视，按实际设备扫描，不依赖 Sony 清单。首个真机操作验收仍使用已调查的 Sony Android 12 固件；其他机型可以展示扫描结果，推荐规则与禁用／卸载能力按机型逐步验证，分别记录支持范围。

## 3. 开发阶段与验收门槛

按 A → B → C → D 顺序完成首个 TCP 机型闭环，再完成 E 的无线能力与 F 的对应设备验收。各阶段必要检查通过后分别创建本地提交。

| 阶段 | 具体工作 | 阶段验收 |
| --- | --- | --- |
| A：识别、基线与 HOME | 区分首次安装／旧版升级；扫描当前电视预装应用，匹配推荐规则；保存当前用户、固件、原默认 HOME 和受支持原桌面组件；实现系统确认与 ADB 设置后读回 | 非 Sony／未知固件仍展示实际扫描结果；取消不切换；成功必须与实际 HOME 一致；原桌面未知时不开放破坏性操作 |
| B：两屏原生界面 | 按原型实现设置与预装列表、三选一、按需连接、卸载确认、成功直达桌面；保留遥控器操作 | 不出现额外引导页；返回焦点正确；取消连接不延迟执行；零选择可直接完成 |
| C：操作序列与保护 | 复用现有单包操作，加入原桌面特例、执行前检查、逐项结果、断连后状态核对 | 未成为实际默认 HOME 时禁止处理原桌面；执行不重复；部分失败不显示全部成功 |
| D：恢复与升级 | 原桌面三态恢复、精确恢复范围、旧安装迁移、异常退出后重新查询 | 先恢复可用再切 HOME；其他应用状态保持；升级不自动重新禁用／卸载 |
| E：无线配对 | 验证库的 TLS 配对能力与 ABI，接入本机服务发现／端口、配对码、连接与取消 | 必须在支持无线调试的电视上实测；配对成功后还需连接及本机／用户校验 |
| F：候选包与真机验收 | 版本与构建号、归档与哈希、原生截图、实际包状态、批准范围内的重启及回归 | 构建、安装、状态读回、真实遥控操作分别留证；按机型列出通过与待验收项 |

阶段 A—D 完成并通过对应真机验收后，可交付“已适配 Sony／TCP”候选版；E 未通过前不标注支持无线配对。原桌面卸载／预装恢复未通过专项真机验收前，不把该机型卸载入口作为已验收功能交付。

## 5. 默认桌面与原桌面识别

第一次改变 HOME 前，先保存“此前默认 HOME”；另外按适配配置识别“原厂桌面”。两者不能混用：此前默认可能是第三方桌面，也可能已经是 Quiet TV。

- 系统支持 `ROLE_HOME` 且可以请求时，使用系统确认流程；返回后重新查询，不能仅凭回调或页面状态判定成功。
- 系统未提供可用入口时，按需连接本机 ADB，再设置当前用户 HOME 并读回。厂商拒绝时停留当前页给出必要说明，不显示成功。
- 旧版已使用 Quiet TV 的用户直接进入桌面，在应用管理中主动打开设置；不因缺少新偏好就强制重新引导。
- 旧记录没有原桌面时，仅在适配固件且组件核验通过后识别已知原桌面；无法确认则只允许保留，不猜测包名。
- 设置 Activity 从系统选择器／开发者设置返回时重新检查状态；取消返回不自动跳页或执行未确认动作。

系统角色可用性及请求接口以 [Android RoleManager 文档](https://developer.android.com/reference/android/app/role/RoleManager) 为依据；是否能在具体电视上完成仍需实机验证。

## 6. 自动识别预装应用与原桌面处理

清单由当前电视的实际扫描结果生成，覆盖不同品牌、机型与固件，不固定展示 Sony 应用。设备适配规则用于补充应用用途、推荐操作与已验证能力；没有适配规则的电视仍能识别并展示预装应用。

识别流程：

1. 读取品牌、制造商、机型、Android 版本、固件指纹与当前用户，作为规则匹配条件；不能仅凭品牌或包名前缀确定应用用途。
2. 复用 `AppRepository` 枚举设备可见的包、实际名称、图标、版本及状态，结合系统应用标记识别预装应用，包括更新后的系统应用。普通用户安装的应用不混入预装清单；厂商以普通应用形式预置的包，仅在有已核实的来源证据或适配规则时归入预装，无法确认时标为来源待确认。
3. 未连接 ADB 时先展示可读取的结果；如受包可见性或权限限制，明确标记扫描未完整。连接并校验本机／当前用户后，通过 shell 查询核对系统包、当前用户安装与禁用状态，补齐清单。无法确认完整性时不能提示“未发现预装应用”。
4. 将扫描结果与适用于当前设备的已核实规则匹配，标记“推荐禁用”“建议保留”或“用途待确认”。只为已安装、已启用且通过操作资格检查的推荐项默认勾选；用途待确认的系统包展示为只读，不自动推荐或操作。

| 识别结果 | 首次设置中的处理 |
| --- | --- |
| 命中当前设备规则且允许禁用 | 展示实际名称、图标、用途与状态，默认勾选，可取消 |
| 已禁用 | 展示实际状态，不计入待执行数量，不自动重新启用 |
| 当前用户已卸载、系统仍留包 | 不计入待禁用项；在应用管理中按已验证能力提供恢复入口 |
| 用途待确认或关键系统组件 | 展示识别结果与只读原因，不默认勾选 |
| 规则中存在但设备上不存在 | 不展示，不生成待执行操作 |

现有 Sony 调查清单仅作为首批规则数据；换用其他电视时重新扫描并匹配对应规则，不沿用 Sony 推荐结果。识别到预装应用不代表它可以安全禁用或卸载，“推荐禁用”也不等于已验证卸载安全。更多应用沿用应用管理中的单应用操作与保护规则。

识别依据参照 [Android 应用信息标记](https://developer.android.com/reference/android/content/pm/ApplicationInfo)与[包可见性限制](https://developer.android.com/training/package-visibility)；应用的用途与可操作性需要额外核实，不能由系统应用标记推断。

原桌面按第 5 节读取实际 HOME 候选组件，并结合当前设备规则识别，不写死单一品牌包名；此前默认 HOME 与原厂桌面分别记录。候选不唯一或身份无法确认时，只允许保留。

- **保留**：不改变它当前的安装与启用状态，不自动启用此前已禁用的包。
- **禁用**：仅针对当前用户，保留安装及数据；当前设备与目标组件核验通过、禁用能力已验证时默认选择，否则默认保留。
- **卸载**：为当前用户移除；独立确认数据删除。仅对当前设备匹配且卸载／恢复能力专项验收通过的原桌面开放。

原桌面不直接加入通用系统包允许清单。执行前必须同时满足设备规则命中、目标组件核验、当前用户一致、Quiet TV 已成为实际默认 HOME 且 HOME 组件可用。Quiet TV、自身测试组件、设置及其他关键系统组件继续只读。

## 7. 执行、取消与异常规则

执行顺序固定为：

```text
冻结用户确认的选择
  → 按需连接／授权
  → 重新读取用户、固件、HOME、版本与包状态
  → 保存操作前基线
  → 逐个禁用所选预装应用，并核对结果
  → 再次核对 Quiet TV HOME
  → 最后处理原桌面，并核对结果
  → 核对默认 HOME，进入桌面并提示结果
```

任一项失败或结果不明时，停止后续项，尤其不继续处理原桌面。界面只显示必要的失败项与重试／进入桌面入口；已成功项仍保留记录，不把这一组操作描述为可自动回滚的事务。

- 用户只选择保留且没有其他待操作项时，不要求 ADB。
- 卸载先确认，再申请必要连接。关闭确认／连接面板立即作废待执行动作；迟到的连接成功不能触发操作。
- 命令已发出后，取消只能停止后续项，并查询当前项结果，不能声称撤销已执行操作。
- 重复按确定不生成新任务；断连／超时不自动重发修改命令。
- 页面重建可恢复选择；进程终止后先查询实际状态，不自动重放上次的卸载或未完成序列。
- 完全成功才显示“设置成功”；主动跳过显示“已进入桌面”；部分完成明确显示“部分设置未完成”。
- 日志关联运行标识、当前用户、原 HOME、目标包、原始状态与逐项结果；配对码、私钥和应用数据不写入日志。

## 8. 原桌面恢复

| 原桌面实际状态 | 恢复顺序 |
| --- | --- |
| 已安装且可用 | 验证 HOME 组件 → 切回默认 HOME → 读回 |
| 已禁用 | 重新启用 → 验证包与 HOME 组件 → 切回 → 读回 |
| 当前用户已卸载、系统仍留包 | `install-existing` → 验证安装 → 必要时启用 → 验证 HOME 组件 → 切回 → 读回 |
| 系统安装包缺失或恢复失败 | 保持 Quiet TV 可用，显示无法恢复及必要的重新安装路径，不执行切回 |

“恢复原桌面”只处理该桌面及默认 HOME，不顺带启用其他预装应用。状态记录不是应用数据备份，恢复安装不恢复被删除的数据。不承诺所有厂商固件均支持恢复。

## 9. 无线配对的单独交付

先验证现有库对应实现、原生依赖、目标 ABI 与实际电视能力，再决定最小依赖变更。需要区分配对端口与连接端口；配对成功后建立连接，并沿用本机启动标识、shell 身份与用户校验。

开发者设置是外部系统界面，不能假设返回后配对码仍有效。按实际设备验证分屏／设置切换后码的可用性；发现失败时允许输入本机端口。缺少可用系统入口或无法在本机完成配对的机型，不展示“输入六位码即可完成”的保证。

[Android ADB 文档](https://developer.android.com/tools/adb)将电视无线调试的版本前提列为 Android 13／API 33+；版本满足仍需验证厂商实际支持。当前 Android 12 Sony 验收不能替代此阶段验收。

## 10. 验证与交付标准

| 验证层 | 必须覆盖 |
| --- | --- |
| 预装应用识别 | 不同品牌／未知固件、更新后的系统应用、普通用户应用、来源待确认包、已禁用／已移除包、规则缺失／不匹配、无 ADB 及包可见性受限；清单来自实际扫描，推荐与操作资格分别验证 |
| 操作规则检查 | 实际 HOME 前置条件、未知固件保护、状态变化拒绝、单次执行、结果不明不重发 |
| 原生遥控界面 | 两屏跳转、焦点与滚动、卸载默认取消、零选择、返回设置、取消授权、成功直达桌面 |
| 专用测试环境 | 测试 HOME 切换／禁用／重新安装、断连与进程重启；不能用普通测试 APK 的结果冒充预装恢复证据 |
| 旧版本升级 | 原 HOME 已禁用、已使用 Quiet TV、已有 Dock／壁纸、缺少设置基线；不自动改变现存包状态 |
| 目标电视 | 本机独立授权、默认 HOME 读回、选中包前后状态、恢复原桌面、关闭调试后正常回 HOME、批准范围内重启保持 |
| 关联回归 | Dock、壁纸、设置、信号源、遥控与保留的媒体／投屏入口；播放及投屏效果需单独实际验证 |

原桌面卸载／预装恢复的专项验收优先使用可恢复的备用电视或受控系统镜像。现有记录明确保留该项待验收；不擅自在日用电视卸载原桌面或 BRAVIA 演示，也不将本次方案确认当作破坏性真机测试授权。

如评价“提升流畅度”，对比相同设备、分辨率和应用状态下的 HOME 返回时间、遥控焦点响应与空闲占用；记录条件和样本，不预设提速比例。不开启无关的清内存、杀进程或系统服务禁用功能。

每次交付提供：本地提交、APK 版本／构建号及 SHA-256、安装哈希核对、原生截图、包状态前后证据，以及逐机型通过／未验证项。先完成本地实现和候选包，再按已有或后续明确授权执行真实设备安装与状态变更；远程推送、正式发布另行处理。

## 11. 当前建议

先开发 A—D，得到已适配 Sony／传统 TCP 的完整原生闭环，同时使用测试 HOME 验证原桌面分支。先把禁用与恢复做通；卸载分支完成代码后保留专项真机验收门槛。随后完成 E 的无线配对与新增机型验收。

这能先交付与现有工程能力衔接最紧的版本，同时保留已经确认的“保留／禁用／卸载”设计和无线配对开发范围。
